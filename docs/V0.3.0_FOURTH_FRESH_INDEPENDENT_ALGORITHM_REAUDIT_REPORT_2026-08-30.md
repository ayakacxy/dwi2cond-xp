## 结论

这次复审的答案不是“已经完全相同”。当前 v0.3.0 的**默认主流程顺序基本正确**：在项目
支持的默认 `legacy + nonlinear + WLS` 路径中，没有发现新的阶段错序、正式拟合输入串线、
T1 注册依赖倒置或正式 FEM 静默替代。nomoco、legacy、EDDY/TOPUP、DTIFIT、6/12 DOF、
FNIRT、PPD、post-mask、tensor publish 和正式 SimNIBS SESSION 的高层
producer→consumer lineage 能够逐段对应官方流程。

但是，具体算法和计算合同仍确认存在 **2 个 P1 + 3 个 P2**，没有发现 P0：

| 编号 | 严重度 | 确认问题 | 主要影响 |
|---|---:|---|---|
| `D2C-030-060` | P1 | legacy 正行列式/RAS 输入的 registration producer 输出 local scaled-mm matrix，consumer 却按 FSL radiological scaled-mm matrix 解释 | corrected DWI、matrix、可选 corrected bvec、tensor 及全部下游 |
| `D2C-030-061` | P1 | 两个 BET backend 都漏采 7 mm inward endpoint，并漏掉 sub-mm `dscale` stencil | raw/legacy/GRE/TOPUP/EDDY mask 和正式拟合 support |
| `D2C-030-062` | P2，兼容性 | 本地 conductivity 用稳定的 `eigh`，SimNIBS 4.6 字面实现用 `eig`；重复特征值时输出可确定分叉 | standalone `tensor-to-mesh` 与正式 SimNIBS conductivity 不同 |
| `D2C-030-063` | P2，条件性 | FEM cache identity 没有完整绑定复合 solver、实际加载 native library 和完整执行模块 | 环境漂移后可能静默复用旧 FEM 结果 |
| `D2C-030-064` | P2，输出合同 | TOPUP coefficient NIfTI 缺少 FSL cubic-field intent `2016` 及原场 voxel-size intent 参数 | coefficient artifact 不能作为 FSL TOPUP coefficient 互操作 |

其中 `060` 和 `061` 是会进入普通科学数组的算法问题，应优先修复。`062` 不是说本地
`eigh` 的数学选择错误；相反，`eigh` 对实对称张量更合理、更稳定。问题在于项目若声称
“与 SimNIBS 4.6 逐输出一致”，该声明在合法重复特征值输入上不成立，必须明确 stable 与
literal compatibility 的产品合同。`063` 和 `064` 分别是缓存可信度和官方产物互操作问题。

本轮显式配置全部真实 FSL probes 后，全仓测试为：

```text
671 passed, 0 skipped in 208.70s
```

全绿不能推翻上述结论：现有关键 MCFLIRT、BET、TOPUP 和 EDDY fixture 主要使用
负行列式/LAS、平滑 2 mm mask 或只检查产物存在性，恰好没有覆盖本轮判别反例。

## 3. D2C-030-060：legacy 正行列式/RAS 的 matrix 坐标合同错误

### 3.1 问题链

正行列式不是不可达的异常输入：

- `orientation.py:155-171` 明确让 `det(affine)>0` 的数据保持 RAS，让负行列式数据保持 LAS；
- `orientation.py:226-273` 只做 storage permutation/flip，不改变 handedness；
- 已经 canonical 的正行列式 float32 数据甚至可以直接通过无插值输入路径。

local legacy registration producer 的坐标是普通正对角 scaled-mm：

- `legacy.py:137-179` 只从 affine 取正 voxel size；
- `_register_mcflirt_series()` 和 `_optimize_one_stage()` 在这个 local diagonal grid 上优化；
- `legacy.py:571-582` 的 mean-DWI→nodif FLIRT 也使用普通正对角 sampling；
- 因而 producer 返回的是“没有 neurological→radiological x-flip 的 local scaled-mm matrix”。

consumer 却把它当作 FSL matrix：

- `legacy.py:258-283` 的 `_resample_series()` 调用 `fsl_matrix_to_world()`；
- `transforms.py:235-253` 对正行列式 NIfTI 插入 FSL 的 x 反射；
- `transforms.py:256-276` 假定输入 matrix 已经位于 FSL radiological scaled-mm；
- local matrix 因此被按另一个坐标合同解释。保存到 `MAT_*`、最终 corrected image 和
  `bvec_mode=corrected` 的旋转也不再属于同一 matrix 语义。

官方 FSL 在 `newimage/generalio.cc:300-306` 读取 neurological NIfTI 后先
`makeradiological()`；MCFLIRT 随后在 radiological internal storage 上求矩阵并用同一矩阵
重采样。因此官方 producer 和 consumer 是闭合的，本地当前不是。

### 3.2 真实 FSL 判别 A/B

配对输入使用同一组不对称 `25×23×21` 数组、2 mm voxel，同时包含 x/y 平移；只改变
affine 的 determinant。误差均为相同数据和参考图下的 relative L2。image 数字来自用于
隔离 matrix consumer 的 focused trilinear probe，不是一次完整 positive-det legacy sinc
端到端运行；坐标共轭结论不依赖 sinc kernel，完整链仍被列入关闭门禁。

| 指标 | `det>0` RAS | `det<0` LAS control |
|---|---:|---:|
| local raw matrix vs FSL | `1.07603` | `0.009685` |
| 对 local matrix 做正确 x-reflection 共轭后 vs FSL | `0.018729` | 不需要 |
| 当前 `_resample_series` image vs FSL | `0.445403` | `0.019798` |
| 按 local grid `_scaled_to_world` 消费 image vs FSL | `0.020210` | 与当前同类 |

关键 x translation：

```text
FSL det>0 matrix tx       = +1.86422 mm
local det>0 matrix tx     = -1.88515 mm
local 经 x 共轭后的 tx    = +1.88559 mm
```

这组结果同时满足三个判别条件：

1. 正行列式路径明显失败；
2. 相同数组的负行列式 control 接近 FSL；
3. 只做理论上应有的 x 反射共轭即可恢复到与优化器正常数值误差同量级。

所以它不是一般配准轨迹差异或 phantom 太小造成的随机现象，而是确定的
producer→consumer 坐标失配。

### 3.3 影响范围

- pass1 6 DOF mean：`legacy.py:527-547`；
- pass2 12 DOF mean：`legacy.py:550-569`；
- mean-DWI→nodif composition：`legacy.py:571-582`；
- direct b0 replacement：`legacy.py:583-594`；
- 最终一次 sinc / applywarp resampling：`legacy.py:596-616`；
- 保存的 `MAT_*` 和 world matrices：`legacy.py:617-623`；
- `bvec_mode=corrected`：`legacy.py:624-632`；
- `compat46` 虽复制原 bvec，corrected DWI、tensor、T1/PPD、conductivity 和 FEM 仍会继承错误。

现有真实 FSL legacy/MCFLIRT fixture 的关键 affine 为负行列式，例如
`tests/test_preprocessing_legacy.py:28` 和 `:269` 的 LAS diagonal，因此 671 个测试没有触发它。

### 3.4 修复与关闭门禁

推荐统一成一个明确的 FSL radiological internal-grid 合同：正行列式时在 registration
工作数组和 matrix producer 边界正确应用 x 反射，使 producer 直接生成真正的 FSL
scaled-mm matrix；最终继续由 `fsl_matrix_to_world()` 作用到原 NIfTI storage。

不建议只把最后一个 image consumer 换成 local `_scaled_to_world()`：那会让保存的 matrix、
mean-to-nodif composition、direct b0 replacement 和 corrected bvec 继续处于混合合同。

关闭本项至少需要：

1. 同一数组的 `det>0`/`det<0` 物理配对 fixture；
2. 不对称图像、x translation、三轴 rotation；
3. 逐项比较 raw matrix、world-corner displacement、pass1/pass2 mean、direct b0、最终 DWI；
4. 比较 `compat46` 和 corrected-bvec 两种路径；
5. 同输入真实 FSL MCFLIRT/FLIRT A/B；
6. 正行列式完整 legacy raw→tensor 回归，不能只测 matrix helper。

## 4. D2C-030-061：BET inward ray 漏采 endpoint 和 sub-mm stencil

### 4.1 两个 backend 的同一错误

optimized backend：

- `brain_mask.py:194-207` 计算并检查 1 mm 与 7 mm endpoint 是否越界；
- `brain_mask.py:211-224` 却使用 `range(1, 7)`，实际只采 1–6 mm；
- 因而 7 mm 只参与 bounds check，不参与 `Imin`。

reference/vectorized backend：

- `brain_mask.py:492-511` 创建 1–7 mm 坐标并检查第 7 个点；
- `brain_mask.py:513-519` 只读取 `voxel_*[:6]`，同样丢掉 7 mm；
- 两个 backend 都固定 1 mm 步长。

FSL `bet2.cpp:411-415,466-495` 的实际合同是：

1. `dscale = min(xdim, ydim, zdim, 1.0)`；
2. 采 1 mm 点；
3. 明确把 7 mm endpoint 纳入 `Imin`；
4. 以 `dscale` 扫描中间位置，亚毫米 voxel 会得到更密的 samples；
5. 近表面 samples 进入 `Imax`，完整 inward samples 进入 `Imin`。

### 4.2 最小反例

在 1 mm grid 上令 ray 的 1–6 mm intensity 均为 100，仅 7 mm endpoint 为 0，并取：

```text
t2 = 0
tm = 100
t  = 10
f  = 0.2
f**0.275 = 0.642367
```

得到：

```text
local Imin / fit force = 100 / +0.715266
FSL   Imin / fit force =   0 / -1.284734
local normal displacement = +0.035763 mm
FSL   normal displacement = -0.064237 mm
```

这里的位移示例固定 mean edge length 为 1 mm，只比较 surface update 中的法向 fit 项。
这不是小数点级误差，该项的更新方向直接翻转。另一个 0.5 mm voxel 反例把暗点放在
1.5 mm：FSL 的 `dscale=0.5` 会采到，本地固定 1 mm 不会采到。

### 4.3 影响范围

BET mask 会进入：

- raw/nomoco/legacy 的 nodif mask；
- GRE magnitude brain mask 与 corrected mask；
- TOPUP corrected-first-b0 mask；
- EDDY mask、joint mask、GP voxel selection、outlier 和 DTIFIT support；
- 最终 tensor fit 的空间 support，并继续传播到 T1 tensor、conductivity 和 FEM。

现有 `tests/test_preprocessing_brain_mask.py:255-278` 只用平滑 2 mm sphere，并以 Dice
`>0.985` 验收；它不能区别单独 7 mm 暗点，也不能检查 0.5 mm dense stencil。

当前反例确定证明的是 sampler、`Imin` 和单步法向 fit 项分叉，以及该 mask 的正式消费路径；
本轮没有把完整 BET 迭代跑到最终 surface/mask 后再与真实 `bet2` 对抗，也没有直接测得由此
产生的最终 tensor/FEM 数值差。因此完整 mask A/B 是关闭门禁，而不是已经完成的证据。

### 4.4 修复与关闭门禁

1. 两个 backend 共用一个从 FSL C++ loop 逐项转录的 sampling contract；
2. 分别测试 1 mm、0.5 mm 和 anisotropic voxel；
3. 直接断言 `Imin/Imax`，不能只测最终 Dice；
4. 固定上述 7 mm force-direction reversal 反例；
5. 用真实 `bet2` 对抗 phantom 比较 surface 和 mask；
6. 因 mask 会传播，修复后重跑 nomoco、legacy/GRE、TOPUP→EDDY 和正式 fit branch matrix。

## 5. D2C-030-062：conductivity 的 `eigh` 与 SimNIBS 4.6 `eig` 不逐输出一致

### 5.1 实现差异和准确定位

- 本地 `conductivity.py:10-13` 对实对称 tensor 使用 `np.linalg.eigh()`；
- SimNIBS 4.6 `utils/cond_utils.py:9-19` 使用一般求解器 `np.linalg.eig()`；
- 官方随后在 `cond_utils.py:22-25` 把返回 eigenvectors 当作正交基重构。

互异特征值时，两者通常只有符号和舍入差异。重复特征值时，一般 `eig` 不保证重复子空间
返回正交向量，而官方重构公式假设正交，因此可能得到秩亏 conductivity。重复特征值不是
非法输入：各向同性和轴对称 tensor 都可以出现。

### 5.2 固定反例

令：

```text
q = [0.503178628918432, 0.10541287877480549, -0.8577292069110012]
A = I + 2 q q^T
eigenvalues(A) = [3, 1, 1]
scalar conductivity c = 0.126
mode = vn
```

冻结 NumPy 2.3.0 下，逐句官方公式与本地实现得到：

```text
official repeated-eigenvector abs dot = 0.9985485785667437
official conductivity determinant     = 1.0672731640583441e-18
local conductivity determinant        = 0.0019743676283966913 (positive/full-rank)
local vs literal-official relative L2 = 0.4060725208094854
```

因此，这是确定的兼容分叉，但不应把本地稳定实现误写成科学算法错误：`eigh` 才是实对称
eigensystem 的自然选择。正式 FEM workflow 调用真实 SimNIBS，而 standalone
`tensor-to-mesh` 调用本地 converter；所以相同 tensor 在两个入口上可以得到不同 conductivity。

### 5.3 建议合同与关闭门禁

1. 保留 `eigh` 作为明确命名和记录的 stable 模式；
2. 如果产品需要 literal SimNIBS 4.6 compatibility，增加显式 strict 模式逐句使用 `eig`；
3. strict 模式对重复特征值、非正交 basis 和近秩亏结果写 QA，不得静默冒充稳定结果；
4. 固定上述反例，同时比较 local stable、literal formula 和真实 `cond_utils`；
5. 文档明确正式 SESSION 与 standalone converter 的模式边界。

如果产品目标只要求数学上稳定的 conductivity，而不是复制官方病态输出，可以不把 stable
算法降级成 `eig`；但必须删除“任意有效输入与 SimNIBS 逐输出相同”的表述。

## 6. D2C-030-063：FEM cache identity 仍可能碰撞

### 6.1 复合 solver 只要求命中任意文件

`workflow.py:285-317` 为 solver 定义 glob，`workflow.py:368-380` 只要 native file 列表
非空就令 `cache_safe=True`。这不能证明复合 solver 的每个必需组件都被绑定：

- `petsc_pardiso` 同时需要 PETSc 和 MKL，但当前环境的 identity 只找到了 MKL；
- `mumps` 需要 MUMPS Python extension/context 和 native MUMPS libraries，identity 没有绑定
  package-private `_mumps...so`；
- `hypre` 当前没有找到候选文件，因此会保守禁用 cache，这一项本身安全。

当前环境现场结果：

```text
pardiso       cache_safe=True   -> MKL .so.2/.so.3
hypre         cache_safe=False  -> no candidate
mumps         cache_safe=True   -> $CONDA_PREFIX/lib/lib*mumps*_seq.so, missing Python extension
petsc_pardiso cache_safe=True   -> MKL only, missing PETSc extension/library
```

实际执行文件还包括：

```text
site-packages/mumps/_mumps.cpython-311-x86_64-linux-gnu.so
site-packages/petsc4py/lib/arch-linux-c-opt/PETSc.cpython-311-x86_64-linux-gnu.so
site-packages/petsc4py.libs/libpetsc-*.so
site-packages/petsc4py.libs/libHYPRE-*.so
```

SimNIBS `simulation/fem.py:16-17,700-713` 明确显示 `petsc_pardiso` 经过 PETSc `KSPSolver`，
`mumps` 经过 `MUMPS_Solver`/context。这些不是可省略的旁路依赖。

### 6.2 Python 执行模块和 RECORD 不完整

`workflow.py:341-348` 只哈希六个模块：`run_simnibs.py`、`sim_struct.py`、`fem.py`、
`pardiso.py`、`cond_utils.py`、`mesh_io.py`。真实 SESSION 在 `sim_struct.py:45-53,2104`
还直接导入或调用 `electrode_placement.py`、`transformations.py`、`file_finder.py`、
`csv_reader.py` 等。

当前只哈希 `.dist-info/RECORD` 的文本，不会按 RECORD 逐项重新校验已安装文件内容。因此
同版本环境中原位修改一个遗漏模块、保持 RECORD 文本不变，runtime identity 可以完全不变，
但电极放置或 subject-volume 输出已经改变。

### 6.3 候选路径不等于动态加载器实际路径

当前只 glob `sys.prefix/lib`、`Library/bin` 和 `bin`。例如官方 `pardiso.py:54-66` 通过
`ctypes.CDLL("libmkl_rt.so")` 让动态加载器解析实际文件；若 `LD_LIBRARY_PATH` 前置另一份
MKL，实际 solver 已改变，而 identity 仍可能哈希 `sys.prefix/lib` 中的旧文件。

### 6.4 触发后果与修复门禁

这是条件性 P2：只有 runtime 漂移后再次命中 cache 才触发；但触发时不会重新运行 FEM，
会静默返回旧科学结果。

修复应：

1. 为每个 solver 定义必需 component groups，必须每组至少命中一个；
2. 哈希实际 import extension 和动态加载器最终选中的 native libraries；不能解析时禁用 cache；
3. 校验参与执行的 RECORD 条目对应的当前文件，而不只哈希 RECORD 文本；
4. 补齐电极放置、transform、file resolution、CSV/tag 等执行闭包；
5. 增加三类碰撞测试：遗漏 Python 模块修改、package-private extension 替换、动态库解析路径改变；
6. 修复前，除非能够完整解析并绑定实际执行闭包，否则所有真实 FEM cache hit 都应保守
   禁用；`hypre` 在当前环境已经因身份不完整自动禁用。

## 7. D2C-030-064：TOPUP coefficient NIfTI 缺少 FSL intent

### 7.1 当前 writer 与官方 header 合同

本地 `topup.py:2697-2710` 已写入：

- coefficient grid 的 knot spacing affine/pixdim；
- qform translation 中的原 field matrix size；
- qform code `1`、sform code `0`。

但没有写：

- cubic coefficient intent code `2016`；
- `intent_p1/p2/p3 = 原 dense field voxel sizes`。

FSL `topup_file_io.h:101-107` 定义 cubic coefficient intent `2016`；
`topup_file_io.cpp:98-135` 写 intent 和三个原 voxel-size 参数；reader 在 `:229-260`
依 intent 区分 spline coefficient 与 dense field，并在 `:286-307` 结合 intent params、
pixdim 和 qform offsets 重建 field geometry。

本地产物 intent 默认为 0。真实 `TopupFileReader` 会走 unknown/dense-field 分支，而不是把它
识别成 cubic spline coefficients。

### 7.2 影响和为什么当前数组没有立刻坏掉

当前本地 TOPUP→EDDY 在 `topup_eddy.py:137-149` 传给 local EDDY 的是
`field_hz.nii.gz` 和 corrected mask，不消费 `field_coefficients.nii.gz`。因此当前主链的
corrected DWI 没有因这个 header 直接改变。

但是公开 coefficient artifact、QA inventory 及“可由 FSL EDDY/applytopup 继续消费”的
互操作合同不成立。这是确定的输出合同问题，不应仅因当前内部 consumer 绕过它而关闭。

### 7.3 修复与关闭门禁

1. 设置 `intent_code=2016`；
2. 设置 `intent_p1/p2/p3` 为原 dense field voxel sizes；
3. 保持 pixdim 为 knot spacing，qform translation 为 field matrix size；
4. 保持 qform code `1`、sform code `0`，避免普通 neurological swapping 改写 coefficient grid；
5. header 逐字段对比真实 FSL `_fieldcoef`；
6. 按 FSL `<prefix>_fieldcoef`、`<prefix>_movpar.txt` 等 bundle 命名和 staging 合同准备产物，
   再用真实 FSL reader/EDDY 读取；仅修 header 不能单独证明 drop-in `--topup=<prefix>`；
7. 将 coefficients 展开为 dense field，再与本地 `field_hz` A/B；
8. 增强 `tests/test_preprocessing_topup.py:450-489`，当前测试只检查文件存在和 shape。

## 8. 已确认的非字面等价，但不列为本地算法 bug

### 8.1 GRE：本地匹配 intended/patched 官方逻辑，不匹配安装脚本字面执行

官方 `dwi2cond.prepro.source.sh:168` 以五个参数调用 `EDDY_CORRECT`；但
`dwi2cond.functions.source.sh:235-240` 使用 `[ $# -gt 5 ]` 才启用 warp。恰好五个参数时，
安装版脚本字面执行不会进入 applywarp。本地 `legacy.py:596-610` 会正确组合 displacement。

这应解释为本地实现了官方显然想执行的、把 `-gt 5` 修为 `-ge 5` 后的 intended path，
不是本地新缺陷。后续 GRE A/B 必须同时保留 literal oracle 和只修该参数计数的 patched oracle，
不能笼统写“与安装脚本逐语句相同”。

### 8.2 EDDY 默认随机种子是可复现性偏差

官方 `dwi2cond.functions.source.sh:42-83` 调用 FSL EDDY 时不传 `--initrand`；FSL
`EddyCommandLineOptions.cpp:62-64,242-246` 的默认值为 0，随后
`HyParEstimator.cpp:48-79` 使用 `srand(time(NULL))`。本地 `cli.py:247`、
`workflow.py:60`、`topup_eddy.py:48` 和 `eddy.py:3325` 的默认 seed 为 1；现有公开 EDDY
benchmark 也让两侧都使用 seed 1。

本地选择有利于可复现，不是 EDDY 公式错误；但当前证据验证的是 deterministic seed-1
variant，不是 stock SimNIBS invocation。建议保留默认 1，同时文档明确 deliberate deviation，
并提供 `random_seed=None` 或 strict-SimNIBS mode 表示不传 `--initrand`。

### 8.3 TOPUP→EDDY 的实际 consumer 不是“完整 TOPUP products”

官方 `eddy --topup=<prefix>` 会读取 spline coefficients，并可按 acquisition index 消费
TOPUP movement。当前本地 `topup_eddy.py` 只把 dense `field_hz` 和 corrected mask 传给
local EDDY；coefficient 和 movement 只是记录 artifact。

在当前固定的单 acquisition row、first TOPUP movement 为零的合同下，没有定位出新的确定
主链错误；但文档不应写“complete TOPUP products are passed to EDDY”，也不能把这一结论
外推到未来 multi-acquisition 支持。

### 8.4 本地工程扩展

内容寻址 cache、stage manifest、事务发布、失败目录、external Hz field、external world
transform 和 standalone tensor-to-mesh 都是本地扩展。它们不等于官方 shell 原样控制流。
当前事务是每 stage/每 FEM mode 的事务，不是整个 DAG 的全局原子提交；若 tensor publish
成功而随后 FEM 失败，新 tensor 仍可能可见。应在运行语义中说明，不应误写为本轮算法分叉。

## 9. 尚未关闭的高优先级证据缺口

### 9.1 TOPUP/EDDY 正行列式坐标边界

本地 TOPUP `topup.py:2639-2673` 和 EDDY `eddy.py:3353-3366,3392-3411` 在 storage
reorient 后主要把数组、正 voxel sizes、PE axis/sign 传入 core，affine determinant 不再
进入核心。官方 NEWIMAGE 会把 positive-det 输入转为 radiological internal storage，
EDDY `ECScanClasses.cpp:327-343` 的 movement sampling 也使用 internal sampling matrix。

现有真实 TOPUP/EDDY fixture 仍主要是负行列式。仅凭静态代码不能证明当前 core 同时正确
覆盖两种 handedness；鉴于 `060` 已证明同类边界确实能产生 bug，本项风险较高。但是，在
获得专门真实 FSL 配对 A/B 前，本报告不把它虚报成已确认问题。

需要的判别门禁：同一不对称数组的正/负 determinant、优先 x/x- PE，逐项比较 TOPUP field、
movement、corrected pair，以及 EDDY EC/movement parameters、rotated bvec、mask 和 corrected DWI。

### 9.2 FNIRT 位移场仍不是逐值相同

当前冻结证据：

```text
corrected-image relative L2 = 0.001298916
dense-field relative L2     = 0.175488519
max component error         = 0.994548967 mm
```

它通过当前 image `<0.005`、field `<0.25`、max `<1.2 mm` 门槛，但位移场“不相同”是确定事实。
现有证据没有把差异定位为坐标、单位、mask、spline、LM 或 PCG 公式错误，因此这里仍记为
验证缺口，不编造新的 bug 编号。

PPD 使用 field Jacobian；很小的 warped-image L2 不能推出 tensor orientation、conductivity
或 FEM 等价。若目标是“任意输入与 FSL 6.0.4 相同”，当前证据不够；若目标是“冻结 fixture
通过预注册端点门槛”，当前证据成立。

### 9.3 真实完整 raw→FEM A/B 仍缺失

本轮没有重新运行完整 HCP raw DWI→TOPUP/EDDY→FNIRT→PPD→conductivity→四种
conductivity mode（`scalar/vn/dir/mc`）FEM 的同输入端到端 A/B，也没有在受限 sandbox
内启动完整 SimNIBS FEM solve。solver backend 是另一验收维度；历史阶段测试和 synthetic
endpoint 不能替代这条最终证据链。

## 10. 本轮正证据

本轮逐源码和 focused tests 没有发现下列路径的新确定分叉：

- 当前 NewNifti-compatible storage orientation 的 float32 Gram-Schmidt、signed permutation
  与 strict tie-breaking；
- exact-b0 选择、nomoco 不把 b0 registration 错施加到 DWI；
- DTIFIT/WLS design、FSL tensor component order、`S²/1` weighting、两遍 fit、S0 floor、
  unweighted SSE；
- GRE/FUGUE 的 field→voxel shift、forward warp、MI FLIRT 和一次最终 applywarp 高层顺序，
  但会继承 `061` 的 mask 问题；
- TOPUP 九级 `b02b0_nosubsamp` schedule、主要 LM/PCG accept/reject 顺序；
- EDDY b0 threshold、first-b0 scaling、五轮迭代、quadratic EC、spline、GP/outlier replacement
  和 Jacobian resampling 固定子集；
- 6/12 DOF T1 注册 producer、nonlinear schedule、PPD、post-mask 和 tensor decomposition；
- 正式 FEM workflow 调用真实 SimNIBS SESSION，不会静默改用 local tensor-to-mesh；
- backend 失败没有静默回退到 reference/nomoco。

这些正证据只支持列出的边界，不覆盖 `060..064`，也不等同于任意输入形式证明。

## 11. 建议整改顺序与统一验收

建议按传播风险排序：

1. **先修 `060` legacy handedness/matrix contract**，因为它会直接改变 corrected DWI；
2. **再修 `061` BET sampler**，因为 mask 同时传播到多个预处理分支；
3. **修 `063` FEM cache identity**，在身份闭包不完整时宁可禁用 cache；
4. **明确 `062` stable-vs-literal conductivity 合同**，不要为了字面一致无说明地退回病态 `eig`；
5. **修 `064` TOPUP header** 并用真实 FSL reader 关闭互操作门禁；
6. 增加 TOPUP/EDDY 正行列式配对 oracle；
7. 最后运行完整 branch matrix、全部真实 FSL tests，以及至少一个真实 HCP
   raw→aligned tensor→conductivity/FEM A/B。

每项整改都应遵守“一个问题、一个可判别反例、一个真实 oracle、一个独立提交”的顺序。
不能用提高 Dice 容差、放宽 FNIRT field 阈值、只看 pytest 全绿、只看局部 helper 或只看
最终 image 来代替对应阶段的数值/坐标合同。
