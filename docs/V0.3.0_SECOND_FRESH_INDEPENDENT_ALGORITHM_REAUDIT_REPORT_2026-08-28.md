## 结论

这次又找到了 **2 个新的 P1 条件性科学正确性问题**，编号为
`D2C-030-053` 和 `D2C-030-054`。因此当前不能再表述为“没有大问题，只剩很小问题”。

但结论也不是“主流程整体失效”：本轮没有发现 P0、没有重新打开上一轮
`D2C-030-046..052` 的公式/控制流修复，也没有发现新的 DTIFIT、TOPUP public mask、
PPD、conductivity 或 FEM 事务问题。两个新问题分别是：

1. FSL 重定向的离散轴判定算法没有被精确复现。常规轴对齐和轻度倾斜输入通常一致，
   但有效的高倾斜 NIfTI 可选择不同的轴置换，继而改变 PE 轴和后续张量链。
2. FNIRT 在项目修复前声明允许的较新 NumPy/Numba/NiBabel 组合下越过了仓库自己的真实
   FSL 验收阈值；同一源码在发布验证栈通过，在另一允许组合失败。

这两项都不是普通报错或文档问题：它们位于正式科学路径，并可改变 warp、mask、tensor
或 conductivity/FEM 输入。不过第一项触发输入较少见，第二项只在特定依赖组合中确认；
本报告不会把合成 fixture 的差异外推成任意真实被试的误差分布。

按用户授权整改后，第二项的未验证安装组合已由精确 NumPy/Numba 依赖合同阻断；算法源码
没有改动。它的“依赖越界导致门禁失败”已关闭，但发布栈仍有 `17.55%` 位移场相对 L2
残余，继续作为真实 HCP/PPD/FEM 前的证据边界。第一项 orientation 算法差异不在本轮
FNIRT 修复范围内，仍为 open。

## D2C-030-053：`fslreorient2std` 的轴判定并不等于 NiBabel `io_orientation`

### 实现差异

本地 `src/dwi2cond_xp/preprocessing/orientation.py:13-29` 直接调用
`nib.orientations.io_orientation()`，随后变换到 RAS 或 LAS。官方
`/usr/local/fsl/bin/fslreorient2std:104-132` 则先由 `fslhd` 得到
`sform_*orient`/`qform_*orient` 标签，再让 `fslswapdim` 按这些标签执行离散置换。

这些标签来自 NewNifti 的 `nifti_mat44_to_orientation`：

- `/usr/local/fsl/src/NewNifti/legacyFunctions.cc:485-556` 以 float 归一化并按固定顺序做
  Gram-Schmidt；
- `legacyFunctions.cc:563-596` 枚举所有有符号置换，并以固定遍历/tie-breaking 选择最大
  trace；
- NiBabel 使用自己的 SVD/polar orientation 判定。二者对一般倾斜矩阵不是同一个算法。

### 真实 FSL 反例

固定随机种子 `20260828`，对 30 个由旋转、各向异性尺度、平移和正/负 determinant
组成的有效 4D NIfTI 做真实 `fslreorient2std` A/B，第 11 个输入稳定分叉：

```text
affine =
[[ 0.601011634,  1.401550531, 0.942415297,  92.374305725],
 [ 0.538023829, -1.309910774, 1.315203071, -25.246667862],
 [-0.660363793,  0.208347276, 1.929259419,  25.766641617],
 [ 0.000000000,  0.000000000, 0.000000000,   1.000000000]]
det(affine[:3,:3]) = -5.065160968553407
```

按 FSL 自己的最大 trace 度量，该矩阵到所选离散 cardinal orientation 的旋转角为
`59.284274°`。

| 实现 | 输出 shape | 离散结果 |
|---|---:|---|
| FSL 6.0.4 | `(3, 4, 5, 2)` | 仅翻转 x/y，保持轴次序 |
| 本地 + NiBabel 5.4.2 | `(4, 3, 5, 2)` | 交换 x/y 后翻转 |
| 本地 + NiBabel 5.3.3 | `(4, 5, 3, 2)` | 选择另一组轴置换 |

FSL 与 NiBabel 5.4.2 本地结果的数组不相等，qform/sform 最大绝对差约
`2.002562`。同一项目源码在两个当前允许的 NiBabel 小版本中也产生不同 shape，说明该
行为既不等于 FSL，也未被项目自身固定。

当前反例若继续使用同一个 `y` PE 参数，输出 voxel-y 的单位物理方向为：

```text
FSL:       [-0.7263169145, 0.6788270066, -0.1079705277]
local 5.4: [ 0.5765209110, 0.5160998071, -0.6334545195]
dot = 1.6703e-08, angle = 89.999999°
```

SimNIBS 4.6 官方脚本在
`dwi2cond.prepro.source.sh:35-47,117-143` 先重定向 DWI，再使用未改写的
`PHASEDIR`/bvec 文件；本地 TOPUP/EDDY 也在
`topup_eddy.py:65-76,109-145` 与 `eddy.py:3353-3405` 采用相同高层次序。因此轴判定
分叉会把相同 PE 字符串解释到不同的物理方向，并可传播到 TOPUP/EDDY、DTI tensor 和
最终 conductivity/FEM。

### 触发范围

固定种子的离散方向调查每个角度上限采样 5000 个 signed-permutation 邻域：

| 距最近 cardinal orientation 的扰动上限 | FSL/NewNifti 与 NiBabel 5.4.2 分叉数 |
|---:|---:|
| 5°、10°、20°、30°、40°、45° | `0 / 5000`（各组） |
| 60° | `111 / 5000` |
| 90° | `170 / 5000` |

这是用于刻画当前反例区域的随机调查，不是对所有矩阵的形式证明。可以确定的是：普通
轴对齐/轻度倾斜 fixture 不足以覆盖该问题，而官方工具明确接受带有效 orientation 标签的
NIfTI，并没有把高倾斜矩阵排除在接口外。

### 整改与验收要求

1. 在本地精确实现 FSL 6.0.4/NewNifti 的 float32 归一化、Gram-Schmidt、216 次有符号
   置换枚举及严格 `>` tie-breaking；不要继续把 NiBabel `io_orientation` 当作 FSL oracle。
2. 保留 sform 优先、qform fallback、存储 handedness 和 q/s code 合同。
3. 用上述精确 affine 加入真实 FSL data/shape/qform/sform A/B；同时覆盖 qform-only、
   sform-active、正/负 determinant、全部 48 个 signed permutation 和高倾斜输入。
4. 增加 producer 级 PE 验收：比较重定向后 PE voxel 轴对应的物理向量，不能只比较
   `aff2axcodes` 或“世界坐标样本仍保持”。
5. 测试必须在 NiBabel 5.3 与 5.4 都得到同一个项目结果，证明算法不再随 NiBabel
   orientation 内部实现漂移。

## D2C-030-054：允许依赖组合下 FNIRT 越过真实 FSL 门禁

### 支持合同与复现环境

`pyproject.toml:33-41` 修复前声明：

```text
nibabel>=5,<6
numba>=0.64,<1
numpy>=2,<3
scipy>=1.11,<2
```

本轮在相同 Python 3.11、相同 SciPy 1.17.1、单 worker、
`OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`、独立 Numba cache 下，对
`tests/test_preprocessing_nonlinear.py:438-560` 的 `24×23×22` positive-determinant
FNIRT→真实 FSL endpoint 做了对照：

| 环境 | NumPy | Numba | NiBabel | corrected image relative L2 | field relative L2 | field max abs |
|---|---:|---:|---:|---:|---:|---:|
| 发布验证栈 | 2.3.0 | 0.64.0 | 5.3.3 | `0.0012989163` | `0.175488519` | `0.994548967 mm` |
| 当前允许的新组合 | 2.4.6 | 0.66.0 | 5.4.2 | `0.0061349105` | `0.394825930` | `1.652568578 mm` |
| 仓库门禁 | — | — | — | `<0.005` | `<0.25` | `<1.2 mm` |

发布验证栈的两个目标测试为 `2 passed in 48.13 s`。较新组合下，排除仅因该环境缺少
`h5py` 而无法收集的 `tests/test_leadfield.py` 后，显式 FSL 测试为：

```text
1 failed, 623 passed, 1 skipped in 261.03s
```

唯一失败即 `test_positive_determinant_fnirt_endpoint_matches_real_fsl`。自定义独立探针还
确认三个门禁都会失败；不是 pytest 并发、BLAS 线程或共享 cache 假象。两个本地 field
之间的 relative L2 为 `0.317564716`，max abs 为 `1.280384328 mm`。

### 当前原因边界

追加的首步 trace 已把直接机制定位到线性系统与 PCG 数值语义，而不是输入准备或 FNIRT
高层调度：

- 两环境读取同一份冻结 float32 输入后，prepared reference/moving 和 level-1
  reference/moving 均逐字节相同，初始 mean-SSD 也同为 `1027.4153941770394`；
- NumPy `inv/pinv` 路径生成的初始 bias coefficients 最大差仅 `1.0115e-11`；由此形成的
  gradient 最大差 `1.0836e-13`、Hessian data 最大差 `5.5511e-17`，稀疏结构完全相同；
- 该首层阻尼 Hessian 在未缩放参数坐标下的二范数条件数约为 `2.32e19`
  （发布栈）与 `2.57e18`（较新组合）。后续分块复核确认这个原始数值主要来自强度
  多项式参数的量纲跨度，不能直接作为 PCG 的有效条件数或误差放大倍数；见下文追加
  条件数复核；
- 发布验证栈首步 PCG 在第 14 次的 residual 为 `0.018350887`，到第 16 次才以
  `0.000982540 < 1e-3` 停止；较新组合在第 14 次已得到 `0.000191558`，提前两步停止。
  两个 solution 的 relative L2 已达到 `0.0123081`，第一次候选 cost 因而变成
  `16.8725596` 对 `16.9150533`；
- level 1 的 accept/reject 图样尚相同，第一次真正的 LM 决策分叉出现在 level 2
  iteration 3：发布栈把 `1.1925182 → 0.4633302` 接受，较新组合得到
  `0.8218711 → 2.7513620` 并拒绝，随后增加 damping。最终 level-4 cost 为
  `0.00713885` 对 `0.01074889`。

本地 `topup_optimizer.py:157-187` 在 PCG 中调用 `np.linalg.norm` 和 `np.dot`；官方
`/usr/local/fsl/src/miscmaths/cg.h:41-70` 使用 FSL 构建中的 `NormFrobenius` 与
`DotProduct`。两者公式相同，但归约顺序和库实现不是同一个固定数值合同。本地 spline
初始化还通过 `topup.py:2443-2449` 的 NumPy inverse/projector 与
`fnirt.py:565-578` 的 `pinv` 构造映射，也没有锁定为 FSL basisfield 的具体运算顺序。

可行性探针将 PCG 的 dot、norm、vector update 和 CSR row sum 全部改成固定标量顺序，
而不改变 `1e-3` tolerance 或最大迭代数。对两套仅含上述微小差异的首层系统，结果都恢复
为 16 次迭代，residual 分别为 `0.000975016/0.000973389`，solution norm 只差
`1.57e-6`。这证明问题可以通过固定官方等价的归约/线性代数语义修复，不需要降低分辨率、
减少迭代或放宽门禁。

本轮仍没有把全部差异武断归到单独一个包：正常运行同时变化了 NumPy 和 Numba；禁用
JIT 后两环境的首步仍不同，证明 NumPy 路径至少参与了漂移。可以确认的是，本地当前对
版本相关 `dot/norm/inv/pinv` 的依赖不满足“固定 FSL 6.0.4 数值子集”的稳定实现合同。

后续隔离将较新环境的 NumPy 单独替换为 `2.3.0`，同时保留 Numba `0.66.0`、SciPy
`1.17.1` 和 NiBabel `5.4.2`，真实 FSL endpoint 恢复通过；因此 NumPy `2.4.6` 是三个
门禁同时失败的直接必要条件。该隔离组合仍在一个严格单测中暴露 Numba `0.66.0` 的归约
差异：dense PCG 的 solution 和迭代数逐位相同，但 optimized/reference residual 分别为
`1.5396163e-19/1.6229396e-19`。这不是新的科学端点失败，却说明 Numba `0.66.0` 也没有
满足项目已经声明的逐位 reference/optimized 数值合同。

### 整改与验收要求

1. 发布安全上先把 nonlinear/TOPUP 的受支持数值栈限定到实际通过真实 FSL 门禁的组合；
   在没有做组合隔离前，不要凭猜测分别设置宽松上限。
2. 增加最小/最大支持版本 CI 矩阵，每个组合都运行真实 FNIRT、TOPUP 和关键 PPD endpoint；
   不得靠放宽现有阈值把本问题标成通过。
3. 记录每级、每次 LM 的 cost、accept/reject、damping、PCG iteration/residual，找出两环境
   第一次 trajectory 分叉的位置，再决定是否需要固定归约、dtype 或线性代数路径。
4. 若继续支持宽版本范围，应让同一 workers/thread 设置下的关键归约和分支判据具有明确
   的版本稳定合同；无法稳定时应在运行时拒绝未验证组合，并在 provenance 中记录版本。
5. 修复后除 synthetic endpoint 外，还要重新运行真实 HCP nonlinear
   producer→PPD tensor→conductivity/FEM A/B；当前合成数据不能替代真实被试误差评估。

### 本轮修复与最终判定

本轮采用发布安全修复，没有改写 FNIRT、LM 或 PCG 算法：

1. `pyproject.toml` 将普通 wheel 安装的数值依赖从 `numpy>=2,<3`、`numba>=0.64,<1`
   收紧为与冻结 SimNIBS 4.6 环境相同的 `numpy==2.3.0`、`numba==0.64.0`；
2. `tests/test_release_environment.py` 增加发布元数据回归，防止主依赖再次绕开
   `constraints-simnibs46.txt` 和 `environment.yml` 的精确版本；
3. 没有放宽 image/field/max 三个真实 FSL 阈值，也没有修改四级
   `8,4,2,2` schedule、LM damping、PCG `1e-3/500` 或停止条件。

最终冻结栈完整回归为 `646 passed, 13 skipped in 60.95 s`，Ruff 全范围与
`git diff --check` 通过。用最终源码构建的 wheel SHA-256 为
`7ec8061295f0ea22e6a99477af70e87765698689e17ec8acd7f9deb49f0e92b8`；解包元数据明确为
`Requires-Dist: numpy==2.3.0` 和 `Requires-Dist: numba==0.64.0`，且未包含 `.work` 或
诊断脚本。

曾实装固定逐元素归约作为候选。它使 NumPy/Numba 两环境得到相同 endpoint，但把发布栈
field relative L2 从 `0.175488519` 推高到 `0.249524992`，几乎贴住 `<0.25` 门槛；因此
该候选被撤回，未进入最终源码。它证明“可稳定”不等于“更接近实际 FSL/Armadillo”，不能
作为官方等价修复。

最终发布栈仍得到 corrected-image relative L2 `0.0012989163`、field relative L2
`0.175488519`、field component max abs `0.994548967 mm`。进一步分解显示 FSL field
每分量 RMS 为 `1.092245 mm`，两场差值 RMS 为 `0.191676 mm`；差值向量的中位数、
95 分位和最大值分别为 `0.256695/0.594187/1.185406 mm`。这是真实的残余场差异，不能
称为位移场逐值等价。

另一方面，该合成 fixture 的形变场并非唯一可辨识：FSL 和本地相对注入解析位移的场 RMS
误差分别约 `1.02223/1.07066 mm`，两者都没有恢复同一“真值”，但校正图像彼此只差
`0.1299%`。因此当前证据支持的结论是：高层算法、坐标/单位和图像端点一致，NumPy 2.4
越界问题已由安装合同阻断；基线 `17.55%` field relative L2 仍是中等残余数值风险，不能
单凭该 fixture 判成新的公式错误，也不能宣称与官方位移场完全相同。真实 HCP nonlinear
field→PPD→conductivity/FEM A/B 仍是关闭该残余风险的必要门禁。

## 本轮排除的疑点

- **MCFLIRT thin-volume reference 双次 `fix2D` 不是新 bug。** 官方 `mcflirt.cc` 的 main
  先处理 reference，`correct()` 内再次处理 reference；moving 只处理一次。本地现有薄层
  预期与该控制流一致。
- **物理等价的混合 determinant FNIRT 路径通过。** reference positive、moving negative
  且通过 data flip+affine flip 保持同一物理图像时，corrected-image relative L2
  `0.0012989158`、field relative L2 `0.175488519`、max abs `0.994548967 mm`，与发布验证
  栈的正 determinant 结果一致。
- **FNIRT coefficient artifact 可被真实 FSL 消费。** 对上述混合手性探针，用真实
  `applywarp` 消费本地 coefficient file 后，与本地展开 warp 的 relative L2
  `2.7162e-09`、max abs `7.6294e-06`；未发现 coefficient header/order 新问题。
- 简单的 sform/qform handedness 冲突、现有 shear PPD→真实 `vecreg` 回归均通过；这些
  正结果只覆盖所测分支，不外推到任意 NIfTI。

残余差异继续保留为证据边界，不按完全算法等价关闭。

### 追加：位移场、条件数、随机性和精度复核

针对“位移场差异是否仍是算法错误”的追问，本轮在精确发布栈
NumPy `2.3.0`、Numba `0.64.0` 上重新生成同一真实 FSL endpoint，并保存 coefficient、
dense field、`iout`、`refout` 和 `jout` 做共同目标与 Jacobian 复核。结果如下：

1. 本地采样器消费官方 FSL dense field 后，与官方 `iout` 的 relative L2 为
   `8.42e-8`；本地展开官方 coefficient 与官方保存 dense field 的 relative L2 为
   `2.67e-8`。因此没有发现位移单位、pull/push 方向、坐标约定或三线性采样公式错误。
2. 在共同有效区内，本地/FSL field relative L2 为 `0.203927`，差值向量 RMS 为
   `0.340149 mm`，中位/95 分位/最大模长为
   `0.263354/0.612567/1.185406 mm`；差异位于内部和边界，不能称为逐值等价。
3. 使用同一本地强度映射与同一完整分辨率目标评估，本地场的总目标为 `1.721121`
   （data `0.442761`、regularization `1.278360`），FSL 场为 `1.727637`
   （data `0.473537`、regularization `1.254099`）。相对官方 `refout` 的共同 mask MSE
   分别为 `0.462100/0.462221`。两场位于近乎等价的浅目标谷，不支持“本地场明显优化到
   更差目标”的判断。
4. 只有 `7.605%` 的场差能量平行于 FSL warped-image 的局部梯度，约 `92.395%` 位于
   单通道标量 SSD 当地不敏感的正交方向。这解释了场差异明显而校正图像只差约
   `0.12%`，但不等于下游张量无风险。
5. Jacobian matrix relative L2 为 `0.038913`，determinant relative L2 为
   `0.032487`；由 Jacobian 极分解得到的相对旋转角中位/95 分位/最大值为
   `1.328/3.380/7.178` 度。官方 coefficient 的解析 determinant 与官方 `jout` 的
   relative L2 为 `6.37e-8`，所以这些 Jacobian 差异来自两条优化轨迹，不是本地展开
   公式。后续 PPD/conductivity/FEM 仍需真实被试门禁。
6. 该优化没有随机数路径：源码中没有 RNG、seed、`RandomState` 或 `default_rng`，
   位移 coefficient 初值为零，LM damping 与 PCG tolerance/上限固定。同输入、同版本、
   同算术路径会确定性复现。所谓“轨迹漂移”是浮点归约和近阈值分支造成，不是随机种子。
7. 一个仅改变 float32 表达式括号、moving-image relative L2 仅 `1.12e-8` 的诊断输入，
   使真实 FSL 自己输出的场发生 `0.16616` relative L2、`0.92609 mm` max-abs 变化；重复
   运行结果确定一致。这证明该小型合成 fixture 的场解对输入 ULP 高度敏感，不能把场
   差异全部归为本地公式错误。

首层条件数也做了重新解释。首层降采样后只有 `4×4×4` 网格和 `18` 个有效数据体素，
但参数为 `375` 个位移 coefficient、`64` 个 bias coefficient 和 `5` 个全局强度参数，
合计 `444`。数据项天然低秩；弯曲能正则具有不处罚低阶形变的零空间，最终依赖数据项、
正则和 LM 阻尼共同闭合。未缩放阻尼 Hessian 的对角线从 `0.020936` 到
`4.7034e16`，跨度 `2.25e18`，主要由原始强度幂多项式参数造成。FSL 实际使用对角
预条件后，同一阻尼系统满秩，二范数条件数为 `257.695`，两个 NumPy/Numba 环境在该值
上实质相同。因此原报告的 `1e18..1e19` 是原始参数化条件数，数字本身没有算错，但将其
直接解释为 PCG 的有效误差放大倍数过强；当前更准确的机制是欠辨识的浅目标、底层
dot/norm/pinv 数值差异、`1e-3` 停止阈值和后续 LM accept/reject 共同形成轨迹分叉。

不建议把整个 FNIRT 默认路径升级为 FP64。官方 FSL 的 coefficient、Hessian、LM/PCG
求解本来就是 double，而图像、插值和若干 SSD 乘积仍是 float；本地当前也遵守这一混合
精度边界。全图像 FP64 会成为第三种、非官方的算术轨迹，也不能消除目标不可辨识性。
保持官方目标、schedule、正则、停止条件和 mixed-precision 默认路径；若继续提高鲁棒性，
应先用 FSL 6.0.4 C++ 小型 oracle 锁定 `SpMat`、Armadillo/OpenBLAS `DotProduct`、
`NormFrobenius` 和 `pinv` 的逐步结果，再做最小等价实现。单纯把当前 CSR 变成 CSC 不是
修复：两者在列索引排序后对每个输出行的累加顺序逐位相同，判别探针 max diff 为 `0`。

### 追加：FSL 低层数值 oracle 与候选优化判定

随后直接使用 FSL 6.0.4 的 debug 导出和本机安装库建立了低层 oracle。官方首层初始
gradient/Hessian 输入官方 `SpMat` 列累加、Armadillo/OpenBLAS `DotProduct`、
`NormFrobenius` 和对角 PCG 后，首个 displacement step 与官方 debug coefficient 的
relative L2 为 `6.90e-6`、max abs 为 `3.66e-6`；同一官方线性系统使用当前
NumPy/Numba PCG 的 step relative L2 为 `0.107449`。这确认低层 oracle 确实复现了
官方求解器，而不是根据最终场反向调参。

但把官方 PCG 算术替换到本地微小不同的 Hessian/gradient 后，最终结果并未改善。所有
候选都使用原始四级 schedule、LM damping、`1e-3` PCG tolerance 和 500 次上限；没有
降低分辨率、减少迭代或放宽门禁：

| 候选 | corrected image relative L2 | field relative L2 | field max abs (mm) |
|---|---:|---:|---:|
| 当前冻结基线 | `0.001298916` | `0.175488519` | `0.994548967` |
| FSL 旧 OpenBLAS dot + FSL CSC matvec | `0.00368884` | `0.286491936` | `1.31699` |
| FSL Armadillo spline projector/mapping | `0.00522145` | `0.3324073` | `1.71585` |
| FSL PCG + FSL spline mapping | `0.00531527` | `0.3140585` | `1.67229` |
| 固定 1/2/4/8/16 路 dot 归约 | `0.002162..0.006084` | `0.249525..0.411167` | `1.03067..2.28410` |
| FSL float32 polynomial gradient | `0.00786640` | `0.462830984` | `1.72571` |
| float32 polynomial gradient + FSL PCG | `0.00555685` | `0.394998967` | `2.20685` |
| 上项再加 FSL spline mapping | `0.00948006` | `0.507803432` | `1.88601` |

另在第 4 层官方已接受 coefficient 上，将官方 `ScaledRef` 作为冻结强度映射输入，直接
评估本地位移-only 数据项。官方与本地 mask 为 `1258/1258` 且逐位相同，warped image
relative L2 为 `6.11e-8`、max abs 为 `3.05e-5`；gradient relative L2 为
`1.24e-5`，Hessian relative Frobenius 为 `1.05e-7`，稀疏非零数同为 `1,024,347`。
因此位移展开、三线性插值、mask、弯曲能、解析梯度和 Gauss-Newton Hessian 没有暴露
结构性差异。低层官方 step 在官方状态上可复现，但微小改变本地轨迹后不保证回到官方
浅谷；这正是欠辨识非线性问题的分支敏感性，而不是可以用单个求和替换修好的公式错误。

结论是：本轮没有保留任何 FNIRT 算法改动。当前冻结基线是全部受控候选中三项 endpoint
总体最接近 FSL 的实现；把某个低层算子改得“更像官方”却让完整 endpoint 变差，不满足
整改条件。后续若要继续降低位移场差异，应使用多个可辨识 synthetic fixture 和真实 HCP
nonlinear→PPD→conductivity/FEM A/B 共同选择方案，不得针对这一小型欠辨识 fixture
做轨迹拟合。

## 建议整改顺序

1. 先修 `D2C-030-053`：它是明确的公式/离散选择算法不一致，反例和官方源码都已闭合。
2. 保持本轮已经收紧的发布数值栈；只有新增真实 FSL 版本矩阵证据后才能恢复宽版本范围。
3. 将 `D2C-030-054` 的基线位移场残余差异带入真实 HCP nonlinear/PPD/FEM A/B，不得
   用 synthetic corrected-image 一项正结果外推完整场等价。
4. 运行真实 FSL 全测试、orientation 高倾斜 producer gate、FNIRT 多版本矩阵和 HCP
   nonlinear→tensor→conductivity/FEM 里程碑 A/B，再决定是否替换 `v0.3.0` Release。
