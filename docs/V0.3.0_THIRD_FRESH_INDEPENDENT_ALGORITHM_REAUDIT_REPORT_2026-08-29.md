- **P2**：退化输入、QA/cache、入口要求、FEM composition 或可复现身份存在确定性差异，
  但标准正式数组路径未被证明普遍错误。

- 没有运行新的完整 HCP 被试；

- 没有把合成数据 FNIRT 的误差外推为真实 HCP 张量、PPD、电导率或电场误差；
- 没有声称任意 FSL 版本、任意 NIfTI 或任意优化轨迹 bitwise 等价。

## 3. D2C-030-053：离散 orientation 算法仍不等于 FSL

### 3.1 实现差异

tag 的 `src/dwi2cond_xp/preprocessing/orientation.py:13-29` 使用
`nib.orientations.io_orientation()`，再按行列式变换到 RAS/LAS。

FSL 6.0.4 的真实链是 `fslreorient2std:104-132` → `fslhd` orientation labels →
`fslswapdim`。orientation labels 来自 NewNifti
`legacyFunctions.cc:485-596`：

1. 用 float 对三列归一化；
2. 按固定顺序执行 Gram-Schmidt；
3. 枚举 216 个有符号轴组合；
4. 只保留坐标手性相同的组合；
5. 用严格 `>` 和固定遍历顺序选择最大矩阵迹。

NiBabel 使用 SVD/polar 判定，两者不是一般仿射上的同一个算法。

### 3.2 本轮真实 FSL 复现

输入为有效、有限、非奇异 4D NIfTI：

```text
affine =
[[ 0.601011634,  1.401550531, 0.942415297,  92.374305725],
 [ 0.538023829, -1.309910774, 1.315203071, -25.246667862],
 [-0.660363793,  0.208347276, 1.929259419,  25.766641617],
 [ 0.000000000,  0.000000000, 0.000000000,   1.000000000]]

det(affine[:3, :3]) = -5.065160968553407
```

本轮在真实 `/usr/local/fsl/bin/fslreorient2std` 上得到：

| 实现 | NiBabel | 输出形状 | 与 FSL 数组相等 |
|---|---:|---:|---:|
| FSL 6.0.4 | — | `(3, 4, 5, 2)` | — |
| tag 本地 | 5.3.3 | `(4, 5, 3, 2)` | false |
| tag 本地 | 5.4.2 | `(4, 3, 5, 2)` | false |

FSL 与两个本地结果的仿射最大绝对差分别约为 `2.343966` 和 `2.002562`。同一个
输出 voxel-y PE 轴的单位物理方向为：

```text
FSL:       [-0.72631691,  0.67882701, -0.10797053]
local 5.4: [ 0.57652091,  0.51609981, -0.63345452]
dot = 1.6703e-08; angle = 89.999999 degrees
```

官方脚本和本地流程都在重定向后继续使用同一个 PE 字符串。因此这不是只影响
头信息展示：它可把 TOPUP/EDDY 的 PE 方向放到不同物理轴，继而传播到形变、张量、
PPD、电导率和 FEM。

### 3.3 整改要求

1. 精确实现 FSL 6.0.4/NewNifti 的 float32 归一化、Gram-Schmidt、带符号排列
   枚举和严格并列判定规则；
2. 保留 sform 优先、qform 备用路径、q/s code 和存储坐标手性；
3. 增加上述仿射的真实 FSL data/shape/qform/sform A/B；
4. 增加生成端级 PE 物理向量断言，不得只检查 `aff2axcodes`；
5. 在 NiBabel 5.3/5.4 下必须得到同一个项目结果。

## 4. D2C-030-054：公开 tag 的 FNIRT 依赖稳定性仍未关闭

### 4.1 tag 的安装要求与验证要求不一致

tag `pyproject.toml:33-41` 声明：

```text
nibabel>=5,<6
numba>=0.64,<1
numpy>=2,<3
scipy>=1.11,<2
```

但 `constraints-simnibs46.txt` 和 `environment.yml` 的验证栈是 NumPy `2.3.0`、Numba
`0.64.0`、NiBabel `5.3.3`、SciPy `1.17.1`。tag 的
`tests/test_release_environment.py:13-27` 只检查冻结文件彼此一致，不检查 project
依赖；CI 和 Release 流程直接 `pip install .[...]`，没有应用 constraint。
因此普通 wheel 安装仍可解析到未经验收检查验证的组合。

当前未提交工作树已把 NumPy/Numba 改为精确 pin，并添加 project 元数据回归。这是
合理的发布安全缓解，但在 commit/tag/Release 更新前，公开 `v0.3.0` 的问题状态仍为待修复。

### 4.2 本轮同输入真实 FSL 复现

测试节点为
`tests/test_preprocessing_nonlinear.py::test_positive_determinant_fnirt_endpoint_matches_real_fsl`，
固定 `24×23×22` 输入、单工作线程、OpenBLAS/OMP 单线程和真实 FSL FNIRT：

| 环境 | NumPy | Numba | NiBabel | 校正图像相对 L2 误差 | 场相对 L2 误差 | 结果 |
|---|---:|---:|---:|---:|---:|---:|
| 冻结验证栈 | 2.3.0 | 0.64.0 | 5.3.3 | `<0.005` | `<0.25` | `1 passed in 37.13s` |
| tag 允许的新组合 | 2.4.6 | 0.66.0 | 5.4.2 | `0.0061349105` | `0.3948259303` | failed |

仓库验收检查是 image `<0.005`、场 `<0.25`、分量最大误差 `<1.2 mm`。新组合至少前两个
验收检查确定失败；这一结果来自真实 FSL 比较。

此前的轨迹记录已将第一次分叉定位到底层线性代数/PCG 数值语义：极小的 inverse、
gradient、Hessian 与归约差异改变 PCG 停止点，随后改变 LM accept/reject。当前没有证据
指向新的坐标、单位、spline expansion 或掩膜公式错误，也没有 RNG 路径；但这仍说明
项目的宽依赖范围不满足固定 FSL 6.0.4 子集的稳定计算要求。

冻结栈本身也只能称为“通过现有端点验收检查”，不能称为位移场逐值相同。既有冻结证据中
场相对 L2 误差约 `0.17549`，真实 HCP PPD/conductivity/FEM A/B 仍未完成。

### 4.3 整改要求

1. 先将普通 wheel 元数据、constraint、environment 和 CI 安装要求统一到验证过的精确
   NumPy/Numba 组合；
2. 增加 wheel METADATA 回归，不能只检查 constraint 文本；
3. 增加最小/最大受支持组合的真实 FNIRT/TOPUP/PPD 验收检查；
4. 不得通过放宽 image/field/max 阈值关闭问题；
5. 若未来重新放宽依赖，应先固定或显式验证 PCG/LM 的版本稳定语义。

## 5. D2C-030-055：原始数据 QA 拟合模式未进入缓存标识

`workflow.py:843-853` 的 `run_raw_fit()` 实际将
`config.fit_compatibility_mode` 传给 `fit_dti_nifti()`，但对应
`StageDefinition` 在 `workflow.py:883-895` 的参数只有工作线程数和固定 fit 文本，
依赖为空。`pipeline.py:410-432` 的指纹只使用显式输入、依赖、
参数、实现和运行环境标识，不会分析 Python 闭包。

本轮在 tag 临时诊断副本中，把现有缓存测试的第二次配置从 `strict-fsl` 改为 `robust`，
期望所有受影响阶段重新运行。实际第二次状态为：

```text
fit_raw_dti_qa = cached
preprocess_nomoco = completed
register_t1 = completed
publish_tensor = completed
pipeline_qa = completed
```

这证明碰撞只发生在原始数据 QA 阶段：主 corrected fit、primary T1 transform 和正式张量会
按新模式重跑，不受旧 raw 张量污染；但 raw FA/SSE/valid/QA、raw 6DOF QA 矩阵、
registered raw maps 和 aggregate QA 会由新 run 使用旧模式结果。

该参数会实际改变输出。`nifti_fit.py:163-170` 中 `strict-fsl` 与 `robust` 对 NaN、有限值和
正值有效范围的处理不同，现有 `tests/test_nifti_fit.py:186-277` 已证明输出域可不同。

整改应把 `fit_compatibility_mode` 加入 `fit_raw_dti_qa` 参数，并增加同一 output/cache
目录下 `strict-fsl → robust` 和反向切换的判别测试，明确原始数据阶段和下游 QA 均重新计算。

## 6. D2C-030-056：完整流程漏掉官方 CHARM 必需标记文件

官方 `dwi2cond.t1reg.source.sh:2-20` 在任何 FLIRT/FNIRT 前检查 T1、labeling、
bias-corrected T1，并强制 `m2m_*/final_tissues.nii.gz` 存在；缺失时明确报告当前版本需要
CHARM segmentation。tag 的独立命令 `register-t1` 在 `cli.py:804-818` 也检查该文件，
公开 `INPUT_CONTRACT.md` 同样将其列为必需。

完整流程却在 `workflow.py:77-109` 只于 `require_fem=True` 时加入
`final_tissues`，而 `workflow.py:245-247` 仅当 `fem_smoke != "none"` 才开启该检查。
CLI 默认 `fem_smoke="none"`、publish 为 true。

所以默认 `run-pipeline`/`run-prefit-pipeline` 可在官方会于注册前拒绝的 m2m 目录上完成
T1 注册并发布正式张量。`final_tissues` 不直接参与张量数值，故本项定 P2 而非 P1；
但这是正式入口和发布状态差异，不能忽略。

整改应让所有 T1 流程无条件要求 `final_tissues`，并增加
`fem_smoke=none + missing final_tissues` 的流程级回归。

## 7. D2C-030-057：FEM 网格备用路径未进入真实 SESSION

tag 的 `workflow.py:80-90` 和 `simulation.py:57-74` 在标准 `<subject>.msh` 不存在时，
明确接受目录中唯一的 `*.msh`；测试也断言 `only.msh` 备用路径可用。静态验证与 dry-run
因此都会通过。

但 `simulation.py:197-216` 构建 SESSION 时只设置 `session.subpath`、EEG 电极帽和张量，
没有设置已经解析的 `input_contract["head_mesh"]`。SimNIBS 4.6
`sim_struct.py:158-180` 随后执行 `SubjectFiles(None, subpath)`；
`file_finder.py:430-441` 强制目录 basename 为 `m2m_<id>`，并重新构造 `<id>.msh`。

后果是：

- `m2m_<id>` 中唯一但非标准名网格会通过本地 validation/dry-run，真实 solve 前却寻找
  `<id>.msh` 并失败；
- 非 `m2m_<id>` 目录可通过部分本地 T1 流程，但真实 SimNIBS 在解析 subject ID 时晚失败；
- 当前 fake SESSION 测试没有执行 faithful `_prepare()`，所以没有发现生成端→使用端
  组合矛盾。

整改应统一支持策略：若保留备用路径，就将已解析网格显式赋给 `session.fnamehead`，
同时为需要 subject assets 的路径验证 `m2m_<nonempty-id>`；增加真实或 faithful
`SESSION._prepare()` composition 测试，并让 dry-run 也覆盖这项兼容性检查。

## 8. D2C-030-058：FEM 缓存没有绑定真实 SimNIBS 计算身份

`workflow.py:276-294` 的 `_simnibs_runtime_identity()` 记录发行版本、
`simnibs/__init__.py` 路径和该单一文件 SHA-256。FEM 阶段把这份字典放入参数，
通用运行环境标识还会记录 distribution 和已加载 threadpool library 版本。

问题是实际计算由 `run_simnibs`、`sim_struct.py`、`cond_utils.py`、mesh/FEM 模块及求解器
实现完成。保持 `simnibs==4.6.0` 和 `__init__.py` 不变、只替换这些实际模块或求解器时，
FEM 阶段指纹不变，可静默复用旧结果。现有
`tests/test_preprocessing_workflow.py:1090-1120` 只验证 init 文件 hash，正好固化了这个盲区。

本项需要同版本本地修改、重新打包或求解器漂移才触发，故定为条件性 P2。建议将缓存
运行标识绑定到安装分发的 RECORD/关键模块集合与实际求解器标识；如果不能完整确定
计算身份，应禁用 FEM 缓存复用，而不是用单个入口文件代表整个后端。

## 9. D2C-030-059：VN 的非零秩亏张量与官方逐语句结果不同

公开 `tensor-to-mesh` 路径为 `cli.py:1287-1305` → `simnibs_adapter.py:41-84` →
`conductivity.py:tensors_to_conductivity()`。tag `conductivity.py:176-179` 计算行列式
scale 后执行：

```text
determinant_scale[determinant_scale == 0] = 1.0
```

SimNIBS 4.6 `cond_utils.py:257-266` 只修复全零张量，然后直接除以
`abs(prod(eigenvalues))^(1/3)`，之后才 `_fix_eigv()`；没有上述 guard。

判别输入为一个 anisotropic tissue、VN mode、scalar 电导率 `0.126 S/m`、张量
`diag(1, 1, 0)`：

```text
local conductivity = diag(0.252, 0.252, 0.02714588)  # finite
literal SimNIBS 4.6 eigenvalue path = [NaN, NaN, NaN]
```

现有测试覆盖 SPD、全负、全零和 excentricity，但没有覆盖“非零且秩亏”的 VN。
README 将所有修复笼统描述为 SimNIBS 安全修正行为，没有声明这一分支是主动稳健化。

本项不影响完整流程的正式 FEM 阶段：`run_tdcs` 将张量交给实际 SimNIBS，未调用
本地转换器。受影响的是公开 `tensor-to-mesh` API/CLI，因此定为 P2。

整改不应简单删除 guard。应先明确公开行为：

- 若要 strict SimNIBS 4.6 等价，非零奇异张量应复现官方结果或在进入计算前明确失败；
- 若要 robust 扩展，应显式提供模式、记录修复计数、加入判别测试，并停止称该分支为逐语句
  官方等价。

### 附属工程观察（不计入算法问题编号）

`scripts/run_coverage.py:228-235` 使用未指定 `dir` 的 `TemporaryDirectory()`，也没有在
入口设置 `TMPDIR/TEMP/TMP` 或 pytest `--basetemp`。在当前主机默认会写入共享 `/tmp`；
正常退出会清理，异常中止仍可能留下 NIfTI/cache/coverage 输出文件。这不影响官方算法
等价结论，但与当前项目“所有可控临时文件必须位于项目专用持久目录”的规则冲突，建议在
单独工程修复中把临时根显式传入。
