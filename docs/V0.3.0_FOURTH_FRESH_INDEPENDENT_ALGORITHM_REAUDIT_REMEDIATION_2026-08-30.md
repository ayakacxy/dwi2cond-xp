## 2. D2C-030-060: legacy matrix coordinates

### 2.1 Fix

`legacy._register_mcflirt_series()` continues to optimize on the local positive-diagonal scaled-mm grid already validated against negative-determinant FSL inputs. Its output is now explicitly converted before being returned as an FSL matrix:

```text
C = S_fsl @ inverse(S_local)
M_fsl = C @ M_local @ inverse(C)
```

`S_fsl` comes from `fsl_voxel_to_scaled_mm()`. For negative determinants, `C=I`; for positive determinants, `C` reflects x around the final x voxel. Pass1, pass2, direct-b0, and mean-DWI-to-nodif all follow this convention before composition, `MAT_*` storage, final resampling, and corrected-bvec calculation.

Conversion at the producer boundary was chosen because real discriminating runs showed that flipping the optimizer's working arrays changes the approximate optimizer's search trajectory. Exact conjugation preserves the existing trajectory while providing the required local-to-FSL coordinate transformation.

### 2.2 Evidence

- `test_local_scaled_matrix_to_fsl_matches_nifti_handedness` checks the x-translation sign change and negative-determinant identity control.
- `test_mcflirt_thin_volume_matches_fsl_fix2d_matrices` runs real FSL MCFLIRT on the same asymmetric arrays with both `det<0` and `det>0`.
- Negative-determinant matrix relative L2=`0.01073097`, max-abs=`0.04755928`.
- Positive-determinant matrix relative L2=`0.01309271`, max-abs=`0.05444754`.
- Focused legacy and transforms regression: `33 passed`.

These results resolve the confirmed handedness mismatch between producer and consumer. They do not establish bitwise identical 3-D optimizer trajectories with MCFLIRT for every input.

## 3. D2C-030-061: BET inward ray

### 3.1 Fix

`brain_mask._fsl_inward_sampling_contract()` follows `bet2.cpp` statement by statement:

1. Set `dscale=min(xdim, ydim, zdim, 1.0)`.
2. Sample the 1 mm point separately and update `Imin/Imax`.
3. Sample the 7 mm endpoint separately and update `Imin`.
4. Use `dscale` for the source's intermediate `gi=2; gi<7` loop.
5. Include near-surface intermediate points with `gi<3` in `Imax`.
6. If either the 1 mm or 7 mm endpoint is out of bounds, leave fit force at its source-code initial value of zero.

The reference/vectorized and optimized/Numba backends share the same distances and maximum-membership arrays to prevent future drift between implementations.

### 3.2 Evidence

- The 1 mm-grid dark-endpoint counterexample restores `Imin=0`, changing the normal fit force from the old implementation's positive value to FSL's negative value.
- A dark point at 1.5 mm is sampled on a 0.5 mm grid; anisotropic voxels use the smallest voxel size.
- An out-of-bounds endpoint returns an invalid path, and both reference and optimized backends set fit force to zero.
- Real FSL sub-mm dark-shell phantom: final mask Dice=`0.99687416`, with `5599/5598` local/FSL mask voxels.
- Full brain-mask file focused regression: `10 passed`.

## 4. D2C-030-062: conductivity eigensystem modes

### 4.1 Fix

Standalone `tensor-to-mesh` now provides:

- `--eigensystem-mode stable` (default): retain `np.linalg.eigh()` for real symmetric tensors.
- `--eigensystem-mode simnibs46-literal`: follow SimNIBS 4.6's `np.linalg.eig()`, real-part extraction, descending sort, and column reconstruction statement by statement.

QA JSON records `eigensystem_mode`, the maximum basis orthogonality error per tissue, and the number of nonorthogonal bases. Literal mode does not silently orthogonalize or replace ill-conditioned output; stable mode retains its behavior. The production FEM workflow still calls real SimNIBS SESSION and is not replaced by the standalone converter.

### 4.2 Evidence

For the fixed repeated-eigenvalue counterexample `A=I+2qq^T`, with eigenvalues `[3,1,1]`:

- The literal eigensystem is array-equal to the statement-by-statement NumPy/SimNIBS 4.6 formula.
- Stable conductivity retains a positive determinant.
- On the Linux reference stack, literal output reproduces the near-rank-deficient result, and QA records one nonorthogonal basis. Different LAPACK backends may choose different valid bases in a degenerate eigenspace. Cross-platform checks therefore compare against each platform's own literal `np.linalg.eig()` and verify its actual QA, rather than treating the Linux eigenvector choice as platform independent.
- Focused conductivity, adapter, and CLI regression: `55 passed`.

## 5. D2C-030-063: FEM cache safety

`_simnibs_runtime_identity()` still records the distribution RECORD, inspected Python modules, numerical packages, and native library hashes for diagnosis and future completion of execution identity. These candidates do not establish the full set of executed PETSc, MUMPS, MKL/Pardiso, and dynamically loaded extension files. Consequently:

- Every real FEM stage sets `cache_safe` to `false`.
- Its reason is `disabled-unresolved-execution-closure`.
- If SimNIBS is not installed, the reason is `simnibs-not-installed`.
- Only deterministic dry-run preparation, which performs no numerical solver execution, may be cached.

Focused tests passed for complete installations, missing modules, native discovery for all four solvers, and reason fields.

## 6. D2C-030-064: TOPUP coefficients and prefix bundle

Coefficient NIfTI output now contains:

- Intent code `2016` (FSL TOPUP cubic spline coefficients).
- The original field voxel sizes in `intent_p1..p3`.
- Knot-spacing `pixdim`, qform shape translation, and qform/sform codes following the official format.

Alongside the existing `field_coefficients.nii.gz` and `movement_parameters.txt`, output now includes `topup_fieldcoef.nii.gz` and `topup_movpar.txt`. Thus `<output>/topup` can be passed directly as an FSL `--topup` prefix while preserving the local dense-Hz consumer and previous paths.

Checks compare intent and voxel fields individually against real FSL `_fieldcoef` output. Real FSL 6.0.4 `applytopup --topup=<local-prefix>` successfully reads the local bundle and produces finite output. TOPUP artifact, TOPUP-to-EDDY, and workflow behavior tests also pass.

## 7. Validation status and remaining limits

The combined focused batch for all five changes produced `155 passed`, including real FSL MCFLIRT, BET, TOPUP, and the `applytopup` reader. After freezing the source, the complete main batch produced `666 passed, 0 skipped`, and the separate montage batch produced `12 passed`. The coverage runner also executed all three real synthetic TOPUP, EDDY, and FNIRT CLI workflows end to end. Final production statement coverage was `13,663/13,663`, or `100.00%`. Coverage data and batch workspaces were stored in this release's verification directory under the project's dedicated persistent root, without writing to shared `/tmp`.

Version, Markdown, manifest, privacy, dependency, wheel/sdist, clean-install, and remote cross-platform/security release checks continue through the release process. Remote run IDs, tag objects, Release IDs, and release-asset hashes are recorded in the project ledger only after successful read-back; candidate source does not claim these checks in advance.

The five fixes do not resolve these remaining limits:

1. No complete paired positive-determinant reverse-PE TOPUP/EDDY endpoint has been established.
2. FNIRT fields reproduce FSL within numerical bounds; they are not pointwise or bitwise identical.
3. Real HCP raw DWI through the FEM solver in all four conductivity modes has not been rerun at this remediation commit.
4. The project does not claim support for arbitrary inputs, arbitrary FSL parameters, or general FSL replacement.
