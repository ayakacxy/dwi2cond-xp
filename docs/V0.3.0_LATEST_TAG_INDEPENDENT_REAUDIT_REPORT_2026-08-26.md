# dwi2cond-xp v0.3.0 最新 tag 独立算法复审报告

> 日期：2026-08-26
> 审计对象：`437e90bc448638413684ed88a65a77d2e50b63ec`
> tag/分支：`HEAD = origin/main = v0.3.0^{}`
> 官方参考：SimNIBS 4.6.0 `dwi2cond`；FSL `6.0.4:ddd0a010`
> 审计性质：只读复审；本报告不包含算法修复、commit、push 或 release 操作

## 1. 结论

这轮不能继续接受“`D2C-030-015..041` 已全部关闭”或“v0.3.0 已与官方完整同逻辑”
的表述。

更准确的结论是：

1. **普通有限输入下的核心数学已经接近稳定。** DTIFIT/WLS、grad-dev、主 T1
   FLIRT、affine vecreg、nonlinear PPD、T1 post-mask、`dir/vn/mc`，以及整改后的 EDDY
   `016/017/031/040` 控制流均有较强正证据。
2. **仍有一个核心 legacy 数值流程不一致。** 本地 MCFLIRT 在每级同时预重采样
   reference 和 moving；FSL 只预重采样 reference，并从原始 moving 直接计算 cost。
   非整数变换下两者不是同一个 objective。薄层 `fix2D` 的判断时机和 padding 次序也仍
   不同。
3. **正式主流程目前存在发布阻断级集成回归。** 通用 JSON validator 把真实
   `nomoco`、`legacy`、TOPUP+EDDY QA 中的 `artifacts` 字典误当成 FEM 动态产物列表，
   使 stage 在计算成功后仍失败，并删除声明输出。默认 `run-pipeline` 的 `legacy` 路径
   因此不能正常完成。
4. **另有 producer 谱系、科学 QA、FEM inventory、m2m 发布事务和低层 API 边界残留。**
   本报告将它们与核心公式问题分开，避免把工程合同问题误称为普通主路径数学错误。
5. **现有全绿测试不能排除这些问题。** 本轮显式接入全部可用 FSL probe 后测试全过，
   但 workflow 测试用 fake producer 和简化 JSON，恰好绕开了真实组件组合。

本轮按问题簇记录 **6 个 P1** 和 **9 个 P2/P3**。其中只有 legacy MCFLIRT 是普通/特殊
输入上的核心 optimizer 计算流程问题；其余主要属于主流程集成、QA、cache、事务或退化
边界。没有发现新的 P0 静默科学数组错误。

## 3. 官方流程与当前主干映射

```text
官方 raw-DWI 路径
├─ canonical reorientation + bvals/bvecs
├─ exact b==0 → MCFLIRT 6 DOF → mean b0 → BET -f 0.2
├─ correction 前 raw DTIFIT WLS（FA/SSE QA）
├─ nomoco / legacy(+GRE) / EDDY / TOPUP→EDDY
├─ corrected DWI -thr 0
└─ final DTIFIT --wls --sse --save_tensor

官方 T1 路径
├─ labeling 1..499 → T1 brain mask
├─ FLIRT 6/12 DOF
├─ linear vecreg 或 FNIRT 8,4,2,2 → nonlinear vecreg/PPD
├─ mandatory T1 post-mask
├─ tensor_decomp
└─ corrected/raw 6 DOF FA/SSE QA
```

| 阶段 | 当前判定 |
| --- | --- |
| canonical raw、exact-b0、BET、raw/final WLS | 数值主合同总体一致；raw QA 在 DAG 中的执行顺序晚于官方 |
| nomoco producer | 独立算法主干一致；direct-mmap 与 workflow 正式产物合同断裂 |
| legacy MCFLIRT | **不一致**：moving pyramid/cost sampling、`fix2D` 判断与 padding 次序不同 |
| TOPUP fixed subset | 九级 schedule 和公共 gmean 主语义一致；均值累加精度仍不同 |
| EDDY fixed subset | `016/017/031/040` 控制流已对齐；optimizer 不声明 bitwise 相同 |
| FLIRT/affine vecreg | 正常有限输入有强 A/B；主动更严格的非有限值失败合同不是字面 FSL 行为 |
| FNIRT/PPD/post-mask | 主 DAG 顺序一致；identity 低层边界和产物事务仍有残留 |
| conductivity `vn/dir/mc` | 正常有限输入达舍入级一致；全零 anisotropic tissue 失败合同不稳定 |
| FEM | 求解器仍调用官方 SimNIBS；本地负责的 inventory/cache/事务尚未闭合 |

## 4. P1 问题簇

### D2C-030-042（P1，E3）：真实 QA schema 与通用 JSON validator 冲突

[`pipeline.py:148`](../src/dwi2cond_xp/preprocessing/pipeline.py#L148) 对任意 JSON 顶层
`artifacts` 都强制要求 `list`。但三个真实 producer 写的是普通 artifact 名称到路径的
`dict`：

- [`nomoco.py:247`](../src/dwi2cond_xp/preprocessing/nomoco.py#L247)；
- [`legacy.py:680`](../src/dwi2cond_xp/preprocessing/legacy.py#L680)；
- [`topup_eddy.py:146`](../src/dwi2cond_xp/preprocessing/topup_eddy.py#L146)。

workflow 又分别在
[`workflow.py:417`](../src/dwi2cond_xp/preprocessing/workflow.py#L417)、
[`workflow.py:454`](../src/dwi2cond_xp/preprocessing/workflow.py#L454) 和
[`workflow.py:596`](../src/dwi2cond_xp/preprocessing/workflow.py#L596) 把这些 JSON 声明为正式
stage output。只有 FEM simulation manifest 的 `artifacts` 才是真正的动态 inventory list。

本轮直接对三个历史真实 QA 产物调用当前 validator，三者均得到：

```text
artifacts=dict
ValueError: JSON artifacts must contain a list
```

随后 [`pipeline.py:426-450`](../src/dwi2cond_xp/preprocessing/pipeline.py#L426) 会把该 stage
标为 failed，并删除声明输出。因此默认 `legacy`、`nomoco` 和 reverse-PE TOPUP+EDDY
workflow 都会在 producer 成功后失败。standalone preprocess 命令不经过该 runner，故不受
这一项影响。

测试盲点是确定的：

- [`test_preprocessing_pipeline.py:253`](../tests/test_preprocessing_pipeline.py#L253) 反而把
  任意 `artifacts={}` 固定成必须拒绝；
- [`test_preprocessing_workflow.py:25`](../tests/test_preprocessing_workflow.py#L25) 的 fake JSON
  只有 `{"status":"completed"}`；
- workflow tests 没有把真实 producer schema 接到真实 runner。

**关闭标准**：给 `ArtifactContract` 增加显式 JSON schema/动态 inventory 标志，不能再由
通用键名猜测；用真实 nomoco、legacy、EDDY、TOPUP+EDDY、prefit 和 FEM producer 分别完成
cold run、cache hit、篡改与失败清理组合测试。

### D2C-030-019-R（P1，E3）：nomoco direct-mmap 正式产物断链

[`nomoco.py:39-73`](../src/dwi2cond_xp/preprocessing/nomoco.py#L39) 对 canonical、float32、
未压缩、finite 的 `.nii` 输入直接返回原文件，不生成 `preprocess/DWIraw.nii`。但
[`workflow.py:417-431`](../src/dwi2cond_xp/preprocessing/workflow.py#L417) 无条件声明并消费
`preprocess/DWIraw.nii`。

真实历史输入探针结果：

```text
strategy                  validated_input_mmap
materialized              False
declared DWIraw.nii       does not exist
```

因此即使修复 042，该合法输入分支仍会因正式 artifact 缺失而失败。现有 producer test 覆盖
direct mmap，但 workflow stub 总会伪造 `DWIraw.nii`。

此外，官方 raw b0/BET/raw DTIFIT 位于 correction 前；本地 raw QA stage 在 preprocess 后并
依赖它。成功终点可使用同一 canonical raw 数据，但失败位置、进度和 lineage 不是官方顺序。

**关闭标准**：要么 nomoco 始终发布一个正式 canonical `DWIraw.nii`，要么 workflow 从
producer 返回值中声明/消费真实路径；测试必须覆盖 compressed/materialized 和 canonical
uncompressed/direct 两条真实组合路径。若目标是控制流同序，raw QA 还应移到 correction
branch 之前。

### D2C-030-039-R（P1，E2/E3）：legacy MCFLIRT objective 与 `fix2D` 仍不等价

这是本轮最重要的剩余核心算法问题。

**普通 3-D 也受影响的 objective 差异**：

- 本地 [`legacy.py:138-150`](../src/dwi2cond_xp/preprocessing/legacy.py#L138) 在每个 stage
  同时预重采样 reference 和每个 moving volume；优化器随后又从 coarse moving 插值；
- FSL `/usr/local/fsl/src/mcflirt/mcflirt.cc:690,720` 只预重采样 reference；
  `correct():427-445` 把原始 `timeseries[i]` 交给 cost function；
  `newimage/costfns.cc:1786-1850` 按物理 sampling matrix 从原始 moving 直接插值。

所以在非整数候选变换下，本地是“moving 先插值到 coarse grid，再插值求 cost”，官方是
“从原始 moving 一次插值求 cost”。两者不是相同 objective，也会产生不同 optimizer
trajectory。

**薄层 `fix2D` 差异**：

- 本地 [`legacy.py:117-120`](../src/dwi2cond_xp/preprocessing/legacy.py#L117) 在原始 grid 上
  判断 `zsize < 3 or z-FOV < 20 mm`；
- FSL 先把 reference 重采样到首级 8 mm，再运行 `fix2D`；
- `zsize>=3` 且 `20 <= z-FOV < 24 mm` 会被本地漏判。真实 `5×4.2=21 mm` 输入上，FSL
  明确输出 `restricting optimization to R_z, T_x and T_y`，本地谓词为 false；
- FSL stage-1 reference 还会在外层和 `correct()` 内各 padding 一次，moving 在
  `correct()` 内 padding；本地双方只 padding 一次。

现有真实 FSL test 只覆盖 `2×5=10 mm`，并允许 matrix relative L2 `<0.06`、max abs
`<0.2`；已记录结果 `0.0405314` 只能证明近似 gate 通过，不能证明同一算法。此前 legacy
tensor/SSE gate 的 relative threshold 还分别宽到 `0.8/1.1`，同样不是等价证据。

**关闭标准**：按 FSL 保持 raw moving grid、reference-only pyramid、原始 moving 一次
物理采样和逐次 `fix2D`/padding 顺序；验收必须比较每 stage 的 grid/shape、初始 cost、
parameter history 和最终 matrix，并加入 20/21/24 mm 阈值判别输入。

### D2C-030-045（P1，E2/E3）：科学 QA grid 与 cache 输入谱系不完整

核心 mask/FA/tensor/valid-mask 已检查 affine，但
[`qa.py:419-521`](../src/dwi2cond_xp/preprocessing/qa.py#L419) 中的 V1、field、Jacobian、
T1/registered-FA overlay、SSE 和 raw registered FA/SSE 多数只检查 shape 或不检查 affine。
同 shape、平移 affine 的 V1 探针仍返回 `completed`，可把不同空间的数组直接比较。

同时，QA action 在
[`workflow.py:1087-1135`](../src/dwi2cond_xp/preprocessing/workflow.py#L1087) 实际读取 raw
DWI/mask、rotated bvec、field、Jacobian、EDDY parameters/outlier map，但
[`workflow.py:1158-1175`](../src/dwi2cond_xp/preprocessing/workflow.py#L1158) 的 `qa_inputs`
漏掉多项，并以 `config.data` 代替 producer 的 `raw_qa_dwi`。这些文件改变后可能错误命中旧
QA cache。

**关闭标准**：所有配对 NIfTI 做 shape+affine 精确合同检查；建立 action 实际读取文件与
`StageDefinition.inputs` 的一一对应表；逐个修改任一 QA 输入都必须 cache miss；加入 shifted/
axis-permuted affine 判别测试。

### D2C-030-021-R（P1，E2）：FEM dynamic inventory 仍不足以证明正式产物完整

[`pipeline.py:153-183`](../src/dwi2cond_xp/preprocessing/pipeline.py#L153) 当前允许空 inventory，
且未验证 root containment、重复 path、`relative_path` 对应关系、`outputs`/
`masked_subject_volumes` 与 inventory 的成员一致性；NIfTI shape/affine/dtype 也直接信任
manifest 自述值。

[`test_simulation.py:344-370`](../tests/test_simulation.py#L344) 的 fake solve 可返回不存在的
`mesh.msh`，测试仍断言 `completed`。因此“有一个带 hash 的 list”尚不能证明 FEM 正式输出
齐全或 cache 安全。

**关闭标准**：run 模式要求非空 inventory、root containment、无重复、重新读取 NIfTI
metadata，并把 solver outputs、subject volumes、inventory 和 QA 审计统一为一套可交叉验证
的成员/hash 合同。

### D2C-030-022-R（P1，产品事务，E3）：m2m 发布会先删除旧有效对

[`pipeline.py:253-261`](../src/dwi2cond_xp/preprocessing/pipeline.py#L253) 在 cache miss 的
attempt 前先删除全部声明输出。`publish_tensor` 又把 m2m 中的正式 tensor 和 provenance
声明为普通 stage outputs，见
[`workflow.py:987-1015`](../src/dwi2cond_xp/preprocessing/workflow.py#L987)。发布函数内部先
replace tensor、再 replace provenance，见
[`workflow.py:262-291`](../src/dwi2cond_xp/preprocessing/workflow.py#L262)。

故障注入后旧 tensor/provenance 均不存在；进程在两次 replace 之间退出还会暴露混合对。
README 的“atomically publish the final tensor”不适用于 runner 包装后的实际可用性合同。

**关闭标准**：在 attempt-specific staging 中生成并验证 tensor+provenance，再提交；对 copy、
hash、provenance write 和 rename 每个故障点注入异常，均必须保留旧有效对，且不得暴露新旧
混合 provenance。

## 5. P2/P3 问题簇

### 5.1 D2C-030-023-R：standalone `pipeline-qa` 仍默认 b0≤50

- API [`qa.py:267-283`](../src/dwi2cond_xp/preprocessing/qa.py#L267) 默认 `0.0`；
- CLI [`cli.py:302-328`](../src/dwi2cond_xp/cli.py#L302) 仍默认 `50.0`，并在
  [`cli.py:991-1043`](../src/dwi2cond_xp/cli.py#L991) 显式传入。

解析器实测为：

```text
pipeline-qa CLI default: 50.0
build_pipeline_qa API default: 0.0
```

官方 shell 以 exact `b==0` 选择 b0。主 `run-pipeline` 未显式传 threshold，故使用 API 的
`0.0`；问题只影响 standalone QA。关闭测试必须使用 `[0,20,1000]`，而非不可判别的
`[0,1000]`。

### 5.2 D2C-030-033-R：公开低层 PPD 仍用 mask>0

[`nonlinear.py:263-273`](../src/dwi2cond_xp/preprocessing/nonlinear.py#L263) 的公开低层
`resample_tensor_ppd_fsl` 对 source/reference mask 使用 `>0`；FSL `vecreg.cc:440-449`
只排除 `mask==0`，即使用 `!=0` support。identity warp、`diag(3,2,1)` tensor 上：

```text
all +1 mask  local valid = 27
all -1 mask  local valid = 0
all -1 mask  FSL support = 27
```

高层 NIfTI wrapper 已先转换为 bool，因此主 DAG 不受影响。应直接修低层语义或只允许 bool
并拒绝数值 mask。

### 5.3 D2C-030-041-R：FNIRT self-registration 条件仍不同

[`fnirt.py:2366-2379`](../src/dwi2cond_xp/preprocessing/fnirt.py#L2366) 使用 `1e-12` affine
容差，并要求两 masks 相同。FSL `fnirtfns.cpp:1133-1152` 使用严格 `<1e-8` identity 判据，
且 self-check 发生在 mask 读取/构造前。相同图像配 `5e-9` translation 或不同 explicit
masks 时，FSL 走 identity，本地进入 optimizer。普通 FA→T1 通常不是 self-registration，
因此这是低频但已确认的兼容边界。

### 5.4 D2C-030-038-R：TOPUP mean 使用 float32 而 FSL 使用 double 累加

[`topup.py:2473-2479`](../src/dwi2cond_xp/preprocessing/topup.py#L2473) 的 input means 和
[`topup.py:2594-2595`](../src/dwi2cond_xp/preprocessing/topup.py#L2594) 的 common mean 都是
float32。FSL `topup.cpp:132-142,236` 使用 `vector<double>`/`double gmean`，NEWIMAGE 对
`volume<float>` 以 double 累加。

最小反例：

```text
input float32 [1e8, 1, 1, 1, 1, 1, 1, 1, 1, 1]
local float32 mean      10000000.0
FSL double accumulation 10000000.9
```

公共 gmean 恢复的主错误已修，这里是剩余精度问题。尚无正常 MRI 上 optimizer 分岔的 E3
终点证据，故定 P2；若真实判别 A/B 显示 coefficient/field 分岔，应升为 P1。

### 5.5 D2C-030-037-R：FEM finalize/dry-run 事务未闭合

[`simulation.py:342-377`](../src/dwi2cond_xp/simulation.py#L342) 的 `try` 未覆盖 `_json_safe`
和最终 completed manifest write；第二次写入失败可把磁盘 manifest 永久留在 `running`。
dry-run 又在 `build_tdcs_session` 参数校验前返回，可把非法 current/solver/electrode geometry
记录为 `planned`，并可能与旧 real-run 文件共存。

关闭时应把 build、solve、postprocess、inventory、serialize、final write 全部纳入同一
failed-phase 状态机；dry-run 也必须完成同一静态参数验证并隔离旧输出。

### 5.6 D2C-030-024-R：FEM cache 未绑定实际 SimNIBS identity

[`pipeline.py:264-317`](../src/dwi2cond_xp/preprocessing/pipeline.py#L264) 已记录 Python、
NumPy/SciPy/Numba/Nibabel/threadpoolctl 和线程库，这是有效整改；但 FEM stage 只硬编码
`backend="simnibs-4.6.0"`，没有查询实际 SimNIBS package/build。实际 SimNIBS 安装改变后，
同输入可能继续复用旧 solve cache。

至少应加入实际 distribution version、关键模块/build hash 和求解 backend identity。平台
字段是否纳入应作为明确 cache policy，而不能由 synthetic test 暗示已经完整解决。

### 5.7 公开输入/API 合同仍有静默忽略或晚验证

这些可合并为一个 consumed-or-rejected 参数矩阵整改：

- scalar simulation 接受并静默忽略显式 `tensor_file`；CLI 同时公开 `--tensor`；
- `fem_smoke="none"` 的 `solver`、prefit 下的部分 fit config 可被接受但不消费；
- standalone `pipeline-qa` 只有一个 DWI mask，无法表达 API 的 raw/corrected 独立 masks；
- QA 只要求 DWI volume 数“足够”，额外 volumes 会被静默忽略，而非要求与 bvals/bvecs
  精确相等；
- TOPUP+EDDY 组合入口在 reorient、TOPUP 和 BET 后才由 EDDY 验证 readout `[0.01,0.2]`，
  非法输入会先产生昂贵部分产物。

### 5.8 全零 anisotropic tissue 的 `dir/mc` 失败合同不稳定

[`conductivity.py:178-218`](../src/dwi2cond_xp/conductivity.py#L178) 在整个 anisotropic
tissue 全零且 intensity correction 开启时，把负 determinant 转为 Python fractional power，
最终偶然抛出 complex `TypeError`。官方同输入产生 NaN 和 warning；两者都不能进入 FEM。

正常有限 A/B 很强：24 tensors、3 tissues 的 `vn` relative L2 为 `6.38e-16`，`dir/mc`
小于 `1e-18`。这里不应复制官方 NaN，而应在无正 determinant、denominator 非正/非有限或
scale 非有限时给稳定的显式拒绝。

### 5.9 FNIRT 高层预验证和未声明产物

[`nonlinear.py:657-775`](../src/dwi2cond_xp/preprocessing/nonlinear.py#L657) 只先检查
`brain_mask_file is not None`，实际存在性/grid 验证发生在完整 FNIRT 和若干输出写出之后。
missing-mask 探针会留下 warp、field、Jacobian 和 registered FA。另有三个成功产物未列入
[`workflow.py:969-977`](../src/dwi2cond_xp/preprocessing/workflow.py#L969) 的 stage outputs，
删除它们不会使 cache 失效，失败清理也不会管理它们。

应在计算前验证 mask 的存在、3-D shape、affine、finite/support，并使用 attempt directory
统一发布；所有生成/报告的正式文件必须声明为 outputs。

## 7. 主动差异，不应混作新 bug

下列行为不是安装版字面相同，必须继续明确声明：

- GRE dwell：官方 shell 用 `bc scale=5` 截断；本地精确除以 1000。`0.789 ms` 为
  `0.00078` 对 `0.000789 s`，位移比例约差 `1.1538%`；
- GRE 固定路径只接受已换算 rad/s，不包含 Siemens phase+TE/PRELUDE；
- 官方 shell 的 GRE warp 参数数目有 `$# -gt 5` off-by-one，安装版五参数调用不会套 warp；
  本地行为是 intended correction，不是 literal reproduction；
- EDDY 默认 seed 固定为 1，官方不传 `--initrand`；严格 A/B 必须双方显式同 seed；
- 本项目限定单壳和固定 TOPUP/EDDY/FNIRT 子集，不是通用 FSL replacement；
- PE 公开语法、保留 intermediates/cache、无 GUI/HTML log、无 `first_ev_for_check.msh` 等
  与官方 shell 不同；
- FEM 是官方 `dwi2cond` 之后增加的 consumer，不属于 shell 本身的等价范围。

## 9. 整改顺序与验收门禁

### 第一批：恢复可运行的正式主流程

1. 修复 042 的 JSON schema 冲突；
2. 修复 nomoco direct-mmap 的正式 raw artifact；
3. 用真实 producer+runner 覆盖 legacy、nomoco、EDDY、TOPUP+EDDY、prefit；
4. 第二次运行必须命中 cache，任一正式 artifact 改动必须使对应 stage 重算。

### 第二批：修复剩余核心算法与科学 QA

1. 按 FSL 重写 legacy reference-only pyramid/raw-moving objective；
2. 恢复准确的 `fix2D` 判断时机和 padding 次序；
3. 加入逐 stage grid/cost/parameter-history/endpoint FSL A/B；
4. 给所有 QA NIfTI 补 shape+affine 检查和完整 cache inputs；
5. TOPUP mean 改用 FSL double 累加顺序并做判别 A/B。

### 第三批：产物、事务与公开边界

1. 收紧 FEM inventory、actual SimNIBS cache identity 和 finalize 状态机；
2. 修复 m2m tensor/provenance 的失败事务；
3. 关闭 023/033/041 的低层残余；
4. 统一 standalone QA masks、volume count 和所有公开参数的 consumed-or-rejected 合同；
5. 预验证 FNIRT mask并声明全部生成产物；
6. 对全零 anisotropic tissue 给稳定显式失败。

### 最终关闭条件

在以下条件同时满足前，不应再次写“全部关闭”或“与官方实现相同逻辑”：

- 每个问题先有修复前失败的判别 test，再有修复后通过；
- 真实 producer 与真实 runner 组合，而不只使用 fake JSON；
- legacy/TOPUP/EDDY/FNIRT 分别绑定正确官方配置、命令、输入 hash 和阶段输出；
- 正常路径、特殊分支、失败清理、cache hit/miss 和发布事务均有独立门禁；
- 报告明确绑定整改实现 commit、最终 tag target 和实际执行命令；
- optimizer tolerance 只声明数值对应，不被外推为 bitwise 或任意输入等价。

## 10. 对当前 v0.3.0 的最终判定

当前 v0.3.0 **不是“还有大量核心公式写错”**；相反，普通有限输入下多数核心数学已经有
很强证据。但它也**不是“只剩无关紧要的小问题”**：默认正式 workflow 的 schema 冲突、
legacy MCFLIRT objective、nomoco producer 谱系、科学 QA/cache、FEM inventory 和正式发布
事务都必须整改。

建议下一步严格按第 9 节三批顺序修改。先恢复真实 end-to-end composition，再修 legacy
核心 objective，最后收紧低层/API/FEM 边界；不要在这些正确性门禁关闭前开始新一轮性能
优化或再次替换 release。
