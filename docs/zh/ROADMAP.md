`v0.3.0` 是当前稳定版本。项目处于维护阶段，没有正在执行的 `v0.4.0` 开发周期、
`10x` 性能目标或已安排的性能发布。此前的性能周期在建立可靠新基线前已取消，预备
样本不作为产品性能结论或后续开发承诺。

## 稳定版本的范围

项目用纯 Python 实现 SimNIBS 4.6 `dwi2cond` 使用的固定子集：原始 DWI 或预拟合
单壳张量流程，legacy/GRE/TOPUP/EDDY 预处理，仿射与非线性 DTI→T1 配准，PPD 张量
重定向，`scalar`/`vn`/`dir`/`mc` 电导率，以及 SimNIBS FEM 和先导场接口。
FSL 仅用于可选的数值比较，不是运行依赖。

维护内容包括已确认的正确性修复、依赖与平台兼容、打包和安全更新、文档修订。稳定 tag
通常不变。若明确授权修订历史文档，应保留原 tag 对象和提交的备份及项目记录，保持
算法源码不变，重建发布文件，并记录可核验的恢复关系。

## 如何使用历史结果

单纯整理文档无需重复已完成的实验。历史结果应对应明确的源码版本、输入、环境、指标和
计时或数值比较范围。只有新结论依赖改变后的实现/环境，原证据无法重建，或发现影响
结论的不一致时，才需要重跑。

因此，`v0.1.0` 至 `v0.3.0` 的历史仍以各版已完成的验证为依据。具体输入上的数值与
耗时见[基准记录](BENCHMARKS.md)，其结果不能推广为所有硬件或输入上的保证。

## 后续开发的前提

未来功能或性能工作需先明确范围。发布数值或速度结论前，应：

1. 固定参考 tag 或 wheel，以及合法、可复现的输入。
2. 在状态稳定的主机上，按候选版本相同的输入、输出、资源、缓存和进程范围建立基线。
3. 重复配对测量并报告离散程度，不采用最快单次或中断运行作为依据。
4. 先通过各阶段及完整流程的数值比较，再解释性能变化。
5. 每次优化一个可测热点，保留参考实现，并明确报告优化实现失败。
6. 用实际设备和平台上的运行支持 GPU 或跨平台声明。

这些是开展新工作的条件，不是 `v0.4.0` 计划、日程、发布承诺或预设速度目标。

## 已知限制

- 项目只实现 SimNIBS 4.6 `dwi2cond` 使用的固定 FSL 子集，不覆盖通用 FSL 命令。
- 严格张量拟合限于单壳；需 PRELUDE 的缠绕相位，以及任意 TOPUP/EDDY/FNIRT 配置
  不在支持范围内。
- 性能结果只适用于记录中的具体输入与计时范围，没有通用的完整流程加速倍数。
