# dwi2cond-xp v0.2.0 算法一致性审计报告

> 审计日期：2026-08-25
> 审计对象：`v0.2.0` annotated tag `e557d3975c988ba56a6e4a9d0f538a4c1f4e2722`
> 实际代码提交：`20f40923bb04e146522f458332a4e2fc152d3f00`
> 官方基线：SimNIBS 4.6.0 `dwi2cond` + FSL `6.0.4:ddd0a010`
> 审计结论：**v0.2.0 不能认定为与官方实现具有相同的端到端流程、算法分支和计算逻辑。**

## 1. 结论摘要

本次审计先比较完整流程，再逐模块核对输入合同、分支、计算顺序、数值公式、坐标/掩膜语义和最终输出。结论不是“所有底层算法都错误”：WLS 正常输入主公式、tensor 六分量顺序、gradient-nonlinearity 九分量排列、affine tensor polar reorientation、FNIRT 固定 schedule、nonlinear PPD 主体以及主 `run_tdcs` 调用官方 SimNIBS 的路径，均有较好的源码或数值一致性证据。

真正的问题是，v0.2.0 在若干关键接线和边界上偏离官方流程。其中最严重的是：

1. `run-pipeline --preprocessing-mode eddy` 把仍在 scan space 的 `outlier_free_data.nii.gz` 送入 WLS，而没有使用真正完成运动、eddy-current 和 susceptibility 校正的 `corrected_dwi.nii.gz`。因此该完整 DAG 的 EDDY 最终 tensor 实际绕过了几何校正。
2. nonlinear 路径漏掉官方在 `vecreg` 后必做的 T1 brain mask，导致最终 tensor、FA、V1 和 valid mask 在脑外仍可非零。
3. GRE fieldmap 路径虽然计算出 undistorted mask，却没有把它交给 legacy WLS；拟合仍使用 distorted-grid mask。
4. standalone `tensor-to-mesh` 的 DIR/MC 在 eigendecomposition 前提前填充零 tensor，默认 `correct_intensity=True` 时改变全组织 intensity scaling；含零 tensor 时可产生接近数量级的结果偏差。
5. DTI fitting 没有像 FSL 一样先单位化 b-vector；非单位 b-vector 的同输入复现中，tensor 相对 FSL 偏差为 `0.143597`。
6. 现有测试将 EDDY 的两个不同语义产物只做 shape 检查，也没有覆盖 nonlinear 脑外严格为零、DIR/MC 零 tensor、非单位 b-vector、负定 tensor 派生图等不变量，所以 `100% statement coverage` 没有拦住上述问题。

在完成本报告所列 P0/P1 修复及同输入 FSL/SimNIBS A/B 前，不建议继续使用“完整替代官方 dwi2cond”“同逻辑实现”或对所有输入成立的 conductivity parity 表述。

## 3. 官方流程与 v0.2.0 流程对照

官方 SimNIBS 4.6 `dwi2cond` 主流程为：

```text
raw DWI / pre-fitted tensor
  -> raw DWI、fieldmap、reverse-PE 的 fslreorient2std
  -> exact b=0 对齐均值 + BET
  -> nomoco / legacy(+GRE) / EDDY(+TOPUP)
  -> 对最终 DWIforfit 统一执行 -thr 0
  -> dtifit --wls --sse --save_tensor（完整单壳 volume）
  -> T1 brain/mask
  -> FLIRT 6/12 DOF
  -> 默认 FNIRT 或 linear vecreg
  -> post-vecreg T1 brain mask
  -> tensor decomposition、QA、m2m tensor 发布
```

关键官方证据：

- 默认 legacy correction、默认 nonlinear：`dwi2cond:51-70`；
- 仅支持调用者已经准备好的 single-shell 输入：`dwi2cond:143-160`；
- raw/reverse-PE reorientation：`dwi2cond.prepro.source.sh:33-64`；
- exact b=0、MCFLIRT mean、BET：`dwi2cond.prepro.source.sh:67-100`；
- EDDY/TOPUP 和 legacy/GRE 分支：`dwi2cond.prepro.source.sh:117-170`；
- correction 后统一 `-thr 0`，再拟合全部输入 volume：`dwi2cond.prepro.source.sh:173-178`；
- FLIRT/FNIRT/vecreg/post-mask：`dwi2cond.t1reg.source.sh:19-44`；
- QA 和 `first_ev_for_check.msh`：`dwi2cond.t1reg.source.sh:47-65`。

v0.2.0 的 nominal stage 名称与官方相似，但在以下位置出现实质差异：

| 阶段 | 官方 | v0.2.0 | 结论 |
| --- | --- | --- | --- |
| 默认模式 | legacy + nonlinear | nomoco + affine | 默认科学流程不同 |
| raw orientation | 所有 raw DWI/reverse-PE 先 reorient | nomoco/legacy 有；EDDY/TOPUP 无 | EDDY/TOPUP 非 canonical 输入不等价 |
| b0 规则 | raw mask 用 exact `b=0`；EDDY 内部阈值 100 | 多处共用或硬编码 50 | 分支分类不同 |
| TOPUP→EDDY | reverse 4D 对齐/均值、TOPUP、corrected-b0 BET、`--topup` | 两个 standalone 3D b0 + 外部 3D Hz field artifact + 外部 mask | 不是官方完整闭环 |
| EDDY fit artifact | registered corrected DWI | scan-space outlier-free data | Critical 接线错误 |
| fit 前阈值 | correction 后统一 `-thr 0` | EDDY 缺失；nomoco/legacy 部分提前 | 计算顺序不同 |
| DTI volume | 完整、已由调用者保证单壳 | 隐式选择 `b<=50` 与 `1000±100` | 科学输入合同不同 |
| b-vector | FSL 先单位化 | 不单位化也不拒绝 | design matrix 不同 |
| nonlinear 输出 | vecreg 后 T1 mask | 未应用 post-mask | 脑外 tensor 非零 |
| conductivity | 官方 `cond_utils` | 主 `run_tdcs` 走官方；standalone adapter 自实现 | standalone DIR/MC 零 tensor 错误 |
| 最终发布 | `m2m_*/DTI_coregT1_tensor.nii.gz` | DAG output root | 外部 SimNIBS 默认发现失败 |

## 5. Critical、High 与重要流程问题详述

### D2C-020-001：EDDY DAG 拟合了错误空间的数据

v0.2.0 在 `src/dwi2cond_xp/preprocessing/workflow.py:227` 将变量 `corrected_dwi` 指向：

```text
eddy/outlier_free_data.nii.gz
```

随后在 `workflow.py:232-244,276-293` 把它交给 `fit_dti_nifti`。

但 EDDY 实现自身清楚地区分了两个产物：

- `eddy.py:2938-2944`：完成 outlier replacement 后立即复制 `outlier_free_scans = scans.copy()`；此时仍是 scan space；
- `eddy.py:2944-2952,3114-3150`：之后才执行最终 movement/EC/susceptibility unwarp 和 resampling；
- `eddy.py:3176-3182`：真正校正后的数据是 `corrected_scans`；
- `eddy.py:3279-3287`：分别写出 `corrected_dwi.nii.gz` 和 `outlier_free_data.nii.gz`。

FSL 源码同样把两者区分为不同空间：

- `/usr/local/fsl/src/eddy/ECScanClasses.cpp:1262-1273` 的 `WriteOutlierFreeData` 直接写 scan-space 图像；
- `/usr/local/fsl/src/eddy/eddy.cpp:362-377` 单独写最终 registered images；
- 官方 `dwi2cond.prepro.source.sh:140-177` 使用 EDDY 主输出 `DWI_corr` 作为 `DWIforfit`。

当前完整 DAG 因而将未做最终几何校正的 DWI 与已经旋转的 b-vector 组合拟合。这不是小数值偏差，而是 artifact lineage 错误。

同时该路径没有执行官方 `dwi2cond.prepro.source.sh:173-177` 的最终 `-thr 0`。

**修复要求**：

1. WLS 和 corrected-DWI QA 只允许消费 `corrected_dwi.nii.gz`；
2. 在 correction 完成后、fit 前执行与 `fslmaths -thr 0` 相同的 float32 非负阈值；
3. `outlier_free_data` 改名或在 manifest 中明确为 scan-space diagnostic，不允许作为 fit artifact；
4. cache fingerprint 必须区分两个产物。

**最小回归测试**：mock EDDY 令 corrected 数据全为 `2`、outlier-free 全为 `1`，断言 fitter 实际读取的是 `2`。现有 `tests/test_preprocessing_eddy.py:397-398` 只检查两个文件 shape，`tests/test_preprocessing_workflow.py:279-301` 的 fake fitter 又忽略输入内容，因此没有发现问题。

### D2C-020-002：EDDY 最终输出未应用 FSL 默认联合 mask

项目在每次 resampling 中已经计算 mask：

- `eddy.py:1623-1645` 返回 `transformed.mask`；
- `eddy.py:2530-2537,2949-2968` 计算 b0/DWI joint mask。

但 `eddy.py:3114-3150` 生成最终 `corrected_scaled` 时只复制 `transformed.values`，没有收集或应用全 volume mask。

FSL 默认没有打开 `--dont_mask_output`：

- `/usr/local/fsl/src/eddy/EddyCommandLineOptions.cpp:97`；
- `/usr/local/fsl/src/eddy/EddyCommandLineOptions.h:208`。

其 `/usr/local/fsl/src/eddy/ECScanClasses.cpp:1401-1430` 对每个 volume 的 `tmpmask` 求交，并在写出前执行 `ovol *= omask`。项目的 periodic cubic sampling 在无效坐标仍可能返回外推值；不乘 joint mask 会把这些值保留到后续 DTI mask 内。

**修复要求**：最终 resampling 同时返回 values 和 mask；对 b0 与 DWI 的所有 volume 求交；写出前一次性乘整个 4D corrected data。FSL 默认运行会应用 joint mask，但不会写 `.eddy_output_mask`；诊断参考运行应显式加 `--dont_mask_output`，从它写出的 4D per-volume mask 求交，再用另一趟默认运行验证 registered output 在联合无效域精确为零。项目可以额外发布自己的 joint mask，但不能把它误称为 FSL 默认产物。

### D2C-020-003：nonlinear 最终 tensor 漏掉 T1 brain mask

官方顺序是：

```text
fnirt -> vecreg -> fslmaths DTI_coregT1_tensor -mas T1_brainmask
```

证据为 `dwi2cond.t1reg.source.sh:39-44`。

v0.2.0：

- `workflow.py:348-399` 调 nonlinear stage 时未传 `T1_brainmask`；
- `nonlinear.py:711-721` 调 tensor registration wrapper 时未传 output/reference mask；
- `nonlinear.py:260-270` 在没有 reference mask 时默认整个 target grid 有效；
- `nonlinear.py:336-355` 只按 source support、warp fold/奇异性决定输出。

identity-warp 小型复现使用 `6×6×6` 全域非零 tensor 和中心 `4×4×4` T1 mask：

- v0.2.0：脑内 64 个非零体素，脑外仍有 152 个非零体素；
- 模拟官方 post-mask：脑外非零体素为 0。

这会影响最终 tensor、FA、V1、valid mask，以及脑边界处 mesh interpolation。聚合 QA 又先用 brain mask 截取统计，因此可能掩盖实际输出违规。

**修复要求**：PPD 完成后立即同时 mask tensor 和 valid mask，再从 mask 后 tensor 计算 FA/V1；brain mask 必须进入 stage input/fingerprint。验收断言 tensor、valid、FA、V1 在 mask 外逐元素精确为零。

### D2C-020-004：GRE corrected mask 没有进入 WLS

本条以第 7 节定义的 **intended/patched SimNIBS reference** 为科学比较对象；官方 4.6.0 原 shell 的参数计数 off-by-one 会使 literal upstream 行为自身不完整，不能作为应复制的正确算法。

官方 GRE 分支：

- `dwi2cond.functions.source.sh:159-167` 生成 `nodif_brain_mask_UNDIST`；
- `dwi2cond.prepro.source.sh:153-160` 把它复制到 raw-DTI 结果目录；
- `dwi2cond.prepro.source.sh:173-177` 使用该 corrected mask 拟合。

v0.2.0 的 `fieldmap.py:593-608` 已经写出 `corrected_b0` 和 `corrected_mask`，但：

- `workflow.py:172-181` 只把 displacement 交给 legacy；
- `legacy.py:361-373` 从 distorted nodif 生成原始 mask；
- `legacy.py:447-464` 对 DWI 应用 displacement；
- `legacy.py:489-505` 仍用原始 mask 拟合。

因此 DWI 已在 undistorted grid/support，mask 却仍来自 distorted support。

**修复要求**：fieldmap stage 必须以不可拆分 bundle 传递 displacement、corrected b0、corrected brain mask；legacy WLS 使用 corrected mask，并验证 corrected DWI 与 mask 的 shape、affine、qform/sform 和 support 一致。

### D2C-020-005：standalone DIR/MC 零 tensor 顺序错误

v0.2.0 `conductivity.py:150-153` 在所有模式 eigendecomposition 前，把零 tensor 替换成 `conductivity * I`。DIR/MC 默认 `correct_intensity=True` 时，随后在 `conductivity.py:177-225` 将这些预填 tensor 纳入全局 intensity scale。

官方 `cond_utils.py` 的分支顺序不同：

- VN 在 eig 前执行 `_fix_zeros`：`cond_utils.py:252-270`；
- DIR/MC 对原始 tensor 先 eig，再 `_fix_eigv(..., -1e-6)`，计算全局 scale，第二次 `_fix_eigv(..., tissue conductivity)`，重建后才 `_fix_zeros`：`cond_utils.py:272-344`。

直接按官方源码顺序转录的同输入复现使用一个组织、一个零 tensor 加三个正常 DTI-scale tensor：

| 指标 | 官方顺序 | v0.2.0 |
| --- | ---: | ---: |
| intensity scale | `196.0419603` | `1.5874008` |
| 零 tensor 输出对角线 | `0.126` | `0.2000125` |
| DIR 全结果 relative L2 | baseline | `0.93885` |
| MC 全结果 relative L2 | baseline | `0.91859` |

已有 README 的 `0–2.22e-16` parity fixture 没有覆盖零 tensor，所以不能外推到实际含零 support 的 tensor。

**修复要求**：严格复制官方 VN 与 DIR/MC 的不同顺序；DIR/MC 不得提前填零；增加零 tensor 占比、多个组织和不等体积权重 A/B。报告中的灾难性全局 scale 偏差特指默认 `correct_intensity=True`；`correct_intensity=False` 没有这一步全局 scaling，但仍应按官方的 eig/fix/reconstruct/末尾 `_fix_zeros` 顺序单独验证。

**影响边界**：该问题影响公开 `tensor-to-mesh`/`simnibs_adapter` 路径。主 `run_tdcs` 将 tensor 交给官方 SimNIBS SESSION，最终走官方 `cond_utils.cond2elmdata`，不受这一 standalone adapter bug 影响。

### D2C-020-006：b-vector 未按 FSL 单位化

项目：

- `gradients.py:10-29` 只检查 shape、finite、b-value 非负；
- `tensor_fit.py:45-70` 直接用原始 b-vector 构造 design matrix。

FSL `/usr/local/fsl/src/fdt/dtifit.cc:423-432` 在拟合前逐列单位化 b-vector；若有 gradient nonlinearity，则在 `dtifit.cc:373-395` 变换方向、按模长平方修改 b-value，再次单位化方向。

本轮一体素同输入 A/B 使用 9 个 DWI 方向，方向模长从 `0.8` 到 `1.2`：

- 项目 tensor 对 FSL relative L2：`0.1435971297`；
- FSL tensor 对生成真值 relative L2：`7.3589e-8`；
- 项目 tensor 对生成真值 relative L2：`0.1435971243`。

极简公式也能显示差异：`b=1000, g=[2,0,0]` 时，项目 design 的 Dxx 系数为 `4000`，FSL 单位化后为 `1000`。

**修复要求**：strict compatibility 路径按 FSL 对每个非零方向单位化，并保持 b0 零向量合同；零模长但 `b>0` 应明确与 FSL 行为一致或显式失败。测试必须同时覆盖 `3×N`、`N×3`、非单位方向和 grad-nonlinearity。

### D2C-020-007：拟合派生图使用了错误的 FSL 子工具语义

`nifti_fit.py:40-59,337-344` 在拟合后调用 `tensor_ops.decompose_tensor6`。后者在 `tensor_ops.py:37-42,82-100` 对最大特征值不大于零的 tensor 清零 FA/MD/MO/L/V。

该行为匹配 `fslmaths -tensor_decomp`（`/usr/local/fsl/src/avwutils/fslmaths.cc:1241-1276`），但不匹配拟合阶段的 `dtifit`。FSL `dtifit.cc:627-648` 对 mask 内已拟合 voxel 无条件写出 L/FA/MD/MO/V。

本轮构造一个负定各向异性 tensor 的同输入 WLS 复现：

| 输出 | 项目 | FSL |
| --- | ---: | ---: |
| tensor max abs difference | `0` | baseline |
| FA | `0` | `0.58911705` |
| MD | `0` | `-4.6666665e-4` |
| V1 max component | `0` | `0.974248` |

也就是说，tensor 拟合本身完全一致，但项目立即把 `dtifit` 本应输出的派生图清零。raw-space FA 是后续 T1 registration 的输入，因此该差异**可能**传播到最终 transform 和 tensor；本轮只实测了派生图差异，没有实测由该 synthetic voxel 引起的 transform 偏差。

**修复要求**：拟合阶段实现 `dtifit` 派生图语义；官方明确调用 `fslmaths -tensor_decomp` 的 prefit-tensor import（`dwi2cond.prepro.source.sh:15-17`）和 post-vecreg 阶段使用 L1>0 门控。两种语义不能复用同一无上下文实现。

### D2C-020-008：EDDY/TOPUP raw ingest 缺少 `fslreorient2std`

官方对 raw DWI 和 reverse-PE 均先进行 storage reorientation：`dwi2cond.prepro.source.sh:35-36,57-63`。注释明确说明这是为了避免 neurological input 导致 tensor 左右翻转。

v0.2.0：

- `eddy.py:3226-3255` 直接加载原始 DWI/mask/field，并按原数组轴解释 PE；
- `topup.py:2631-2646` 直接加载 forward/reverse b0；
- 这两个入口没有 canonical-storage 前置 stage，也没有把“输入必须已经 canonical”写成强制验证。

对非 canonical、neurological 或 qform/sform 边界输入，PE axis、movement matrix、susceptibility field 和最终 tensor basis 都可能与官方不同。

**修复要求**：建立统一 raw-ingest stage，使用与 FSL 相同的不插值 storage reorientation，并同步处理 DWI、reverse-PE、mask、fieldmap、grad_dev 和相关方向元数据。验收至少覆盖 RAS/LAS、neurological/radiological 和不同 qform/sform code。

### D2C-020-009：官方 TOPUP→EDDY 组合闭环没有实现

官方完整链路包括：

1. reverse-PE 4D `fslreorient2std`、6-DOF MCFLIRT、Tmean：`dwi2cond.prepro.source.sh:57-64`；
2. forward exact-b0 MCFLIRT mean 和 BET：`dwi2cond.prepro.source.sh:67-91`；
3. TOPUP 后取第一 corrected b0，再 `BET -f 0.2`：`dwi2cond.functions.source.sh:197-207`；
4. 将 TOPUP coefficient 和 movement 作为 `--topup=topup_res` 交给 EDDY：`dwi2cond.functions.source.sh:75-83`。

v0.2.0：

- standalone `prepare-topup` 只接受用户预先准备好的两个 3D b0：`cli.py:193-207`、`topup.py:2605-2638`；
- `run-pipeline` 没有 reverse-PE/TOPUP stage：`cli.py:306-338`、`workflow.py:141-299`；
- EDDY 要求外部 `dwi_brain_mask`，不能从 TOPUP corrected b0 生成官方 BET mask；
- TOPUP 的 joint validity mask 不是 BET brain mask；
- 对外只提供一个 3D Hz field 接口，而不是官方 `topup_res` 完整产品合同。

所以“先手工 `prepare-topup`，再把 field 和 joint mask 传给 EDDY”不能被视为官方完整 TOPUP→EDDY DAG。本条是组合 workflow/产品能力缺口，故列为 Medium；不否定 standalone TOPUP 和 EDDY kernel 已有的数值证据。

这里需要避免一个误判：项目并没有在所有 EDDY 坐标变换中错误地静态叠加 susceptibility 场。`eddy.py:1389-1407,1503-1536` 在 model→scan 时按每卷 movement 拉取 TOPUP 场；`eddy.py:1590-1637` 在 scan→model 时将已经位于共同 model grid 的场静态相加，同时按每卷 movement 处理 EC field 和图像坐标。该分工与 FSL `ECScanClasses.cpp:487-508,574-596,618-634` 同构。SimNIBS 固定流程的 DWI index 全为 1，而 TOPUP 第一张是零运动参考，所以未读取 TOPUP movpar 在这个固定边界下也没有形成已证实的数值错误。本条结论来自 reverse-PE preparation、corrected-b0 BET mask 和组合 DAG 缺失，不是 field-motion kernel 错误。

**修复要求**：新增从 reverse 4D 到官方 corrected-b0 BET mask、TOPUP products、EDDY 的组合 stage；所有中间产物进入 manifest，逐阶段与 FSL 对齐。

### D2C-020-010：legacy direct-b0 registration 截断了序列

项目 `legacy.py:433-444` 只把输入序列截到“最后一个 b0 volume”为止，再运行 direct-b0 registration。

官方 `dwi2cond.functions.source.sh:261-273` 对完整 4D DWI 运行 MCFLIRT，之后只复制 `b==0` 的矩阵。FSL `/usr/local/fsl/src/mcflirt/mcflirt.cc:443-454` 在 8 mm 初始 stage 中向下一 volume 传播初值，只在完整序列末端停止该传播。

如果最后一个 b0 后仍有 DWI，项目把该 b0 错当成截断序列末端，使其初始化和优化路径与官方不同。该控制流差异已经确认，但本轮尚未取得同输入 FSL matrix/tensor 数值传播结果，因此列为 Medium。

**修复要求**：direct-b0 MCFLIRT 必须看到完整 volume 序列；完成后只替换 b0 matrix。回归 fixture 必须是交错 b0，且最后一个 b0 后仍有 DWI。

### D2C-020-011：默认科学流程与官方相反

- 官方默认：legacy correction + nonlinear FNIRT，见 `dwi2cond:51-70`；
- v0.2.0 默认：nomoco + affine，见 `workflow.py:33-34`、`cli.py:315-322`。

因此不加 mode 参数时，项目会跳过官方默认的 motion/eddy correction 和 nonlinear registration。这是用户最容易遇到的流程级偏差。

**修复要求**：如果 `run-pipeline` 声称兼容官方，默认应恢复 legacy + nonlinear；如希望保留快速默认，必须将命令明确命名为非兼容 workflow，并要求用户显式选择。

### D2C-020-012：隐式选壳改变科学输入合同

官方只声明支持 single-shell，并把调用者提供的全部 volume 交给 `dtifit`：`dwi2cond:143-160`、`dwi2cond.prepro.source.sh:173-178`。

项目 `gradients.py:32-53`、`nifti_fit.py:229-239` 无条件保留：

```text
b <= 50 或 |b - 1000| <= 100
```

`run-pipeline` 又没有暴露这些参数。HCP 等 multi-shell 输入会被静默裁为 b1000，而不是明确拒绝或记录一个单独选壳步骤。

这也与 v0.2.0 `docs/INPUT_CONTRACT.md:84-86` 的公开合同矛盾：文档要求 multi-shell 必须先经过显式 `select-shell` 或等价可追踪步骤，而 `run-pipeline` 内部直接使用不可见的默认选择。

同一个默认 `b0_threshold=50` 还在 `nomoco.py:121-130,186-199` 被用于构造 nodif mean 和 BET mask；官方 raw 流程在 `dwi2cond.prepro.source.sh:73-91` 使用 exact `b=0`。所以 `b=1..50` 不仅影响拟合 volume selection，也会改变 nomoco registration reference 和 mask。

自动选壳本身可以作为安全工具，但不是官方同逻辑。

**修复要求**：strict compatibility 入口先验证输入只有一个非零 shell，然后拟合全部 volume；multi-shell 必须失败并提示用户先运行显式 `select-shell`，后者记录 shell/tolerance/hash/volume indices manifest。

### D2C-020-013：EDDY b0/DWI 阈值错误

- 项目 `eddy.py:3011-3017`：`b<=50` 为 b0，`b>50` 为 DWI；
- FSL `/usr/local/fsl/src/eddy/EddyUtils.h:44,124-127`：`b_range=100`，只有 `b>100` 才是 DWI。

因此 `b=51..100` 会在项目和 FSL 中进入不同 GP、outlier、registration 和 shell 分组逻辑。项目的“全局 b-value range 不大于 100”检查也不等于 FSL 的逐壳 `AreInSameShell`。常规 exact-b0 + b1000 strict single-shell 输入不触发这一区间，且本轮没有该边界的最终 tensor A/B，所以列为 Medium。

**修复要求**：分离三套规则，禁止共用一个全局 50 常量：

- 官方 raw nodif/BET：exact `b=0`；
- FSL EDDY 内部分组：100；
- 显式选壳工具：用户指定阈值和 tolerance。

## 6. Medium/Low 兼容性问题

### D2C-020-014：负信号截断顺序过早

`nomoco.py:24-89` 和 `legacy.py:337-376` 在 raw materialization 时就设置 `nonnegative=True`。这份数据随后参与 b0 mean、BET 和 MCFLIRT。

官方只在所有 correction 完成后、最终 `dtifit` 前执行 `-thr 0`。负背景或重建产生的负值因而会改变项目的 registration cost 和 mask。修复时应把截零移回统一的 correction→fit 边界；EDDY 也必须补上该边界。

### D2C-020-015：最终 tensor 没有发布到 m2m 官方路径

官方写入：

```text
m2m_<subject>/DTI_coregT1_tensor.nii.gz
```

v0.2.0 `workflow.py:403,549-552` 只返回 DAG output root 中的 tensor。内部 FEM 因显式传入 tensor 可运行，但后续普通 SimNIBS SESSION 无法默认发现它。这也与 `README.md:258-260` 的声明不一致。

建议提供一个显式、原子、带 checksum/provenance 的 publish stage；若不允许自动写 m2m，则修正文档并提供需用户确认的 `publish-to-m2m` 命令。

### D2C-020-016：官方输入、PE 和 QA 合同未完整覆盖

以下是能力/接口缺口，不应与已实现的核心数值 kernel 混为一谈：

- 官方支持只给一个 FSL `DTI_tensor`，自动 copy/reorient/decompose 后进入 T1reg；v0.2.0 `run-pipeline` 强制 raw DWI+bvals+bvecs，standalone `register-t1` 又要求 tensor+FA；
- 官方 reverse-PE 接受 4D 并负责 MCFLIRT/Tmean；项目要求调用者先准备 3D；
- 官方 GRE 支持 Siemens wrapped phase、默认 TE difference `2.46 ms` 和 magnitude 第一 volume；项目只支持已解缠、已缩放 rad/s subset；
- 官方 no-TOPUP EDDY 支持 x/-x/y/-y/z/-z；项目 EDDY wrapper 只接受 x/x-/y/y-；
- 项目 EDDY wrapper 只接受 `3×N` b-vector，FSL 也接受 `N×3`；
- 官方 raw QA 额外生成 raw FA/SSE、6-DOF QA 和 `first_ev_for_check.msh`；项目 unified QA 是新增替代物，不是同一输出合同。

这些缺口若是产品有意缩小范围，应在 README 和 CLI 中逐项声明；若继续声称“SimNIBS 4.6 dwi2cond 完整固定子集”，则需要实现。

### D2C-020-017：nonlinear 前无用地生成 affine tensor

`workflow.py:300-343` 无论最终是否 nonlinear，都运行完整 `run_t1_registration_nifti`，其中 `t1_registration.py:348-411` 已做一次 affine tensor resampling、PPD、decomposition 和写盘。随后 `workflow.py:348-399` 又从 raw-space tensor 做 nonlinear PPD，前一份 affine tensor 不被最终结果消费。

官方 nonlinear 只需要 FLIRT matrix/T1 preparation→FNIRT→一次 vecreg。项目额外工作通常不改变最终数值，但增加时间、RSS、cache dependency 和不必要的失败点。应拆出 matrix/T1/QA-only 前置 stage，并用 bitwise final-artifact 回归证明重构不改变 nonlinear 输出。

### D2C-020-018：robustness 扩展不是 strict-FSL 行为

以下行为可以作为安全扩展保留，但必须与 strict compatibility 分开：

- `tensor_fit.py:147-153,169-171` 使用 float64 log 上限约 709；FSL `dtifit.cc:79-82,331-349` 固定 `maxlogfloat=23`，最终直接 `exp`；
- `nifti_fit.py:397-451` 排除 NaN/Inf 或全非正 mask voxel，并把 tensor/S0/SSE 置零；FSL 仍执行其 nonpositive-signal robustification；
- nonlinear 对 fold、near-singular 或 PPD 不稳定 voxel 显式清零；FSL `vecreg` 没有完全相同的公共任意-warp安全分支。

建议提供 `strict-fsl` 与 `robust` 两种明确模式；默认、manifest、QA 和文档必须记录所用模式，禁止静默改变。

### D2C-020-019：无 FEM 时仍要求 FEM 文件

`workflow.py:55-82` 无论 `fem_smoke` 是否为 `none`，都要求 mesh 和 EEG 文件。官方 dwi2cond preprocessing/T1 registration 不消费 EEG；官方 mesh 只在最后生成 `first_ev_for_check.msh` QA 时使用。应按实际 stage 延迟校验 EEG，以及当前 DAG 没有消费的文件；mesh 是否必需应由是否实现该官方 QA stage 决定。否则一个纯 tensor 任务会被无关文件阻塞。

## 7. 官方 GRE 脚本自身的缺陷边界

官方 SimNIBS 4.6 shell 脚本存在一个明确的参数计数错误：

- `dwi2cond.functions.source.sh:228-240` 的 `EDDY_CORRECT` 使用 `if [ $# -gt 5 ]` 判断是否启用第 5 个 warp 参数；
- `dwi2cond.prepro.source.sh:168` 在有场图时恰好传 5 个参数。

按 shell 字面语义，官方会准备 undistorted mask，却不把第 5 个 DWI warp 应用到最终 DWI。v0.2.0 实际应用 displacement，复现的是显然的设计意图，而不是该 upstream off-by-one bug。

后续修复不应故意复制这个官方 bug。建议冻结两条参考：

1. **literal upstream**：记录官方 4.6.0 原脚本行为，用于 provenance；
2. **intended/patched reference**：只把 `-gt 5` 修为能接收第 5 参数，用于 GRE 科学 A/B。

任何报告都应明确使用哪条参考，不能混用。

## 8. 已核实基本一致或可接受的部分

本次审计没有发现以下主体逻辑存在流程级错误：

- 正常、finite、positive、单位 b-vector 的 WLS 主公式；本机 FSL `dtifit` 定向测试通过；
- tensor 顺序 `[Dxx,Dxy,Dxz,Dyy,Dyz,Dzz]`；
- gradient-nonlinearity 九分量矩阵排列；在输入 b-vector 已单位化时，直接使用变换后向量与 FSL 的“方向再单位化、b-value 乘模长平方”在 design product 上等价；
- legacy 两遍 6/12-DOF 名义顺序、DWI mean→nodif、b0 matrix 替换和最终单次 sinc；
- legacy `compat46` 不旋转 b-vector，符合官方脚本；
- TOPUP `b02b0_nosubsamp` 的九级 warpres/fwhm/miter/lambda/estmov/minimizer schedule；
- EDDY `--repol` 的五轮名义结构、outlier 阈值、inverse-movement b-vector rotation 和 Jacobian modulation 主方向；
- EDDY susceptibility field 的 model→scan 逐卷运动变换与 scan→model 共同 model-grid 分工；该点已与 FSL C++ 调用链核对，不需要修改算法；
- GRE 已解缠 rad/s subset 的 median、P50 offset、6-DOF MI registration 和 displacement 合成主体；
- affine tensor inverse pull、trilinear六分量插值、前三分量 source mask、polar finite-strain `RDR^T`；该 polar rotation 与 FSL `vecreg` 源码等价；
- FNIRT 固定四级 schedule：subsamp `8,4,2,2`，miter `5,5,5,5`，lambda `240,120,60,60`，以及对应 smoothing/estint/Jacobian 约束；
- nonlinear pull、warp Jacobian、PPD 和六分量输出主体；固定同一 FSL warp 的已有 PPD A/B 很接近；
- 主 `run_tdcs`/FEM 路由将 tensor 交给官方 SimNIBS，最终 conductivity 由官方 `cond_utils` 计算。

这些一致部分只说明应保留的实现基础，不能抵消前面 artifact、mask、默认值和输入合同错误。

### 9.4 定向数值实验的可复现边界

本轮新增的精确数字来自 v0.2.0 解包快照中的一次性定向实验，尚未固化为版本化 fixture/test。它们用于确认源码差异确实能产生数值差异，**不能在未固化前作为发布验收门禁**。输入合同如下，后续修复时应按这些参数建立正式测试：

- **非单位 b-vector**：`1×1×1` voxel，两个 b0 加 9 个 `b=1000` 方向；基础方向依次为 x/y/z、xy/xz/yz 正对角和 xy/xz/yz 一正一负对角，先单位化；生成信号使用单位方向、`S0=1000` 和 tensor `[1.4e-3,8e-5,-4e-5,7e-4,6e-5,4e-4]`，提供给两边的 DWI b-vector 再依次缩放到模长 `0.8,0.85,...,1.2`。项目调用 tag 中 `fit_dti_nifti`，FSL 调用 `/usr/local/fsl/bin/dtifit --wls --save_tensor --sse`。
- **负定派生图**：同一两个 b0 + 9 方向、`b=1000`、`S0=1000`，生成 tensor 为 `[-2e-4,5e-5,-3e-5,-4e-4,4e-5,-8e-4]`；项目与 FSL tensor max-abs 为 0，但派生图按各自生产路径写出。
- **DIR/MC 零 tensor**：单一 tissue tag `1`，参考 conductivity `0.126`，四个 weight 均为 1，`max_ratio=10`、`max_cond=2`、`correct_intensity=True`；四个 tensor 依次为零矩阵、`diag(1.5e-3,0.7e-3,0.4e-3)`、`diag(1.2e-3,0.8e-3,0.5e-3)`、`diag(0.9e-3,0.6e-3,0.3e-3)`。官方结果来自对 `cond_utils.py:272-344` 分支顺序的直接转录；受限环境导入完整 SimNIBS 时会触发 MPI socket 限制，因此修复验收必须在可运行 SimNIBS 的环境中改为直接调用官方 `cond_utils` A/B。
- **nonlinear mask**：`6×6×6` 全域正定非零 tensor、identity warp、中心 `4×4×4` T1 brain mask；统计输出 tensor 的 mask 内/外非零 voxel。后续正式 fixture 需固定 tensor 六分量、NIfTI affine/header 和输出 hash。

上述实验脚本和临时数据没有加入发布仓库。本报告保留输入参数和证据边界，修复阶段应先把它们转成最小回归测试，再引用精确小数结果。

## 11. 修复后验收矩阵

所有正式结论都应使用同输入、同 shape、同 mask、同 bvals/bvecs、同精度和相同输出边界；先 small synthetic，再真实 single-shell fixture。固定八线程 reference A/B，并记录版本、预热、同步、wall、RSS 和误差。

| 门禁 | 必测输入 | 必比输出 | 建议判定 |
| --- | --- | --- | --- |
| EDDY artifact lineage | corrected/outlier-free sentinel | fitter 实际输入 hash | 必须只消费 corrected |
| EDDY output mask | 非平凡运动/EC/field、边界失效 | corrected DWI、output mask | FSL support 精确一致；mask 外精确零 |
| b-value 分类 | `0/50/51/100/101` | b0/DWI indices、shell groups | 与 FSL 6.0.4 相同 |
| b-vector | 单位/非单位、3×N/N×3、grad_dev | design、tensor、FA/SSE/V1 | stage-level FSL A/B |
| DTI 派生图 | 正定、负定、全零、非正、极端 S0 | tensor/S0/SSE/FA/MD/MO/L/V | strict 模式逐输出 A/B |
| raw orientation | RAS/LAS、neurological/radiological、qform/sform | normalized DWI/mask/PE/bvec | storage 和世界坐标合同一致 |

## 12. 最终判定

v0.2.0 已经实现了许多有价值的 FSL/SimNIBS 固定子集 kernel，但当前版本的完整控制流、输入合同和若干算法顺序并不等同于官方实现。尤其是 EDDY fit artifact、nonlinear post-mask、GRE corrected mask 和 standalone DIR/MC 零 tensor 问题，足以否定“端到端同逻辑”的结论。

建议把本报告作为修复主清单：先关闭 P0，再逐项关闭 P1；每修一项只改一个可测热点，保留 reference 路径和明确开关，并以同输入 FSL/SimNIBS A/B 重新建立证据。未重新验收前，v0.2.0 的现有 release/test/coverage 证据只能证明工程可运行和部分 kernel 接近参考，不能证明官方算法等价。
