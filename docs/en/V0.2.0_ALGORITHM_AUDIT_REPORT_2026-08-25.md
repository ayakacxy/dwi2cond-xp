## 1. Findings

This audit first compared the full workflow, then checked each module's input requirements, branches, operation order, numerical formulas, coordinate/mask semantics, and final outputs. Several underlying implementations have good source-level or numerical consistency evidence: the principal WLS formula on ordinary input, tensor six-component order, gradient-nonlinearity nine-component arrangement, affine tensor polar reorientation, fixed FNIRT schedule, main nonlinear PPD implementation, and the main `run_tdcs` path calling official SimNIBS.

The significant differences occur at several critical connections and boundaries in v0.2.0:

1. `run-pipeline --preprocessing-mode eddy` passes scan-space `outlier_free_data.nii.gz` to WLS instead of `corrected_dwi.nii.gz`, which contains actual motion, eddy-current, and susceptibility correction. The final EDDY tensor in the full DAG therefore bypasses geometric correction.
2. The nonlinear path omits the official T1 brain mask required after `vecreg`, allowing final tensor, FA, V1, and valid-mask values to remain nonzero outside the brain.
3. The GRE fieldmap path computes an undistorted mask but does not pass it to legacy WLS, which continues using the distorted-grid mask.
4. Standalone `tensor-to-mesh` DIR/MC fills zero tensors before eigendecomposition. With default `correct_intensity=True`, this changes intensity scaling across the tissue and can cause nearly order-of-magnitude result differences when zero tensors are present.
5. DTI fitting does not normalize b-vectors as FSL does. In a same-input reproduction with nonunit b-vectors, tensor deviation from FSL is `0.143597`.
6. Existing tests check only the shapes of EDDY's two semantically different products and omit invariants for exact-zero nonlinear output outside the brain, DIR/MC zero tensors, nonunit b-vectors, and derived maps for negative-definite tensors. `100% statement coverage` did not detect these issues.

Until the P0/P1 fixes and same-input FSL/SimNIBS A/B described here are complete, avoid claims of a “complete replacement for official dwi2cond”, “identical logic”, or conductivity parity for all inputs.

## 3. Official and v0.2.0 workflow comparison

Official SimNIBS 4.6 `dwi2cond` follows:

```text
raw DWI / pre-fitted tensor
  -> fslreorient2std for raw DWI, fieldmap, and reverse-PE
  -> aligned exact b=0 mean + BET
  -> nomoco / legacy(+GRE) / EDDY(+TOPUP)
  -> apply -thr 0 uniformly to final DWIforfit
  -> dtifit --wls --sse --save_tensor (all single-shell volumes)
  -> T1 brain/mask
  -> FLIRT 6/12 DOF
  -> default FNIRT or linear vecreg
  -> post-vecreg T1 brain mask
  -> tensor decomposition, QA, publication of m2m tensor
```

Key official evidence:

- Default legacy correction and nonlinear registration: `dwi2cond:51-70`.
- Only caller-prepared single-shell inputs are supported: `dwi2cond:143-160`.
- Raw/reverse-PE reorientation: `dwi2cond.prepro.source.sh:33-64`.
- Exact `b=0`, MCFLIRT mean, BET: `dwi2cond.prepro.source.sh:67-100`.
- EDDY/TOPUP and legacy/GRE branches: `dwi2cond.prepro.source.sh:117-170`.
- Uniform post-correction `-thr 0`, then fitting of every input volume: `dwi2cond.prepro.source.sh:173-178`.
- FLIRT/FNIRT/vecreg/post-mask: `dwi2cond.t1reg.source.sh:19-44`.
- QA and `first_ev_for_check.msh`: `dwi2cond.t1reg.source.sh:47-65`.

v0.2.0 uses similar stage names but differs materially at these points:

| Stage | Official | v0.2.0 | Finding |
| --- | --- | --- | --- |
| Default modes | legacy + nonlinear | nomoco + affine | Different default scientific workflow |
| Raw orientation | Reorient all raw DWI/reverse-PE first | Present for nomoco/legacy; absent for EDDY/TOPUP | Noncanonical EDDY/TOPUP inputs are not equivalent |
| b0 rules | Exact `b=0` for raw masks; internal EDDY threshold 100 | Shared or hardcoded 50 in several places | Different branch classification |
| TOPUP→EDDY | Reverse 4D alignment/mean, TOPUP, corrected-b0 BET, `--topup` | Two standalone 3D b0s, external 3D Hz field, external mask | Not the complete official workflow |
| EDDY fitting artifact | Registered corrected DWI | Scan-space outlier-free data | Critical connection error |

## 5. Critical, High, and major workflow issues

### D2C-020-001: EDDY DAG fits data in the wrong space

At `src/dwi2cond_xp/preprocessing/workflow.py:227`, v0.2.0 assigns `corrected_dwi` to:

```text
eddy/outlier_free_data.nii.gz
```

`workflow.py:232-244,276-293` then passes it to `fit_dti_nifti`.

The EDDY implementation itself distinguishes these artifacts:

- `eddy.py:2938-2944`: copy `outlier_free_scans = scans.copy()` immediately after outlier replacement, while still in scan space.
- `eddy.py:2944-2952,3114-3150`: only afterward perform final movement/EC/susceptibility unwarping and resampling.
- `eddy.py:3176-3182`: `corrected_scans` contains the actual corrected data.
- `eddy.py:3279-3287`: write `corrected_dwi.nii.gz` and `outlier_free_data.nii.gz` separately.

FSL also distinguishes their spaces:

- `WriteOutlierFreeData` in `/usr/local/fsl/src/eddy/ECScanClasses.cpp:1262-1273` writes scan-space images directly.
- `/usr/local/fsl/src/eddy/eddy.cpp:362-377` separately writes final registered images.
- Official `dwi2cond.prepro.source.sh:140-177` uses EDDY main output `DWI_corr` as `DWIforfit`.

The full local DAG therefore combines DWI lacking final geometric correction with already rotated b-vectors. This is an incorrect artifact connection, not a small numerical deviation.

The same path also omits the final `-thr 0` at official `dwi2cond.prepro.source.sh:173-177`.

**Required fix:**

1. WLS and corrected-DWI QA must use only `corrected_dwi.nii.gz`.
2. After correction and before fitting, apply a float32 nonnegative threshold matching `fslmaths -thr 0`.
3. Rename `outlier_free_data` or clearly identify it in the manifest as a scan-space diagnostic; it must not be used for fitting.
4. Cache fingerprints must distinguish the two artifacts.

**Minimal regression:** mock EDDY so corrected data is all `2` and outlier-free data is all `1`, then assert that the fitter actually reads `2`. Existing `tests/test_preprocessing_eddy.py:397-398` checks only shapes, while the fake fitter in `tests/test_preprocessing_workflow.py:279-301` ignores content, so neither detects the issue.

### D2C-020-002: final EDDY output lacks FSL's default joint mask

The project already calculates masks during resampling:

- `eddy.py:1623-1645` returns `transformed.mask`.
- `eddy.py:2530-2537,2949-2968` computes b0/DWI joint masks.

But final `corrected_scaled` generation at `eddy.py:3114-3150` copies only `transformed.values`, without collecting or applying a mask across all volumes.

FSL does not enable `--dont_mask_output` by default:

- `/usr/local/fsl/src/eddy/EddyCommandLineOptions.cpp:97`.
- `/usr/local/fsl/src/eddy/EddyCommandLineOptions.h:208`.

At `/usr/local/fsl/src/eddy/ECScanClasses.cpp:1401-1430`, it intersects each volume's `tmpmask` and applies `ovol *= omask` before writing. Local periodic cubic sampling may return extrapolated values at invalid coordinates. Without the joint mask, those values can persist within the later DTI mask.

**Required fix:** return values and masks from final resampling, intersect every b0 and DWI volume's mask, and multiply the complete corrected 4D data once before writing. Default FSL applies the joint mask but does not write `.eddy_output_mask`. A diagnostic reference run should explicitly use `--dont_mask_output`; intersect the resulting per-volume 4D mask, then use a separate default run to verify exact-zero registered output outside the joint valid domain. The project may publish its own joint mask but must not call it a default FSL artifact.

### D2C-020-003: final nonlinear tensors lack the T1 brain mask

Official ordering is:

```text
fnirt -> vecreg -> fslmaths DTI_coregT1_tensor -mas T1_brainmask
```

See `dwi2cond.t1reg.source.sh:39-44`.

In v0.2.0:

- `workflow.py:348-399` invokes the nonlinear stage without `T1_brainmask`.
- `nonlinear.py:711-721` invokes the tensor-registration wrapper without an output/reference mask.
- `nonlinear.py:260-270` treats the entire target grid as valid when no reference mask is supplied.
- `nonlinear.py:336-355` limits output only by source support, warp folds, and singularity.

A small identity-warp reproduction uses nonzero tensors throughout a `6×6×6` grid and a central `4×4×4` T1 mask:

- v0.2.0: 64 nonzero voxels inside the brain and 152 outside.
- Emulated official post-mask: 0 nonzero voxels outside the brain.

This affects final tensors, FA, V1, the valid mask, and mesh interpolation near the brain boundary. Aggregate QA restricts its statistics with the brain mask first, potentially hiding invalid actual outputs.

**Required fix:** immediately after PPD, mask both tensor and valid mask, then derive FA/V1 from the masked tensor. Include the brain mask in stage inputs/fingerprints. Assert elementwise exact zeros in tensor, valid, FA, and V1 outside the mask.

### D2C-020-004: GRE corrected mask does not reach WLS

The scientific comparison for this issue uses the **intended/patched SimNIBS reference** defined in section 7. The official 4.6.0 shell's argument-count off-by-one makes literal upstream behavior itself incomplete and unsuitable as a correct algorithm to copy.

Official GRE branch:

- `dwi2cond.functions.source.sh:159-167` generates `nodif_brain_mask_UNDIST`.
- `dwi2cond.prepro.source.sh:153-160` copies it into the raw-DTI result directory.
- `dwi2cond.prepro.source.sh:173-177` uses the corrected mask for fitting.

v0.2.0 `fieldmap.py:593-608` already writes `corrected_b0` and `corrected_mask`, but:

- `workflow.py:172-181` passes only displacement to legacy.
- `legacy.py:361-373` builds an original mask from distorted nodif.
- `legacy.py:447-464` applies displacement to DWI.
- `legacy.py:489-505` still fits with the original mask.

DWI is therefore on undistorted grid/support while the mask retains distorted support.

**Required fix:** pass displacement, corrected b0, and corrected brain mask as one inseparable fieldmap-stage bundle. Use the corrected mask in legacy WLS and verify agreement of corrected DWI/mask shape, affine, qform/sform, and support.

### D2C-020-005: incorrect zero-tensor order in standalone DIR/MC

Before eigendecomposition in every mode, v0.2.0 `conductivity.py:150-153` replaces zero tensors with `conductivity * I`. With DIR/MC default `correct_intensity=True`, `conductivity.py:177-225` then includes those filled tensors in global intensity scaling.

Official `cond_utils.py` uses different branch ordering:

- VN applies `_fix_zeros` before eigendecomposition: `cond_utils.py:252-270`.
- DIR/MC decomposes original tensors first, then applies `_fix_eigv(..., -1e-6)`, calculates global scale, applies a second `_fix_eigv(..., tissue conductivity)`, reconstructs, and only then applies `_fix_zeros`: `cond_utils.py:272-344`.

A same-input reproduction directly transcribing official operation order uses one tissue with one zero tensor and three ordinary DTI-scale tensors:

| Metric | Official order | v0.2.0 |
| --- | ---: | ---: |
| Intensity scale | `196.0419603` | `1.5874008` |
| Zero-tensor output diagonal | `0.126` | `0.2000125` |
| DIR full-result relative L2 | baseline | `0.93885` |
| MC full-result relative L2 | baseline | `0.91859` |

The README's existing `0–2.22e-16` parity fixture has no zero tensors and cannot be extrapolated to tensors with zero support.

**Required fix:** reproduce the different official VN and DIR/MC operation orders exactly. Do not prefill DIR/MC zeros. Add A/B varying the zero-tensor fraction, multiple tissues, and unequal volume weights. The severe global-scale difference above specifically concerns default `correct_intensity=True`. `correct_intensity=False` lacks this global scaling, but still requires separate verification of official eig/fix/reconstruct/final-`_fix_zeros` ordering.

**Affected scope:** public `tensor-to-mesh`/`simnibs_adapter`. Main `run_tdcs` passes the tensor to official SimNIBS SESSION and ultimately official `cond_utils.cond2elmdata`, so it is unaffected by this standalone adapter bug.

### D2C-020-006: b-vectors are not normalized as in FSL

Local implementation:

- `gradients.py:10-29` checks only shape, finiteness, and nonnegative b-values.
- `tensor_fit.py:45-70` constructs the design matrix directly from original b-vectors.

FSL `/usr/local/fsl/src/fdt/dtifit.cc:423-432` normalizes each b-vector column before fitting. With gradient nonlinearity, `dtifit.cc:373-395` transforms directions, scales b-values by squared norm, and renormalizes directions.

The one-voxel same-input A/B uses 9 DWI directions with norms from `0.8` to `1.2`:

- Local tensor versus FSL relative L2: `0.1435971297`.
- FSL tensor versus generating truth relative L2: `7.3589e-8`.
- Local tensor versus generating truth relative L2: `0.1435971243`.

A simple example shows why: with `b=1000, g=[2,0,0]`, the local design coefficient for Dxx is `4000`; FSL normalization gives `1000`.

**Required fix:** in the strict-compatibility path, normalize every nonzero direction as FSL does and preserve b0 zero-vector behavior. A zero-norm vector with `b>0` must either explicitly match FSL or fail clearly. Test `3×N`, `N×3`, nonunit directions, and gradient nonlinearity.

### D2C-020-007: fitted derived maps use the wrong FSL subtool's behavior

After fitting, `nifti_fit.py:40-59,337-344` calls `tensor_ops.decompose_tensor6`. At `tensor_ops.py:37-42,82-100`, this zeros FA/MD/MO/L/V when the largest eigenvalue is nonpositive.

That matches `fslmaths -tensor_decomp` at `/usr/local/fsl/src/avwutils/fslmaths.cc:1241-1276`, but not fitting-stage `dtifit`. FSL `dtifit.cc:627-648` writes L/FA/MD/MO/V unconditionally for fitted voxels inside the mask.

A same-input WLS reproduction with a negative-definite anisotropic tensor gives:

| Output | Local | FSL |
| --- | ---: | ---: |
| Tensor maximum absolute difference | `0` | baseline |
| FA | `0` | `0.58911705` |
| MD | `0` | `-4.6666665e-4` |
| V1 maximum component | `0` | `0.974248` |

Tensor fitting is identical, but the local code immediately zeros maps that `dtifit` would output. Raw-space FA feeds later T1 registration, so this **may** propagate to the final transform and tensor. Only derived-map differences were measured here; transform differences caused by this synthetic voxel were not measured.

**Required fix:** use `dtifit` derived-map behavior during fitting. Apply L1>0 gating where official code explicitly calls `fslmaths -tensor_decomp`: prefit tensor import at `dwi2cond.prepro.source.sh:15-17` and post-vecreg. The two behaviors cannot share one context-free implementation.

### D2C-020-008: raw EDDY/TOPUP ingestion lacks `fslreorient2std`

Official raw DWI and reverse-PE inputs undergo storage reorientation first: `dwi2cond.prepro.source.sh:35-36,57-63`. Its comment explicitly says this avoids left-right tensor flips for neurological inputs.

In v0.2.0:

- `eddy.py:3226-3255` loads original DWI/mask/field directly and interprets PE along original array axes.
- `topup.py:2631-2646` directly loads forward/reverse b0.
- Neither entry has a canonical-storage prerequisite stage or enforces already-canonical input.

For noncanonical, neurological, or qform/sform boundary inputs, PE axes, motion matrices, susceptibility fields, and final tensor bases may all differ from official behavior.

**Required fix:** create a shared raw-ingest stage using FSL-equivalent, interpolation-free storage reorientation. Handle DWI, reverse-PE, masks, fieldmaps, grad_dev, and associated direction metadata consistently. Acceptance must cover at least RAS/LAS, neurological/radiological storage, and different qform/sform codes.

### D2C-020-009: complete official TOPUP→EDDY workflow is missing

The complete official sequence includes:

1. Reverse-PE 4D `fslreorient2std`, 6-DOF MCFLIRT, Tmean: `dwi2cond.prepro.source.sh:57-64`.
2. Forward exact-b0 MCFLIRT mean and BET: `dwi2cond.prepro.source.sh:67-91`.
3. First corrected b0 after TOPUP, then `BET -f 0.2`: `dwi2cond.functions.source.sh:197-207`.
4. TOPUP coefficients and movement passed to EDDY as `--topup=topup_res`: `dwi2cond.functions.source.sh:75-83`.

In v0.2.0:

- Standalone `prepare-topup` accepts only two caller-prepared 3D b0 images: `cli.py:193-207`, `topup.py:2605-2638`.
- `run-pipeline` has no reverse-PE/TOPUP stage: `cli.py:306-338`, `workflow.py:141-299`.
- EDDY requires external `dwi_brain_mask`; it cannot generate the official BET mask from TOPUP-corrected b0.
- TOPUP's joint validity mask is not a BET brain mask.
- The external interface provides one 3D Hz field, not the complete official `topup_res` product set.

Manually running `prepare-topup` and passing its field and joint mask to EDDY is therefore not the complete official TOPUP→EDDY DAG. This is a combined-workflow/capability gap rated Medium; it does not invalidate existing numerical evidence for standalone TOPUP and EDDY kernels.

**Important non-issue:** this audit does **not** classify the susceptibility-field motion treatment in current standalone EDDY as a bug. `eddy.py:1389-1407,1503-1536` pulls the TOPUP field according to each volume's movement in model→scan; `eddy.py:1590-1637` statically adds the field already on the common model grid during scan→model, while handling EC fields and image coordinates with per-volume movement. This division matches the structure of FSL `ECScanClasses.cpp:487-508,574-596,618-634`. In the fixed SimNIBS workflow every DWI index is 1, and the first TOPUP image is the zero-motion reference. Not reading TOPUP movpar has therefore not established a numerical error within that fixed scope. The finding concerns missing reverse-PE preparation, corrected-b0 BET, and combined DAG, not the field-motion kernel.

**Required fix:** add a combined stage covering reverse 4D preparation, the official corrected-b0 BET mask, TOPUP products, and EDDY. Record every intermediate artifact in the manifest and compare each stage with FSL.

### D2C-020-010: legacy direct-b0 registration truncates the sequence

At `legacy.py:433-444`, the project truncates the input at the last b0 volume before running direct-b0 registration.

Official `dwi2cond.functions.source.sh:261-273` runs MCFLIRT on the entire 4D DWI, then copies only `b==0` matrices. During the initial 8 mm stage, FSL `/usr/local/fsl/src/mcflirt/mcflirt.cc:443-454` propagates initialization to the next volume, stopping only at the end of the complete sequence.

If DWI volumes follow the final b0, local truncation treats that b0 as the end of the sequence and changes initialization and optimization. The control-flow difference is confirmed, but this audit has not measured its same-input FSL matrix/tensor propagation, so it is rated Medium.

**Required fix:** direct-b0 MCFLIRT must see the complete volume sequence. Replace only b0 matrices afterward. The regression fixture must interleave b0 volumes and include DWI after the last b0.

### D2C-020-011: default scientific workflow differs from the official default

- Official default: legacy correction + nonlinear FNIRT, `dwi2cond:51-70`.
- v0.2.0 default: nomoco + affine, `workflow.py:33-34`, `cli.py:315-322`.

Without explicit mode arguments, the project therefore skips official default motion/eddy correction and nonlinear registration. This is an easily encountered workflow-level difference.

**Required fix:** if `run-pipeline` claims official compatibility, restore legacy + nonlinear defaults. If a fast default is retained, clearly name it as a noncompatible workflow and require explicit selection.

### D2C-020-012: implicit shell selection changes scientific inputs

Official code supports single-shell data and passes every caller-provided volume to `dtifit`: `dwi2cond:143-160`, `dwi2cond.prepro.source.sh:173-178`.

Local `gradients.py:32-53` and `nifti_fit.py:229-239` unconditionally retain:

```text
b <= 50 or |b - 1000| <= 100
```

`run-pipeline` does not expose these parameters. HCP and other multi-shell inputs are silently cropped to b1000 instead of being rejected or passed through a separately recorded shell-selection step.

This also contradicts the public requirements in v0.2.0 `docs/INPUT_CONTRACT.md:84-86`, which require explicit `select-shell` or an equivalent traceable step before multi-shell data is used. `run-pipeline` instead applies hidden defaults internally.

The same default `b0_threshold=50` is used for nodif mean and BET masking at `nomoco.py:121-130,186-199`, while official raw preprocessing uses exact `b=0` at `dwi2cond.prepro.source.sh:73-91`. Thus `b=1..50` changes not only fitting-volume selection but also the nomoco registration reference and mask.

Automatic shell selection may be a useful safety tool, but it does not reproduce official logic.

**Required fix:** a strict-compatibility entry must verify one nonzero shell, then fit all volumes. Multi-shell input must fail with instructions to run explicit `select-shell` first; that tool should record shell, tolerance, hashes, and volume indices in a manifest.

### D2C-020-013: incorrect EDDY b0/DWI threshold

- Local `eddy.py:3011-3017`: `b<=50` is b0; `b>50` is DWI.
- FSL `/usr/local/fsl/src/eddy/EddyUtils.h:44,124-127`: `b_range=100`; only `b>100` is DWI.

Values `b=51..100` therefore enter different GP, outlier, registration, and shell-grouping branches. The local check that the global b-value range is at most 100 also differs from FSL's per-shell `AreInSameShell`. Ordinary exact-b0 + b1000 strict single-shell input does not trigger this interval, and no final tensor A/B was run for it here, so severity is Medium.

**Required fix:** separate three rules instead of sharing a global constant 50:

- Official raw nodif/BET: exact `b=0`.
- Internal FSL EDDY grouping: 100.
- Explicit shell-selection tool: user-specified threshold and tolerance.

## 6. Medium/Low compatibility issues

### D2C-020-014: negative signals clipped too early

`nomoco.py:24-89` and `legacy.py:337-376` set `nonnegative=True` during raw materialization. These data then enter b0 mean, BET, and MCFLIRT.

Official code applies `-thr 0` only after every correction and immediately before final `dtifit`. Negative background or reconstruction values therefore change local registration costs and masks. Move zero-clipping back to the shared correction→fit boundary and add the missing boundary in EDDY.

### D2C-020-015: final tensor is not published to the official m2m path

Official output is:

```text
m2m_<subject>/DTI_coregT1_tensor.nii.gz
```

v0.2.0 `workflow.py:403,549-552` only returns the tensor in the DAG output root. Internal FEM works because the tensor is explicitly supplied, but a later ordinary SimNIBS SESSION cannot discover it by default. This also contradicts `README.md:258-260`.

Provide an explicit atomic publication stage with checksum/provenance. If automatic m2m writes are not permitted, correct the documentation and provide a user-confirmed `publish-to-m2m` command.

### D2C-020-016: incomplete official input, PE, and QA support

These are capability/interface gaps, separate from implemented numerical kernels:

- Official code accepts a lone FSL `DTI_tensor`, then copies/reorients/decomposes it before T1 registration. v0.2.0 `run-pipeline` requires raw DWI+bvals+bvecs; standalone `register-t1` requires tensor+FA.
- Official reverse-PE accepts 4D data and performs MCFLIRT/Tmean; the project requires caller-prepared 3D images.
- Official GRE supports Siemens wrapped phase, default TE difference `2.46 ms`, and the first magnitude volume. The project supports only an already-unwrapped, scaled rad/s subset.
- Official EDDY without TOPUP supports x/-x/y/-y/z/-z; the local wrapper accepts only x/x-/y/y-.
- The local EDDY wrapper accepts only `3×N` b-vectors, whereas FSL also accepts `N×3`.
- Official raw QA additionally outputs raw FA/SSE, 6-DOF QA, and `first_ev_for_check.msh`. Local unified QA is a new alternative, not the same output set.

If these are deliberate scope limits, list them individually in README and CLI. If the project continues to claim the complete fixed SimNIBS 4.6 dwi2cond subset, implement them.

### D2C-020-017: unnecessary affine tensor generation before nonlinear registration

Regardless of the final nonlinear mode, `workflow.py:300-343` runs full `run_t1_registration_nifti`. Inside it, `t1_registration.py:348-411` performs affine tensor resampling, PPD, decomposition, and output writing. `workflow.py:348-399` then performs nonlinear PPD from the raw-space tensor, leaving the preceding affine tensor unused by the final result.

Official nonlinear processing needs only FLIRT matrix/T1 preparation→FNIRT→one vecreg. Extra local work usually does not change final numerics but increases time, RSS, cache dependencies, and failure points. Split out a matrix/T1/QA-only prerequisite stage and demonstrate bitwise unchanged final nonlinear artifacts after refactoring.

### D2C-020-018: robustness extensions differ from strict FSL behavior

The following may be retained as safety extensions, but should be separated from strict compatibility:

- `tensor_fit.py:147-153,169-171` uses a float64 log ceiling around 709; FSL `dtifit.cc:79-82,331-349` fixes `maxlogfloat=23` and applies `exp` directly at the end.
- `nifti_fit.py:397-451` excludes NaN/Inf and entirely nonpositive masked voxels, zeroing tensor/S0/SSE; FSL still applies its nonpositive-signal robustification.
- Nonlinear processing explicitly zeros folded, near-singular, or PPD-unstable voxels. FSL `vecreg` has no identical public safety branch for arbitrary warps.

Provide explicit `strict-fsl` and `robust` modes. Defaults, manifests, QA, and documentation must record the selected mode; do not change it silently.

### D2C-020-019: FEM files are still required with FEM disabled

`workflow.py:55-82` requires mesh and EEG files even when `fem_smoke` is `none`. Official dwi2cond preprocessing/T1 registration does not use EEG; its mesh is used only for final `first_ev_for_check.msh` QA. Validate EEG and other unused files only when the actual stage needs them. Mesh requirements should depend on whether that official QA stage is implemented. Otherwise unrelated files can block a tensor-only task.

## 7. Defect in the official GRE shell script

Official SimNIBS 4.6 shell code contains a definite argument-count error:

- `EDDY_CORRECT` at `dwi2cond.functions.source.sh:228-240` uses `if [ $# -gt 5 ]` to decide whether the fifth warp argument is enabled.
- With a fieldmap, `dwi2cond.prepro.source.sh:168` passes exactly five arguments.

Literal shell behavior prepares an undistorted mask but does not apply the fifth-argument DWI warp to final DWI. v0.2.0 actually applies displacement, reproducing the clear design intent rather than the upstream off-by-one bug.

Do not intentionally copy that official bug. Freeze two references:

1. **Literal upstream:** retain original official 4.6.0 script behavior for provenance.
2. **Intended/patched reference:** change only `-gt 5` to accept the fifth argument, for scientific GRE A/B.

Every report should identify which reference it uses; do not mix them.

## 8. Parts found broadly consistent or acceptable

This audit found no workflow-level error in these main implementations:

- Principal WLS formula for ordinary finite, positive inputs with unit b-vectors; the focused local FSL `dtifit` test passes.
- Tensor order `[Dxx,Dxy,Dxz,Dyy,Dyz,Dzz]`.
- Gradient-nonlinearity nine-component matrix arrangement. With unit input b-vectors, using transformed vectors directly produces the same design product as FSL's direction renormalization and squared-norm b-value scaling.
- Nominal legacy two-pass 6/12-DOF order, DWI mean→nodif, b0 matrix replacement, and one final sinc resampling.
- Legacy `compat46` retains original b-vectors, matching the official script.
- TOPUP `b02b0_nosubsamp` nine-level warpres/fwhm/miter/lambda/estmov/minimizer schedule.
- EDDY `--repol` nominal five-round structure, outlier thresholds, inverse-movement b-vector rotation, and main Jacobian-modulation direction.
- EDDY susceptibility-field division between per-volume movement in model→scan and the common model grid in scan→model. It was checked against FSL's C++ call chain and does not require an algorithm change.
- Main GRE unwrapped rad/s-subset median, P50 offset, 6-DOF MI registration, and displacement composition.
- Affine tensor inverse pull, trilinear interpolation of six components, source mask from the first three components, and polar finite-strain `RDR^T`. The polar rotation matches FSL `vecreg` source.
- FNIRT fixed four-level schedule: subsamp `8,4,2,2`, miter `5,5,5,5`, lambda `240,120,60,60`, and corresponding smoothing/estint/Jacobian constraints.
- Main nonlinear pull, warp Jacobian, PPD, and six-component output. Existing PPD A/B using the same fixed FSL warp is close.
- Main `run_tdcs`/FEM routes tensors to official SimNIBS, with final conductivity calculated by official `cond_utils`.

These findings identify implementation foundations to preserve. They do not negate the artifact, mask, default-value, and input-requirement errors above.

Existing tests emphasize statement/branch coverage and happy-path synthetic numerics. They do not cover:

- Corrected/outlier-free artifact meaning and downstream selection in the complete DAG.
- EDDY joint support across all volumes.
- Exact zeros outside the T1 mask in nonlinear output.

`100% statement coverage` establishes that each statement ran. It does not establish correct downstream artifact selection or preservation of scientific invariants.

### 9.4 Reproducibility limits of focused numerical experiments

New exact numbers in this audit come from one-off focused experiments on the exported v0.2.0 snapshot. They are not yet versioned fixtures/tests. They establish that source differences can produce numerical differences, but **must not become release acceptance checks before being preserved as fixtures**. The inputs below should be used to create formal tests during remediation:

- **Nonunit b-vectors:** `1×1×1` voxel, two b0 volumes and 9 `b=1000` directions. Base directions are x/y/z, positive xy/xz/yz diagonals, then xy/xz/yz diagonals with one positive and one negative component, normalized first. Signals use unit directions, `S0=1000`, and tensor `[1.4e-3,8e-5,-4e-5,7e-4,6e-5,4e-4]`. DWI b-vectors supplied to both implementations are then scaled to norms `0.8,0.85,...,1.2`. Local code calls the tag's `fit_dti_nifti`; FSL calls `/usr/local/fsl/bin/dtifit --wls --save_tensor --sse`.
- **Negative-definite derived maps:** the same two b0 + 9 directions, `b=1000`, `S0=1000`, with generating tensor `[-2e-4,5e-5,-3e-5,-4e-4,4e-5,-8e-4]`. Local/FSL tensor max-abs difference is 0, but derived maps are written through each production path.
- **DIR/MC zero tensor:** single tissue tag `1`, reference conductivity `0.126`, four weights all equal to 1, `max_ratio=10`, `max_cond=2`, `correct_intensity=True`. The four tensors are the zero matrix, `diag(1.5e-3,0.7e-3,0.4e-3)`, `diag(1.2e-3,0.8e-3,0.5e-3)`, and `diag(0.9e-3,0.6e-3,0.3e-3)`. - **Nonlinear mask:** positive-definite nonzero tensors throughout `6×6×6`, identity warp, and a central `4×4×4` T1 brain mask; count nonzero output-tensor voxels inside/outside the mask. A formal fixture must fix all six tensor components, NIfTI affine/header, and output hash.

The experiment scripts and temporary data are not in the release repository. This report preserves their input parameters and evidence limits. Convert them to minimal regression tests before citing their exact decimal results as acceptance evidence.

## 12. Final assessment

v0.2.0 implements many useful kernels for the fixed FSL/SimNIBS subset, but its full control flow, input requirements, and several operation orders differ from the official implementation. EDDY fitting input, nonlinear post-masking, GRE corrected masks, and standalone DIR/MC zero-tensor handling are sufficient to invalidate claims of identical end-to-end logic.

Use this report as a remediation checklist: resolve P0 first, then P1 individually. Change one testable part at a time, preserve the reference path and explicit switches, and rebuild evidence through same-input FSL/SimNIBS A/B. Until that validation is complete, v0.2.0 release/test/coverage results establish operational software and partial kernel agreement, not official algorithm equivalence.
