## Findings

The current v0.3.0 **default workflow order is largely correct**. Within the supported default `legacy + nonlinear + WLS` path, this review found no new stage-order error, incorrect production fitting input, reversed T1-registration dependency, or silent replacement of production FEM. The high-level producer-to-consumer paths for nomoco, legacy, EDDY/TOPUP, DTIFIT, 6/12 DOF, FNIRT, PPD, post-masking, tensor publication, and real SimNIBS SESSION can be mapped stage by stage to the official workflow.

However, **2 P1 and 3 P2 issues** remain in the algorithms and computation behavior. No P0 was found:

| ID | Severity | Confirmed finding | Main impact |
|---|---:|---|---|
| `D2C-030-060` | P1 | For positive-determinant/RAS input, legacy registration produces local scaled-mm matrices that the consumer interprets as FSL radiological scaled-mm matrices | Corrected DWI, matrices, optional corrected bvecs, tensors, and all downstream results |
| `D2C-030-061` | P1 | Both BET backends omit the 7 mm inward endpoint and sub-mm `dscale` sampling stencil | Raw/legacy/GRE/TOPUP/EDDY masks and production fitting support |
| `D2C-030-062` | P2, compatibility | Local conductivity uses stable `eigh`, while literal SimNIBS 4.6 uses `eig`; repeated eigenvalues can produce definite output divergence | Standalone `tensor-to-mesh` differs from production SimNIBS conductivity |
| `D2C-030-063` | P2, conditional | FEM cache identity does not completely identify composite solvers, actually loaded native libraries, or all executed modules | Environmental drift may silently reuse old FEM results |
| `D2C-030-064` | P2, output format | TOPUP coefficient NIfTI omits FSL cubic-field intent `2016` and the original field voxel-size intent parameters | Coefficient artifacts cannot interoperate as FSL TOPUP coefficients |

`060` and `061` affect ordinary scientific arrays and should be fixed first. `062` does not imply that local `eigh` is mathematically wrong; it is the more appropriate, stable choice for real symmetric tensors. The problem is that a claim of matching every SimNIBS 4.6 output fails on valid repeated-eigenvalue inputs. Stable and literal-compatibility behavior must be documented separately. `063` concerns cache reliability and `064` concerns interoperability with official artifacts.

With every real FSL probe explicitly configured, the full repository suite produced:

```text
671 passed, 0 skipped in 208.70s
```

This does not invalidate the findings. Key existing MCFLIRT, BET, TOPUP, and EDDY fixtures mostly use negative-determinant/LAS inputs, smooth 2 mm masks, or file-existence checks. They do not cover the discriminating counterexamples below.

## 3. D2C-030-060: incorrect legacy matrix coordinates for positive-determinant/RAS inputs

### 3.1 Failure path

Positive-determinant input is reachable in normal use:

- `orientation.py:155-171` explicitly retains RAS for `det(affine)>0` and LAS for negative determinants.
- `orientation.py:226-273` only permutes/flips storage and preserves handedness.
- Already canonical positive-determinant float32 data can use the no-interpolation input path directly.

The local legacy registration producer uses ordinary positive-diagonal scaled-mm coordinates:

- `legacy.py:137-179` extracts only positive voxel sizes from the affine.
- `_register_mcflirt_series()` and `_optimize_one_stage()` optimize on this local diagonal grid.
- Mean-DWI→nodif FLIRT at `legacy.py:571-582` also uses ordinary positive-diagonal sampling.
- The producer therefore returns a local scaled-mm matrix without the neurological-to-radiological x flip.

The consumer interprets it as an FSL matrix:

- `_resample_series()` at `legacy.py:258-283` calls `fsl_matrix_to_world()`.
- `transforms.py:235-253` inserts FSL's x reflection for positive-determinant NIfTI.
- `transforms.py:256-276` assumes the input matrix is already in FSL radiological scaled-mm coordinates.
- The local matrix is therefore interpreted in a different coordinate system. Saved `MAT_*`, final corrected images, and `bvec_mode=corrected` rotations no longer share one matrix convention.

Official FSL calls `makeradiological()` after reading neurological NIfTI at `newimage/generalio.cc:300-306`; MCFLIRT then estimates matrices and resamples on the same radiological internal storage. Official producer and consumer agree; the current local pair does not.

### 3.2 Discriminating real FSL A/B

Paired inputs use the same asymmetric `25×23×21` arrays with 2 mm voxels and both x/y translation. Only the affine determinant changes. All errors are relative L2 against the same data and reference image. Image numbers come from a focused trilinear probe isolating the matrix consumer, not a complete positive-determinant legacy sinc run. The coordinate-conjugation finding does not depend on sinc; the full workflow remains a required acceptance check.

| Metric | `det>0` RAS | `det<0` LAS control |
|---|---:|---:|
| Local raw matrix vs FSL | `1.07603` | `0.009685` |
| Local matrix after correct x-reflection conjugation vs FSL | `0.018729` | Not required |
| Current `_resample_series` image vs FSL | `0.445403` | `0.019798` |
| Image using local-grid `_scaled_to_world` vs FSL | `0.020210` | Comparable to current behavior |

Key x translations:

```text
FSL det>0 matrix tx       = +1.86422 mm
local det>0 matrix tx     = -1.88515 mm
local tx after x conjugation = +1.88559 mm
```

Three discriminating conditions are satisfied:

1. The positive-determinant path clearly fails.
2. The negative-determinant control using the same arrays remains close to FSL.
3. Applying only the theoretically required x-reflection conjugation restores error to the scale of ordinary optimizer differences.

This confirms a producer-to-consumer coordinate mismatch, rather than a generic registration-trajectory difference or a random consequence of a small phantom.

### 3.3 Affected paths

- Pass1 6 DOF mean: `legacy.py:527-547`.
- Pass2 12 DOF mean: `legacy.py:550-569`.
- Mean-DWI→nodif composition: `legacy.py:571-582`.
- Direct b0 replacement: `legacy.py:583-594`.
- One final sinc/applywarp resampling: `legacy.py:596-616`.
- Saved `MAT_*` and world matrices: `legacy.py:617-623`.
- `bvec_mode=corrected`: `legacy.py:624-632`.
- Although `compat46` copies original bvecs, corrected DWI, tensors, T1/PPD, conductivity, and FEM still inherit the error.

Key existing real FSL legacy/MCFLIRT fixture affines have negative determinants, such as LAS diagonals at `tests/test_preprocessing_legacy.py:28` and `:269`. The 671 tests therefore do not trigger this issue.

### 3.4 Fix and acceptance checks

Use one explicit FSL radiological internal-grid convention. Correctly apply x reflection at the registration working-array and matrix-producer boundaries for positive determinants so that the producer returns genuine FSL scaled-mm matrices. Continue applying them to original NIfTI storage through `fsl_matrix_to_world()`.

Changing only the final image consumer to local `_scaled_to_world()` would leave saved matrices, mean-to-nodif composition, direct b0 replacement, and corrected bvecs using mixed conventions.

Acceptance requires at least:

1. Physically paired `det>0`/`det<0` fixtures using identical arrays.
2. Asymmetric images, x translation, and rotation about all three axes.
3. Comparisons of raw matrices, world-corner displacement, pass1/pass2 means, direct b0, and final DWI.
4. Both `compat46` and corrected-bvec paths.
5. Same-input real FSL MCFLIRT/FLIRT A/B.
6. A complete positive-determinant legacy raw→tensor regression, beyond the matrix helper.

## 4. D2C-030-061: BET inward ray omits endpoint and sub-mm samples

### 4.1 Shared error in both backends

Optimized backend:

- `brain_mask.py:194-207` calculates and bounds-checks the 1 mm and 7 mm endpoints.
- `brain_mask.py:211-224` uses `range(1, 7)`, sampling only 1–6 mm.
- The 7 mm endpoint participates in bounds checks but not `Imin`.

Reference/vectorized backend:

- `brain_mask.py:492-511` creates 1–7 mm coordinates and checks the seventh point.
- `brain_mask.py:513-519` reads only `voxel_*[:6]`, again omitting 7 mm.
- Both backends use a fixed 1 mm step.

FSL `bet2.cpp:411-415,466-495` instead:

1. Sets `dscale = min(xdim, ydim, zdim, 1.0)`.
2. Samples the 1 mm point.
3. Explicitly includes the 7 mm endpoint in `Imin`.
4. Samples intermediate positions at `dscale`, giving denser sampling for sub-mm voxels.
5. Includes near-surface samples in `Imax` and all inward samples in `Imin`.

### 4.2 Minimal counterexample

On a 1 mm grid, set intensities at 1–6 mm along the ray to 100 and only the 7 mm endpoint to 0, with:

```text
t2 = 0
tm = 100
t  = 10
f  = 0.2
f**0.275 = 0.642367
```

The result is:

```text
local Imin / fit force = 100 / +0.715266
FSL   Imin / fit force =   0 / -1.284734
local normal displacement = +0.035763 mm
FSL   normal displacement = -0.064237 mm
```

The displacement example fixes mean edge length at 1 mm and compares only the normal fit term in the surface update. The direction reverses; this exceeds a rounding-level difference. Another counterexample on 0.5 mm voxels places the dark point at 1.5 mm: FSL's `dscale=0.5` samples it, while the local fixed 1 mm step does not.

### 4.3 Affected paths

BET masks are used by:

- Raw/nomoco/legacy nodif masks.
- GRE magnitude brain masks and corrected masks.
- TOPUP corrected-first-b0 masks.
- EDDY masks, joint masks, GP voxel selection, outlier processing, and DTIFIT support.
- Final tensor fitting support, followed by T1 tensors, conductivity, and FEM.

`tests/test_preprocessing_brain_mask.py:255-278` uses only a smooth 2 mm sphere with acceptance Dice `>0.985`. It cannot distinguish a lone dark 7 mm endpoint or check the dense 0.5 mm stencil.

The counterexamples establish divergence in sampling, `Imin`, and the single-step normal fit term, together with the production path using the resulting mask. This review did not run the full BET iteration to final surface/mask against real `bet2`, nor directly measure final tensor/FEM differences. Full mask A/B is therefore a required future check, not completed evidence.

### 4.4 Fix and acceptance checks

1. Share sampling rules transcribed operation by operation from the FSL C++ loop between both backends.
2. Test 1 mm, 0.5 mm, and anisotropic voxels separately.
3. Assert `Imin/Imax` directly, beyond final Dice.
4. Preserve the 7 mm force-direction-reversal counterexample.
5. Compare surface and mask for an adversarial phantom against real `bet2`.
6. Rerun the nomoco, legacy/GRE, TOPUP→EDDY, and production fitting branch matrix after the fix because masks propagate downstream.

## 5. D2C-030-062: conductivity `eigh` does not match every SimNIBS 4.6 `eig` output

### 5.1 Implementation difference

- Local `conductivity.py:10-13` uses `np.linalg.eigh()` for real symmetric tensors.
- SimNIBS 4.6 `utils/cond_utils.py:9-19` uses general solver `np.linalg.eig()`.
- Official reconstruction at `cond_utils.py:22-25` then treats returned eigenvectors as an orthogonal basis.

For distinct eigenvalues, differences are usually limited to signs and rounding. With repeated eigenvalues, general `eig` does not guarantee orthogonal vectors in the repeated eigenspace, while official reconstruction assumes orthogonality. Rank-deficient conductivity can result. Repeated eigenvalues are valid inputs, including isotropic and axially symmetric tensors.

### 5.2 Fixed counterexample

Set:

```text
q = [0.503178628918432, 0.10541287877480549, -0.8577292069110012]
A = I + 2 q q^T
eigenvalues(A) = [3, 1, 1]
scalar conductivity c = 0.126
mode = vn
```

On frozen NumPy 2.3.0, the statement-by-statement official formula and local code produce:

```text
official repeated-eigenvector abs dot = 0.9985485785667437
official conductivity determinant     = 1.0672731640583441e-18
local conductivity determinant        = 0.0019743676283966913 (positive/full-rank)
local vs literal-official relative L2 = 0.4060725208094854
```

This is a definite compatibility divergence, not evidence that the stable local algorithm is scientifically wrong: `eigh` is the natural choice for real symmetric eigensystems. Production FEM calls real SimNIBS, while standalone `tensor-to-mesh` calls the local converter. The two entry points can therefore produce different conductivity from the same tensor.

### 5.3 Recommended behavior and acceptance checks

1. Retain `eigh` as an explicitly named, recorded stable mode.
2. If literal SimNIBS 4.6 compatibility is needed, add an explicit strict mode using `eig` statement by statement.
3. In strict mode, record repeated eigenvalues, nonorthogonal bases, and near-rank-deficient output in QA; do not silently describe it as stable output.
4. Preserve this counterexample and compare local stable mode, the literal formula, and real `cond_utils`.
5. Document the difference between production SESSION and standalone-converter modes.

If the goal is mathematically stable conductivity rather than reproduction of pathological official output, stable mode need not be changed to `eig`. Claims of matching every SimNIBS output for arbitrary valid inputs must still be removed.

## 6. D2C-030-063: FEM cache identity can still collide

### 6.1 Composite solver checks require only any matching file

`workflow.py:285-317` defines solver globs. At `workflow.py:368-380`, any nonempty native-file list sets `cache_safe=True`. This does not establish that every required component of a composite solver is identified:

- `petsc_pardiso` requires PETSc and MKL, but current identity finds only MKL.
- `mumps` requires the MUMPS Python extension/context and native MUMPS libraries; identity omits package-private `_mumps...so`.
- No `hypre` candidate is found in the current environment, so its cache is conservatively disabled; that case is safe.

Observed current-environment results:

```text
pardiso       cache_safe=True   -> MKL .so.2/.so.3
hypre         cache_safe=False  -> no candidate
mumps         cache_safe=True   -> $CONDA_PREFIX/lib/lib*mumps*_seq.so, missing Python extension
petsc_pardiso cache_safe=True   -> MKL only, missing PETSc extension/library
```

Actually executed files also include:

```text
site-packages/mumps/_mumps.cpython-311-x86_64-linux-gnu.so
site-packages/petsc4py/lib/arch-linux-c-opt/PETSc.cpython-311-x86_64-linux-gnu.so
site-packages/petsc4py.libs/libpetsc-*.so
site-packages/petsc4py.libs/libHYPRE-*.so
```

SimNIBS `simulation/fem.py:16-17,700-713` explicitly routes `petsc_pardiso` through PETSc `KSPSolver` and `mumps` through `MUMPS_Solver`/context. These dependencies are part of computation.

### 6.2 Incomplete Python module and RECORD checks

`workflow.py:341-348` hashes only six modules: `run_simnibs.py`, `sim_struct.py`, `fem.py`, `pardiso.py`, `cond_utils.py`, and `mesh_io.py`. Real SESSION also directly imports or calls `electrode_placement.py`, `transformations.py`, `file_finder.py`, `csv_reader.py`, and others at `sim_struct.py:45-53,2104`.

Only the text of `.dist-info/RECORD` is hashed. Installed file contents are not revalidated against its entries. An in-place edit to an omitted module in the same-version environment, with unchanged RECORD text, can therefore leave identity unchanged even when electrode placement or subject-volume output changes.

### 6.3 Candidate paths may differ from actual loader paths

Current discovery only globs `sys.prefix/lib`, `Library/bin`, and `bin`. Official `pardiso.py:54-66`, for example, calls `ctypes.CDLL("libmkl_rt.so")`, letting the dynamic loader choose the file. If `LD_LIBRARY_PATH` puts another MKL first, the actual solver changes while identity may still hash the old file under `sys.prefix/lib`.

### 6.4 Consequences and acceptance checks

This is conditional P2: it requires runtime drift followed by a cache hit. When triggered, FEM is not rerun and old scientific results are returned silently.

The fix should:

1. Define required component groups per solver, with at least one match in every group.
2. Hash actual imported extensions and native libraries selected by the loader; disable caching if they cannot be resolved.
3. Validate current contents of executed files listed by RECORD, not just RECORD text.
4. Include all executed electrode-placement, transform, file-resolution, CSV/tag, and related code.
5. Add collision tests for omitted Python-module changes, package-private extension replacement, and changed dynamic-library resolution.
6. Until the full executed code/library set can be resolved and identified, conservatively disable every real FEM cache hit. `hypre` already disables caching because of incomplete identity in the current environment.

## 7. D2C-030-064: TOPUP coefficient NIfTI lacks FSL intent

### 7.1 Local writer and official header format

Local `topup.py:2697-2710` already writes:

- Knot-spacing affine/pixdim for the coefficient grid.
- Original field matrix size in qform translation.
- qform code `1` and sform code `0`.

It does not write:

- Cubic coefficient intent code `2016`.
- `intent_p1/p2/p3 = original dense-field voxel sizes`.

FSL `topup_file_io.h:101-107` defines cubic coefficient intent `2016`; `topup_file_io.cpp:98-135` writes intent and the three original voxel-size parameters. Its reader at `:229-260` distinguishes spline coefficients from dense fields by intent, then reconstructs field geometry from intent parameters, pixdim, and qform offsets at `:286-307`.

Local intent defaults to 0. Real `TopupFileReader` takes the unknown/dense-field branch instead of recognizing cubic spline coefficients.

### 7.2 Impact and why current arrays remain usable

At `topup_eddy.py:137-149`, local TOPUP→EDDY passes `field_hz.nii.gz` and the corrected mask to local EDDY; it does not use `field_coefficients.nii.gz`. This header therefore does not directly alter corrected DWI on the current main path.

However, the public coefficient artifact, QA inventory, and claimed ability to pass it on to FSL EDDY/applytopup are incorrect. Internal use of the dense field does not resolve this definite output-format problem.

### 7.3 Fix and acceptance checks

1. Set `intent_code=2016`.
2. Set `intent_p1/p2/p3` to the original dense-field voxel sizes.
3. Keep pixdim as knot spacing and qform translation as field matrix size.
4. Keep qform code `1` and sform code `0` so ordinary neurological swapping does not rewrite the coefficient grid.
5. Compare header fields individually with real FSL `_fieldcoef`.
6. Prepare artifacts using FSL `<prefix>_fieldcoef`, `<prefix>_movpar.txt`, and associated bundle/staging conventions, then read them with real FSL reader/EDDY. A header fix alone does not prove drop-in `--topup=<prefix>` support.

8. Strengthen `tests/test_preprocessing_topup.py:450-489`, which currently checks only existence and shape.

## 8. Confirmed nonliteral behavior that is not a local algorithm defect

### 8.1 GRE follows intended/patched official logic, not literal installed-script execution

Official `dwi2cond.prepro.source.sh:168` calls `EDDY_CORRECT` with five arguments, while `dwi2cond.functions.source.sh:235-240` enables warp only for `[ $# -gt 5 ]`. With exactly five arguments, the installed script does not enter applywarp. Local `legacy.py:596-610` correctly combines displacement.

The local implementation follows the clearly intended path obtained by changing `-gt 5` to `-ge 5`. This is not a new local defect. Future GRE A/B must retain both a literal reference and a reference patched only for argument counting; it must not broadly claim statement-by-statement equivalence with the installed script.

### 8.2 EDDY's default random seed differs for reproducibility

Official `dwi2cond.functions.source.sh:42-83` invokes FSL EDDY without `--initrand`. Its default is 0 at `EddyCommandLineOptions.cpp:62-64,242-246`, leading to `srand(time(NULL))` at `HyParEstimator.cpp:48-79`. Local defaults are seed 1 at `cli.py:247`, `workflow.py:60`, `topup_eddy.py:48`, and `eddy.py:3325`. Existing public EDDY benchmarks also use seed 1 on both sides.

The local choice improves reproducibility and is not an EDDY formula error. The evidence validates a deterministic seed-1 variant, however, rather than stock SimNIBS invocation. Retain default 1, document the deliberate difference, and provide `random_seed=None` or a strict-SimNIBS mode to express omission of `--initrand`.

### 8.3 TOPUP→EDDY does not use the complete TOPUP product set

Official `eddy --topup=<prefix>` reads spline coefficients and can use TOPUP movement according to acquisition index. Current local `topup_eddy.py` passes only dense `field_hz` and the corrected mask to local EDDY; coefficients and movement are recorded artifacts.

No new definite main-path error was identified within the fixed scope of one acquisition row and zero first-TOPUP movement. Documentation should still avoid saying “complete TOPUP products are passed to EDDY”, and the finding cannot be extended to future multi-acquisition support.

### 8.4 Local engineering extensions

Content-addressed caching, stage manifests, transactional publication, failure directories, external Hz fields, external world transforms, and standalone tensor-to-mesh are local extensions. They are not the original shell control flow. Transactions currently apply per stage/per FEM mode, rather than to the entire DAG atomically. If tensor publication succeeds and a later FEM stage fails, the new tensor may remain visible. Document this runtime behavior; it is not a newly discovered algorithm divergence.

## 9. High-priority evidence gaps

### 9.1 Positive-determinant TOPUP/EDDY coordinates

After storage reorientation, local TOPUP at `topup.py:2639-2673` and EDDY at `eddy.py:3353-3366,3392-3411` mainly pass arrays, positive voxel sizes, and PE axis/sign into the core. The affine determinant does not reach the core. Official NEWIMAGE converts positive-determinant input to radiological internal storage, and EDDY movement sampling at `ECScanClasses.cpp:327-343` also uses the internal sampling matrix.

Existing real TOPUP/EDDY fixtures still mostly have negative determinants. Static code alone cannot establish correct handling of both handedness cases. Given that `060` demonstrates a real bug at a similar boundary, this is a substantial risk. Without dedicated real FSL paired A/B, it remains an evidence gap, not a confirmed issue.

Required discriminating checks: positive/negative determinants for identical asymmetric arrays, preferably x/x- PE; compare TOPUP field, movement, corrected pair, and EDDY EC/movement parameters, rotated bvecs, masks, and corrected DWI individually.

### 9.2 FNIRT displacement fields are still not pointwise identical

Current frozen evidence:

```text
corrected-image relative L2 = 0.001298916
dense-field relative L2     = 0.175488519
max component error         = 0.994548967 mm
```

This passes current limits of image `<0.005`, field `<0.25`, and maximum `<1.2 mm`, but the displacement fields definitely differ. Existing evidence has not isolated a coordinate, unit, mask, spline, LM, or PCG formula error, so this remains a validation gap without a new bug ID.

PPD uses the field Jacobian. Small warped-image L2 does not establish tensor-orientation, conductivity, or FEM equivalence. Current evidence supports passing preregistered endpoint limits on a frozen fixture; it does not establish equality with FSL 6.0.4 for arbitrary inputs.

### 9.3 Complete real raw→FEM A/B is still missing

This review did not rerun same-input, end-to-end HCP raw DWI→TOPUP/EDDY→FNIRT→PPD→conductivity→FEM for all four conductivity modes (`scalar/vn/dir/mc`), nor launch a complete SimNIBS FEM solve inside the restricted sandbox. Solver-backend validation is a separate requirement. Historical stage tests and synthetic endpoints do not replace this complete evidence chain.

## 10. Supporting evidence

Source review and focused tests found no new definite divergence in:

- Current NewNifti-compatible storage orientation: float32 Gram–Schmidt, signed permutations, and strict tie-breaking.
- Exact-b0 selection and nomoco's separation of b0 registration from DWI transformation.
- DTIFIT/WLS design, FSL tensor component order, `S²/1` weighting, two-pass fit, S0 floor, and unweighted SSE.
- GRE/FUGUE field-to-voxel-shift, forward warp, MI FLIRT, and one-final-applywarp ordering, although masks inherit `061`.
- TOPUP's nine-level `b02b0_nosubsamp` schedule and main LM/PCG acceptance/rejection order.
- The fixed EDDY subset: b0 threshold, first-b0 scaling, five iterations, quadratic EC, spline, GP/outlier replacement, and Jacobian resampling.
- 6/12 DOF T1 registration producers, nonlinear schedule, PPD, post-masking, and tensor decomposition.
- Production FEM's call to real SimNIBS SESSION, without silent substitution by local tensor-to-mesh.
- Explicit backend failure, without silent fallback to reference/nomoco.

These findings support only the listed scope. They neither cover `060..064` nor prove correctness for arbitrary inputs.

## 11. Recommended fix order and validation

Prioritize downstream impact:

1. **Fix `060` legacy handedness/matrix conventions**, which directly alter corrected DWI.
2. **Fix `061` BET sampling**, because masks feed multiple preprocessing branches.
3. **Fix `063` FEM cache identity**; disable cache reuse when full execution identity is unavailable.
4. **Define `062` stable versus literal conductivity behavior** without silently reverting to pathological `eig` output merely for literal agreement.
5. **Fix `064` TOPUP headers** and verify interoperability through the real FSL reader.
6. Add paired positive-determinant TOPUP/EDDY reference checks.
7. Run the complete branch matrix, all real FSL tests, and at least one real HCP raw→aligned-tensor→conductivity/FEM A/B.

For each fix: isolate one issue, preserve one discriminating counterexample, compare against a real reference, and create one independent commit. Wider Dice tolerances, relaxed FNIRT field limits, an all-green pytest run, a local helper test, or the final image alone cannot replace stage-specific numerical and coordinate checks.
