## Findings

**The standard v0.3.0 workflow largely reproduces the stage order of SimNIBS 4.6.0. The previous fixes for raw-b0, sinc, TOPUP support, positive-determinant FNIRT derivatives, vecreg masking, post-masking, and FEM transactions remain valid. However, the implementation still cannot be described as identical to the official implementation.**

This review confirms **2 P1 and 5 P2 issues** remain open; no P0 was found:

| ID | Severity | Finding | Public tag status |
|---|---:|---|---:|
| `D2C-030-053` | P1, conditional | NiBabel and FSL/NewNifti choose different discrete axes for a highly oblique affine; physical PE axes can differ by 90° | open |
| `D2C-030-054` | P1, dependency combination | New NumPy/Numba combinations allowed by the tag fail the real FSL FNIRT image/field checks | open |
| `D2C-030-055` | P2 | The raw-DTI QA stage uses fitting compatibility mode, but its cache fingerprint omits that parameter | open |
| `D2C-030-056` | P2 | With FEM disabled, the full workflow does not check the official required `final_tissues.nii.gz` sentinel | open |
| `D2C-030-057` | P2 | FEM validation accepts a unique mesh fallback but does not pass the resolved mesh to real SimNIBS SESSION | open |
| `D2C-030-058` | P2, conditional | FEM caching hashes only `simnibs/__init__.py`, without identifying the actual computation modules or solver | open |
| `D2C-030-059` | P2, conditional | Public `tensor-to-mesh` VN returns finite values for a nonzero rank-deficient tensor, whereas the literal official calculation returns NaN | open |

`D2C-030-053` and `D2C-030-054` were found in the second review but remain unresolved in the public tag. `D2C-030-055..059` are new findings. Uncommitted working-tree changes already pin NumPy/Numba exactly and add corresponding metadata tests. These can temporarily prevent the unvalidated installation combination in `D2C-030-054`, but are not part of the `v0.3.0` tag and do not resolve orientation or the other new issues.

## 3. D2C-030-053: discrete orientation still differs from FSL

### 3.1 Implementation difference

The tag's `src/dwi2cond_xp/preprocessing/orientation.py:13-29` calls `nib.orientations.io_orientation()`, then converts to RAS/LAS according to the determinant.

FSL 6.0.4 actually follows `fslreorient2std:104-132` → `fslhd` orientation labels → `fslswapdim`. The labels come from NewNifti `legacyFunctions.cc:485-596`:

1. Normalize three columns using float arithmetic.
2. Apply Gram–Schmidt in a fixed order.
3. Enumerate 216 signed axis combinations.
4. Retain only combinations of matching handedness.
5. Select the maximum trace using strict `>` and fixed traversal order.

NiBabel uses an SVD/polar decision. These are different algorithms for general affines.

### 3.2 Real FSL reproduction

The input is a valid, finite, nonsingular 4D NIfTI:

```text
affine =
[[ 0.601011634,  1.401550531, 0.942415297,  92.374305725],
 [ 0.538023829, -1.309910774, 1.315203071, -25.246667862],
 [-0.660363793,  0.208347276, 1.929259419,  25.766641617],
 [ 0.000000000,  0.000000000, 0.000000000,   1.000000000]]

det(affine[:3, :3]) = -5.065160968553407
```

Real `/usr/local/fsl/bin/fslreorient2std` produced:

| Implementation | NiBabel | Output shape | Array equal to FSL |
|---|---:|---:|---:|
| FSL 6.0.4 | — | `(3, 4, 5, 2)` | — |
| Local tag | 5.3.3 | `(4, 5, 3, 2)` | false |
| Local tag | 5.4.2 | `(4, 3, 5, 2)` | false |

Maximum absolute affine differences between FSL and the two local outputs are approximately `2.343966` and `2.002562`. The unit physical directions of the same output voxel-y PE axis are:

```text
FSL:       [-0.72631691,  0.67882701, -0.10797053]
local 5.4: [ 0.57652091,  0.51609981, -0.63345452]
dot = 1.6703e-08; angle = 89.999999 degrees
```

Both the official script and local workflow continue to use the same PE string after reorientation. The difference therefore affects more than header display: TOPUP/EDDY may apply PE along different physical axes, with consequences for warps, tensors, PPD, conductivity, and FEM.

### 3.3 Required fix

1. Reproduce FSL 6.0.4/NewNifti float32 normalization, Gram–Schmidt, signed-permutation enumeration, and strict tie-breaking exactly.
2. Preserve sform precedence, qform fallback, q/s codes, and storage handedness.
3. Add real FSL data/shape/qform/sform A/B for this affine.
4. Assert physical PE vectors at the producer level; `aff2axcodes` alone is insufficient.
5. Require identical project output under NiBabel 5.3 and 5.4.

## 4. D2C-030-054: FNIRT dependency stability remains unresolved in the public tag

### 4.1 Allowed installations differ from the validated stack

The tag's `pyproject.toml:33-41` declares:

```text
nibabel>=5,<6
numba>=0.64,<1
numpy>=2,<3
scipy>=1.11,<2
```

However, `constraints-simnibs46.txt` and `environment.yml` validate NumPy `2.3.0`, Numba `0.64.0`, NiBabel `5.3.3`, and SciPy `1.17.1`. The tag's `tests/test_release_environment.py:13-27` checks agreement between frozen files but does not inspect project dependencies. CI and Release workflows run `pip install .[...]` without the constraint. Ordinary wheel installation can therefore select an unvalidated combination.

The uncommitted working tree already has exact NumPy/Numba pins and a project-metadata regression. That is a reasonable release safeguard, but the public `v0.3.0` issue remains open until the commit, tag, and Release are updated.

### 4.2 Same-input real FSL reproduction

The test is `tests/test_preprocessing_nonlinear.py::test_positive_determinant_fnirt_endpoint_matches_real_fsl`, using fixed `24×23×22` input, one worker, single-threaded OpenBLAS/OMP, and real FSL FNIRT:

| Environment | NumPy | Numba | NiBabel | Corrected-image relative L2 | Field relative L2 | Result |
|---|---:|---:|---:|---:|---:|---:|
| Frozen validated stack | 2.3.0 | 0.64.0 | 5.3.3 | `<0.005` | `<0.25` | `1 passed in 37.13s` |
| New combination allowed by tag | 2.4.6 | 0.66.0 | 5.4.2 | `0.0061349105` | `0.3948259303` | failed |

Repository limits are image `<0.005`, field `<0.25`, and component maximum `<1.2 mm`. The new combination demonstrably fails at least the first two. This finding comes from a real reference comparison, not coverage counts, pytest concurrency, or a self-consistency test without FSL.

Earlier trajectory tracing located the first divergence in lower-level linear algebra/PCG numerical behavior: very small differences in inverses, gradients, Hessians, and reductions change PCG stopping, then LM acceptance or rejection. There is no current evidence for a new coordinate, unit, spline-expansion, or mask-formula error, and no RNG path. Even so, the broad dependency range does not provide stable computation for the fixed FSL 6.0.4 subset.

The frozen stack itself has only passed the existing endpoint limits; its displacement field is not elementwise identical. Existing frozen evidence has field relative L2 around `0.17549`; real HCP PPD/conductivity/FEM A/B remains incomplete.

### 4.3 Required fix

1. Align wheel metadata, constraints, environment, and CI installation with the validated exact NumPy/Numba combination.
2. Add wheel METADATA regression, not just constraint-text checks.
3. Add real FNIRT/TOPUP/PPD checks for the minimum and maximum supported combinations.
4. Do not resolve the issue by relaxing image, field, or maximum-error limits.
5. Before widening dependencies again, stabilize or explicitly validate PCG/LM behavior across versions.

## 5. D2C-030-055: raw QA fitting mode missing from cache identity

`run_raw_fit()` at `workflow.py:843-853` passes `config.fit_compatibility_mode` to `fit_dti_nifti()`. But the corresponding `StageDefinition` parameters at `workflow.py:883-895` contain only workers and fixed fit text, with no dependencies. The fingerprint at `pipeline.py:410-432` uses only explicit inputs, dependencies, parameters, implementation, and runtime identity; it does not inspect Python closures.

In a temporary diagnostic copy of the tag, the second configuration in an existing cache test was changed from `strict-fsl` to `robust`, with all affected stages expected to rerun. Actual second-run status was:

```text
fit_raw_dti_qa = cached
preprocess_nomoco = completed
register_t1 = completed
publish_tensor = completed
pipeline_qa = completed
```

The collision is limited to raw QA. The main corrected fit, primary T1 transform, and published tensor rerun in the new mode and are not contaminated by the old raw tensor. However, raw FA/SSE/valid/QA, the raw 6DOF QA matrix, registered raw maps, and aggregate QA use results from the previous mode.

The parameter changes real behavior: `strict-fsl` and `robust` handle NaN, finite, and positive support differently in `nifti_fit.py:163-170`; `tests/test_nifti_fit.py:186-277` already demonstrates differing output domains.

Add `fit_compatibility_mode` to `fit_raw_dti_qa` parameters. Test both `strict-fsl → robust` and the reverse transition in the same output/cache directory, asserting that raw-stage and downstream QA outputs are recomputed.

## 6. D2C-030-056: missing official CHARM sentinel in the full workflow

Before any FLIRT/FNIRT call, official `dwi2cond.t1reg.source.sh:2-20` checks T1, labeling, and bias-corrected T1, and requires `m2m_*/final_tissues.nii.gz`. If absent, it explicitly reports that this version requires CHARM segmentation. Standalone `register-t1` in the tag checks the same file at `cli.py:804-818`, and the public `INPUT_CONTRACT.md` also lists it as required.

The full workflow adds `final_tissues` only when `require_fem=True` in `workflow.py:77-109`; `workflow.py:245-247` enables that check only for `fem_smoke != "none"`. CLI defaults are `fem_smoke="none"` and publish=true.

Default `run-pipeline`/`run-prefit-pipeline` can therefore complete T1 registration and publish a tensor into an m2m directory that the official tool would reject before registration. `final_tissues` does not directly affect tensor numerics, making this P2 rather than P1, but the entry and publication behavior differs.

Require `final_tissues` unconditionally for all T1 workflows, with a workflow regression for `fem_smoke=none + missing final_tissues`.

## 7. D2C-030-057: FEM mesh fallback does not reach real SESSION

The tag's `workflow.py:80-90` and `simulation.py:57-74` explicitly accept a unique `*.msh` if the standard `<subject>.msh` is absent. Tests also assert that `only.msh` works as a fallback. Static validation and dry-run therefore pass.

However, SESSION construction in `simulation.py:197-216` sets only `session.subpath`, EEG cap, and tensor, omitting the resolved `input_contract["head_mesh"]`. SimNIBS 4.6 `sim_struct.py:158-180` then calls `SubjectFiles(None, subpath)`; `file_finder.py:430-441` requires an `m2m_<id>` basename and reconstructs `<id>.msh`.

Consequences:

- A unique, nonstandard mesh name in `m2m_<id>` passes local validation/dry-run, but the real solve searches for `<id>.msh` and fails.
- A directory not named `m2m_<id>` can pass parts of the local T1 workflow, then fail late when real SimNIBS parses the subject ID.
- The reviewed SESSION test doubles do not execute a faithful `_prepare()`, so they miss the producer-to-consumer mismatch.

Use one support policy throughout. If fallback remains supported, assign the resolved mesh to `session.fnamehead` and validate `m2m_<nonempty-id>` on paths requiring subject assets. Add real or faithful `SESSION._prepare()` composition tests, and include this compatibility check in dry-run.

## 8. D2C-030-058: FEM caching does not identify actual SimNIBS computation

`_simnibs_runtime_identity()` at `workflow.py:276-294` records the distribution version, path to `simnibs/__init__.py`, and SHA-256 of that one file. FEM stage parameters include this dictionary; generic runtime identity also records distribution and loaded threadpool-library versions.

Actual computation uses `run_simnibs`, `sim_struct.py`, `cond_utils.py`, mesh/FEM modules, and solver implementations. Replacing these while retaining `simnibs==4.6.0` and an unchanged `__init__.py` leaves the FEM fingerprint unchanged and can silently reuse old results. `tests/test_preprocessing_workflow.py:1090-1120` only checks the init-file hash, reinforcing the gap.

This requires same-version local modification, repackaging, or solver drift, so it is conditional P2. Bind identity to the installed distribution's RECORD/key-module set and actual solver identity. If computational identity cannot be established completely, disable FEM cache hits rather than using one entry file to represent the whole backend.

## 9. D2C-030-059: VN differs from the literal official result for nonzero rank-deficient tensors

Public `tensor-to-mesh` follows `cli.py:1287-1305` → `simnibs_adapter.py:41-84` → `conductivity.py:tensors_to_conductivity()`. After computing determinant scale, the tag's `conductivity.py:176-179` applies:

```text
determinant_scale[determinant_scale == 0] = 1.0
```

SimNIBS 4.6 `cond_utils.py:257-266` fixes only all-zero tensors, then directly divides by `abs(prod(eigenvalues))^(1/3)` before `_fix_eigv()`. It has no such guard.

The discriminating input is one anisotropic tissue, VN mode, scalar conductivity `0.126 S/m`, and tensor `diag(1, 1, 0)`:

```text
local conductivity = diag(0.252, 0.252, 0.02714588)  # finite
literal SimNIBS 4.6 eigenvalue path = [NaN, NaN, NaN]
```

Existing tests cover SPD, all-negative, all-zero, and excentricity cases, but not nonzero rank-deficient VN. The README broadly describes corrections as SimNIBS safety behavior without identifying this branch as a deliberate robustness extension.

Production FEM in the full workflow is unaffected: `run_tdcs` passes tensors to real SimNIBS rather than the local converter. The affected public `tensor-to-mesh` API/CLI makes this P2.

Do not simply remove the guard. First define the public behavior:

- For strict SimNIBS 4.6 equivalence, reproduce the official result for a nonzero singular tensor or fail explicitly before computation.
- For a robustness extension, provide an explicit mode, record correction counts, add a discriminating test, and stop describing this branch as statement-by-statement official equivalence.

### Additional engineering observation, outside the algorithm issue list

`scripts/run_coverage.py:228-235` calls `TemporaryDirectory()` without `dir`, and does not set `TMPDIR/TEMP/TMP` or pytest `--basetemp` at entry. On the current host this defaults to shared `/tmp`. Normal exit cleans up, but interruption may leave NIfTI/cache/coverage artifacts. This does not affect algorithm-equivalence findings, but conflicts with the project rule requiring all controllable temporary files under a dedicated project directory. Explicitly pass the temporary root in a separate engineering fix.

## 11. Reviewed paths without a new confirmed issue

Within this review and the inputs covered by existing discriminating fixtures, no new deterministic error was found in:

- Single-shell selection, bvec normalization, grad-dev, and DTIFIT WLS/SSE.
- Raw moving images, `fix2D`, padding, and final extraslice interpolation in raw-b0 MCFLIRT.
- Separation of Hanning/Blackman windows from padding in FLIRT/MCFLIRT/APPLYWARP.
- GRE fieldmap units, mask data flow, and the two-pass legacy registration order.
- TOPUP's nine-level schedule, double mean, joint mask, and the main EDDY rotated-bvec/outlier/repol path.
- FNIRT's internal radiological conventions for positive/negative determinants, complete affine chain rule, coefficient/field coordinates, and PPD for a supplied warp.
- Affine vecreg negative half-ties, nonlinear post-masking, and tensor decomposition.
- Tensor publication and FEM attempt/failure/last-known-good transactions.

These findings mean no new issue was found in the tested scope. They are not formal proofs for arbitrary inputs. In particular, the frozen FNIRT stack retains a nonzero field residual, and real HCP producer→PPD→conductivity/FEM validation remains incomplete.

## 12. Recommended fix order and acceptance checks

1. **Fix `053` first:** implement NewNifti orientation exactly and compare physical PE directions against real FSL.
2. **Resolve public `054`:** commit the current exact pins, metadata regression, and supported-combination checks. Investigate stable PCG/LM later without relaxing thresholds.
3. **Fix `055`:** add the raw-QA cache parameter and two-way mode-switch regression.
4. **Fix `056/057`:** align full/standalone CHARM sentinel checks and use faithful SimNIBS `_prepare()` to verify mesh transfer into SESSION.
5. **Fix `058`:** bind FEM caching to the actual computational backend and solver identity.
6. **Address `059`:** define strict/robust behavior before deciding between finite-value correction and explicit failure.
7. Rerun the full frozen-stack suite, all real FSL probes, wheel METADATA/isolated installation, and at least one real standard `m2m_<subject>` SimNIBS session. Then perform real HCP nonlinear field→PPD→conductivity/FEM A/B.

Until those checks are complete, the supported description is:

> On tested standard inputs, v0.3.0 reproduces the main workflow and most numerical behavior of the fixed SimNIBS 4.6.0 dwi2cond/FSL subset. Two conditional P1 issues can still enter the scientific computation path, along with five issues involving degenerate inputs, caching, CHARM/FEM composition, or the public converter. The version cannot be described as having identical logic or numerical equivalence for arbitrary inputs.
