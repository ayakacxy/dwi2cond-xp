## 1. Findings

The `2 P1 + 5 P2` issues from the third independent review have each been addressed, with tests that distinguish the previous behavior from the fixes. These changes do not reduce resolution, iteration counts, stopping requirements, or numerical thresholds, and do not silently substitute another algorithm when a reference check fails.

The previous VN implementation did aim to avoid NaN, but `determinant_scale == 0 -> 1` changed the result without a mathematical definition or a QA record. Avoiding division by zero alone was insufficient. The resulting behavior is:

- Default `error`: VN determinant normalization explicitly fails for a nonzero singular tensor.
- Explicit `regularize`: project the singular eigensystem using `max_ratio`, then apply the existing two rounds of SimNIBS safety correction and record the number of adjusted tensors.
- This is a documented, auditable robustness extension; it does not claim statement-by-statement equivalence with SimNIBS 4.6 for rank-deficient inputs.

## 3. Orientation algorithm

### 3.1 Implemented behavior

The local implementation now preserves these NewNifti operations:

1. Convert the three spatial affine columns to float32.
2. Normalize i/j/k in order and apply fixed-order Gram–Schmidt with threshold `1e-4`.
3. Enumerate 6 axis permutations and 8 sign combinations.
4. Accept only candidates with the same handedness as the normalized matrix.
5. Maximize the float32 trace and use strict `>` to retain the first tie.
6. Convert to the RAS/LAS storage handedness required by FSL `fslreorient2std`.

This is an independent Python implementation. FSL remains an optional test reference, not a runtime dependency.

### 3.2 Counterexample resolved

The audit's counterexample affine was:

```text
[[ 0.601011634,  1.401550531, 0.942415297,  92.374305725],
 [ 0.538023829, -1.309910774, 1.315203071, -25.246667862],
 [-0.660363793,  0.208347276, 1.929259419,  25.766641617],
 [ 0.000000000,  0.000000000, 0.000000000,   1.000000000]]
```

After the fix, both local code and real FSL choose `x/y` flips and retain shape `(3,4,5,2)`. Arrays, qform, sform, and the unit physical PE vector corresponding to voxel-y agree. Tests also cover qform-only inputs, active sform, positive and negative determinants, all 48 signed permutations, and degenerate Gram–Schmidt branches.

## 4. Dependencies and FNIRT limits

Release dependencies now match `constraints-simnibs46.txt` and the validated environment:

```text
numpy==2.3.0
numba==0.64.0
```

This prevents ordinary installation from selecting the known failing combination. It does not establish bitwise identical FNIRT optimization trajectories across arbitrary BLAS libraries, CPUs, or future dependencies. The frozen stack's existing synthetic endpoint still has a nonzero field residual; image, field, and maximum-error thresholds were not relaxed.

## 5. FEM composition and cache identity

Every CHARM/T1 workflow now requires `final_tissues.nii.gz`. FEM execution additionally requires a standard `m2m_<subject>` directory, mesh, and EEG cap. If `<subject>.msh` is absent but the directory contains exactly one mesh, the path resolved during validation is assigned directly to `SESSION.fnamehead`. Dry-run, real `SESSION._prepare()`, and solve therefore use the same mesh.

FEM caching no longer treats `simnibs/__init__.py` as the identity of the entire backend. Identity now includes:

- SimNIBS distribution version and RECORD SHA-256;
- paths, sizes, and SHA-256 values for six modules directly involved in computation or composition;
- solver name and NumPy/SciPy/PETSc package versions;
- paths, sizes, and SHA-256 values for the selected solver's native libraries in the current environment.

If RECORD, a required module, or native solver identity is missing, the real FEM stage may still run, but it cannot reuse an earlier solve cache. An incomplete identity no longer permits silent reuse.

## 6. VN numerical stability

For a nonzero singular diffusion tensor, the quantity

```text
g = abs(lambda1 * lambda2 * lambda3) ** (1/3)
```

is zero, so VN's `lambda / g` is undefined. Replacing `g` with 1 avoided division by zero but did not establish that the result was a VN mapping, and left no QA record.

The explicit `regularize` policy first projects the anisotropy ratio: small eigenvalues are raised to at least `lambda_max / max_ratio`; an entirely nonpositive degenerate system uses the documented tissue-conductivity fallback. It then recomputes a positive determinant scale before the existing normalization and two safety-correction rounds. This provides three properties absent from the old implementation:

1. No NaN/Inf is produced.
2. Output remains positive definite and constrained by `max_ratio/max_cond`.
3. QA records the policy, count, and parameters, allowing downstream rejection or review.

The default remains `error`, so the ordinary reference-compatible path does not enable the robustness extension without an explicit request.

## 8. Evidence limits

- This work did not rerun a complete HCP raw-DWI→TOPUP/EDDY→FNIRT→FEM workflow. Synthetic tests and `SESSION._prepare()` do not establish new end-to-end numerical equivalence on human data.
- The production FEM workflow still calls real SimNIBS 4.6. The local VN robustness extension affects only the public `tensor-to-mesh` converter; it does not silently replace the conductivity path used by a production SimNIBS solve.
- These results resolve the deterministic counterexamples in `053..059`. They are not a formal or bitwise equivalence proof for arbitrary inputs.
