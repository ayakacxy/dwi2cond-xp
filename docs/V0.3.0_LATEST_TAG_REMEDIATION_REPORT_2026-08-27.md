# dwi2cond-xp v0.3.0 最新 tag 复审问题整改报告

> 日期：2026-08-27
> 缺陷基线：`437e90bc448638413684ed88a65a77d2e50b63ec`
> 输入报告：`V0.3.0_LATEST_TAG_INDEPENDENT_REAUDIT_REPORT_2026-08-26.md`
> 整改实现：包含本报告的提交；最终以 `v0.3.0^{}` 的 tag target 为准
> 官方参考：SimNIBS 4.6.0 `dwi2cond`；FSL `6.0.4:ddd0a010`

## 1. 结论

指定复审报告记录的 **6 个 P1 和 9 个 P2/P3 问题簇已经全部完成代码整改和判别回归**。
本轮不是通过放宽容差、减少迭代或增加静默回退来关闭问题；legacy MCFLIRT 的 moving
采样流程、TOPUP 均值精度、FNIRT identity 条件和低层 PPD mask 语义均直接按官方控制流
修正。workflow、QA、cache、FEM inventory 和失败事务则按实际 producer/consumer 合同
收紧。

整改后可以确认：

1. 报告中导致默认 workflow 失败的 JSON schema 回归已消除；
2. nomoco、legacy、TOPUP/EDDY、T1 registration、发布、QA 和 FEM 的声明产物及 cache
   谱系已闭合；
3. legacy MCFLIRT 只构造 reference pyramid，cost 从原始 moving grid 一次物理采样，
   `fix2D` 判断和 padding 次序与 FSL 对齐；
4. 公开 API 的 ignored/late-validation 分支改为 consumed-or-rejected；
5. 当前 production statement coverage 为 `13370/13370`，没有新增 omit/pragma 或降低门禁。

仍然不把上述结论外推成“FSL 所有 optimizer 对任意输入 bitwise 相同”。特别是完整真实
HCP TOPUP→EDDY→FNIRT→FEM、FNIRT/EDDY optimizer trajectory bitwise equality，以及
进程在两个独立目录项 rename 之间遭受不可恢复机器掉电的瞬时可见性，不属于本报告已经
证明的范围。

## 2. 整改原则

- 先恢复 SimNIBS 4.6 官方 raw QA→correction→final fit→T1 registration→post-mask→QA
  的阶段顺序；
- 数值实现按 FSL 源码控制流修正，不以终点容差替代算法流程；
- 每个正式 stage 的实际读取文件都进入 fingerprint；
- 动态 inventory 只能由显式 contract 启用，不能由通用 JSON 键名猜测；
- 失败不得删除已有有效 m2m tensor/provenance 对；
- dry-run 与 real-run 隔离，且二者执行相同的静态参数验证；
- 正常 producer JSON、FEM 动态 manifest、失败清理和 cache hit/miss 分别测试。

| `D2C-030-039-R` | MCFLIRT 每级只重采样 reference；moving 保持原始 grid，cost 使用独立 reference/moving sampling matrix 一次插值。`fix2D` 在首级 reference 后判断，恢复首级双 reference padding、moving 单 padding及仅 `Rz/Tx/Ty` 参数。 | 20/21/24 mm 阈值测试；21 mm 必须进入 2-D；真实 FSL thin-volume matrix gate 通过。 |

检查拒绝异常状态；不存在跨两个目录项的通用单系统调用原子提交。

## 6. 最终声明边界

本轮足以关闭指定报告的 15 个问题簇，并恢复 `v0.3.0` fixed SimNIBS 4.6/FSL subset 的
控制流、产物和失败合同。以下仍是证据边界，而不是本轮遗留的已确认 bug：

- EDDY/FNIRT optimizer 不声明任意输入 bitwise equality；
- synthetic 阶段证据不外推为新的完整真实 HCP 全链证据；
- GRE 的既有主动差异、fixed subset 边界和 FSL-free runtime 定位保持不变；
- FEM 数值求解继续调用实际 SimNIBS backend，本地只负责输入、电导率、事务与产物合同。

只有在 `main` CI、CodeQL、Scorecard、tag target、Release assets、SHA256SUMS、干净安装与
CLI 均复核通过后，替换后的 `v0.3.0` 才算最终发布闭环。
